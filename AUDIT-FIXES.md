## P0 — безопасность и деньги

- [x] **P0-1. Покупатель сам помечал заказ оплаченным.**
  Миграция V12 (`orders.payment_claimed` + `payment_claimed_at`). `/api/me/orders/{id}/pay` постит
  скрин в чат и ставит только ЗАЯВКУ; `paid`/`received_minor` меняет исключительно админ.
  Карточка отгрузки пишет «скрин прислан, НЕ подтверждён», наложка остаётся полной. Во всех
  списках и карточках — отдельное состояние «Оплата на проверке».
- [x] **P0-2. `ALLOW_UNSIGNED_INIT_DATA` — обход авторизации.**
  `StartupSecurityCheck`: вне профиля `dev` контекст не поднимается с этим флагом, с
  плейсхолдерным `JWT_SECRET` или `ADMIN_PASSWORD`. `SPRING_PROFILES_ACTIVE=dev` локально,
  `prod` — в `docker-compose.prod.yml`.
- [x] **P0-3. Реквизиты в `V2__seed.sql` — НЕ проблема (решение владельца, 2026-09-17).**
  Карта/IBAN/РНОКПП в сиде — тестовые данные, не боевые. Ничего не меняем: править V2 всё равно
  нельзя (Flyway сверяет контрольную сумму накатанной миграции). Боевые реквизиты задаются через
  админку и в репозиторий не попадают.
- [x] **P0-4. Прод публиковал MySQL (3341) и MinIO (9002/9003).**
  `ports: !override []` обоим в `docker-compose.prod.yml`.
- [x] **P0-5. Swagger/Actuator наружу через gateway.**
  Оба gateway отдают 404; `/actuator/**` кроме health/info — под ROLE_ADMIN (раньше открывался
  обычным покупательским токеном).
- [x] **P0-6. Публичный бакет + неподписанный imgproxy + чат-вложения рядом с товарами.**
  Бакет приватный (`mc anonymous set none`). Вложения чата отдаёт бэкенд по подписанной ссылке
  с TTL 1 час (`MediaSigner` + `GET /api/media`), `MessageDto.attachmentUrl` — уже подписанный
  URL. `IMGPROXY_ALLOWED_SOURCES` ограничивает imgproxy своим бакетом; `limit_req`/`limit_conn`
  на `/img`.
- [x] **P0-7. Нет rate-limit.**
  `RateLimitFilter`: 10/5мин на `/api/auth/**`, 30/мин на загрузки, 120/мин на публичные чтения.

## P1 — баги

- [x] **P1-8. Гонка на остатках → оверселл + дрейф стока.**
  `SELECT … FOR UPDATE` на товары (лок в порядке id против дедлоков) и на промокод. Убран
  `Math.max(0, …)`, который глотал единицы при оверселле и возвращал их из воздуха при отмене.
  При наличии вариантов `product.stock` = сумма стоков вариантов.
- [x] **P1-9. Правка товара пересоздавала варианты/картинки (новые UUID).**
  Diff по id (варианты) и по ключу (картинки), коллекции мутируются на месте; осиротевшие
  объекты удаляются из MinIO. Фронт шлёт id вариантов. Уникальность названия проверяется и при update.
- [x] **P1-10. `@Async`/`@Transactional` не работали (self-invocation) в `NovaPoshtaSyncService`.**
  Явный `TaskExecutor`, апсерт страницами в отдельном бине, защита от параллельных запусков.
- [x] **P1-11. `deleteAll()` вариантов оплаты рвал ссылки в заказах.**
  Апсерт по id, пропавшие деактивируются.
- [x] **P1-12. Telegram-вызовы внутри транзакции.**
  `OrderEvents` + `OrderNotificationListener` (`@TransactionalEventListener` AFTER_COMMIT,
  `REQUIRES_NEW` для записи message_id). WS-бродкаст чата — тоже afterCommit.
- [x] **P1-13. `soldCount` всегда 0.** Реальный `GROUP BY` по `order_items` (без REJECTED и подарков).
- [x] **P1-14. Дата-бакеты метрик в UTC.** Режутся по `app.timezone` (Europe/Kyiv).
- [x] **P1-15. Округление денег расходилось.** `NotificationService.money` округляет как фронт.
- [x] **P1-16. JWT в query string WebSocket.** Только CONNECT-заголовок; SockJS удалён.
- [x] **P1-17. WS-синглтон админки держал старый токен + утечка подписок.**
  Клиент на подписку, токен читается на каждый коннект.
- [x] **P1-18. Гонка deep-link → чат + нет ретрая авторизации.**
  Страница чата слушает появление токена; авторизация ретраится с бэкоффом.
- [x] **P1-19. Multipart-лимит 1 МБ + нет валидации.** 15 МБ + `UploadValidator` (whitelist типов
  и расширений).
- [x] **P1-20. Нет catch-all обработчика + `@Valid` не каскадился.**
  `ApiExceptionHandler` с correlation id и обработчиками AccessDenied/DataIntegrity/MaxUploadSize/
  HttpMessageNotReadable/ConstraintViolation; `@Valid`/`@Size`/`@PositiveOrZero` в DTO;
  `SecurityUtil` отдаёт 401 вместо 403.

## Что проверить руками перед мерджем

1. `docker compose up -d --build` — фронты теперь собираются из корня репозитория
   (`context: .`, `-f frontend/Dockerfile`); это единственное изменение в сборке образов.
2. Первый старт бэкенда накатит **V12, V13, V14**.
3. `.env`: добавить `SPRING_PROFILES_ACTIVE=dev` локально. На проде профиль `prod` ставится
   compose-оверрайдом — и там `ALLOW_UNSIGNED_INIT_DATA` обязан быть `false`.
4. `IMGPROXY_KEY`/`IMGPROXY_SALT` должны остаться **пустыми**: фронты строят `/insecure/…` URL,
   а заполненные ключи заставят imgproxy отвергать их.
5. Бакет MinIO станет приватным — проверить, что картинки товаров открываются (их читает
   imgproxy по ключам S3, а не анонимно).
6. Админам понадобится один повторный вход: смена пароля через `AdminBootstrap` бампает
   `token_version` и отзывает старые токены.
