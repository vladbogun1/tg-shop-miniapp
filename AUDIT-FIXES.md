## P0 — безопасность и деньги

- [ ] **P0-1. Покупатель сам помечает заказ оплаченным.**
  `MeController.pay()` ставит `paid=true` + `received=total` по одной картинке → наложка 0.
  *Фикс:* новое поле `payment_claimed` (+ `payment_claimed_at`, миграция V12). `/pay` больше НЕ трогает `received`/`paid`, только постит скрин в чат и ставит заявку. Карточка отгрузки и админка показывают «заявлена оплата, не подтверждена». Подтверждает только админ через `PATCH /{id}/paid`.
- [ ] **P0-2. `ALLOW_UNSIGNED_INIT_DATA` — обход авторизации.**
  *Фикс:* fail-fast на старте — если флаг включён и активен профиль `prod`, контекст не поднимается. Громкий WARN при включении. `.env` локально оставляем true, `.env.example` — false.
- [ ] **P0-3. Реальные реквизиты в `V2__seed.sql` (git).**
  *Фикс:* сид ставит пустые/плейсхолдерные реквизиты; новая миграция не нужна (V2 уже накатана — правим только для новых установок + отдельная V13 не требуется). Реальные значения заводятся через админку. Документируем в README.
- [ ] **P0-4. Прод публикует MySQL (3341) и MinIO (9002/9003).**
  *Фикс:* `ports: !override []` для `mysql` и `minio` в `docker-compose.prod.yml`.
- [ ] **P0-5. Swagger/Actuator наружу через gateway.**
  *Фикс:* убрать `location ~ ^/(swagger-ui|v3/api-docs|actuator)` из `infra/gateway.conf` и `gateway-admin.conf`; в `SecurityConfig` закрыть `/actuator/**` (кроме health/info) под ROLE_ADMIN.
- [ ] **P0-6. Публичный бакет + неподписанный imgproxy + чат-вложения рядом с товарами.**
  *Фикс:* подпись imgproxy на бэке (`/api/media/sign` не нужен — подписываем URL там, где отдаём DTO? нет) → выбранный путь: серверная подпись URL в DTO. Плюс отдельный приватный бакет для чат-вложений и выдача их через backend-прокси с проверкой прав.
- [ ] **P0-7. Нет rate-limit.**
  *Фикс:* лимитер на `/api/auth/**` (по IP + логину, блокировка после N попыток), лимит на публичные NP-эндпоинты, лимит на загрузки.

## P1 — баги

- [ ] **P1-8. Гонка на остатках → оверселл + дрейф стока.**
  *Фикс:* атомарный `UPDATE ... WHERE stock >= ?` для product/variant, без `Math.max(0, ...)`; то же для `promo_codes.uses_count` с учётом `max_uses`.
- [ ] **P1-9. Правка товара пересоздаёт варианты/картинки (новые UUID).**
  *Фикс:* diff по id вместо `clear()`; удаление осиротевших объектов в MinIO.
- [ ] **P1-10. `@Async`/`@Transactional` не работают (self-invocation) в `NovaPoshtaSyncService`.**
  *Фикс:* вынести синк в отдельный бин / использовать `TaskExecutor` явно; батч-апсерт вместо построчного.
- [ ] **P1-11. `deleteAll()` вариантов оплаты рвёт ссылки в заказах.**
  *Фикс:* upsert/diff по id + soft-deactivate вместо удаления.
- [ ] **P1-12. Telegram-вызовы внутри транзакции.**
  *Фикс:* `@TransactionalEventListener(AFTER_COMMIT)` или явный `TransactionSynchronization`.
- [ ] **P1-13. `soldCount` всегда 0 → сортировка «по популярности» фиктивна.**
  *Фикс:* реальный подсчёт из `order_items` (без REJECTED), с кэшем.
- [ ] **P1-14. Дата-бакеты метрик в UTC.**
  *Фикс:* зона `Europe/Kyiv` (конфигом `app.timezone`).
- [ ] **P1-15. Округление денег: бэк `/100`, фронт `Math.round`.**
  *Фикс:* единое правило (round) в `NotificationService.money`.
- [ ] **P1-16. JWT в query string WebSocket.**
  *Фикс:* только CONNECT-заголовок; из query убрать в обоих фронтах и в бэке.
- [ ] **P1-17. WS-синглтон админки держит старый токен + утечка подписок.**
  *Фикс:* пересоздание клиента при смене токена, снятие pending-коллбэков.
- [ ] **P1-18. Гонка deep-link → чат (нет токена) + нет ретрая авторизации.**
  *Фикс:* реактивный токен (`subscribe`), переподключение WS при появлении токена, ретрай авторизации.
- [ ] **P1-19. Multipart-лимит 1 МБ по умолчанию + нет валидации типа/размера.**
  *Фикс:* `spring.servlet.multipart` 15 МБ, whitelist content-type, проверка на фронте, обработчик `MaxUploadSizeExceededException`.
- [ ] **P1-20. Нет catch-all обработчика ошибок + `@Valid` не каскадится на items.**
  *Фикс:* generic handler, обработчики `DataIntegrityViolation`/`MaxUploadSize`/`HttpMessageNotReadable`/`ConstraintViolation`; `@Valid` на списках; `@Size` на строковых полях DTO.
