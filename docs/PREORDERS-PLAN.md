# Предзаказы («Скоро в наличии») + закупка и маржа — план

Статус: **черновик на одобрение** (27.10.2026, вторая редакция — добавлены деньги партии и решения владельца).
Код не начат.

## 1. Идея в двух словах

Товар закончился → Максим заказал его у завода → в админке создаёт **«Поставку»** (что едет, сколько,
примерный срок). Товар на сайте и в Mini App перестаёт быть серым «Немає в наявності» и становится
**«Передзамовлення · їде до нас»** с кнопкой **«Повідомити, коли приїде»**. Покупатель встаёт в очередь
(без оплаты). Когда поставка приехала, Максим жмёт **«Приехала»** → остаток пополняется, первым в очереди
бот пишет «приехало, забронировали за тобой до …» с кнопкой «Купить». Не успел — бронь уходит следующему.

Термины в интерфейсе:

| Где | uk | ru | en |
|---|---|---|---|
| Бейдж товара | Передзамовлення | Предзаказ | Pre-order |
| Подзаголовок | Їде до нас · очікуємо 10–20 лис | Едет к нам · ждём 10–20 ноя | On its way · expected Nov 10–20 |
| Кнопка | Повідомити, коли приїде | Сообщить, когда приедет | Notify me |
| После подписки | Ви в черзі · №5 | Вы в очереди · №5 | You're in line · #5 |
| Раздел | Скоро в наявності | Скоро в наличии | Coming soon |
| В кабинете | Мої очікування | Мои ожидания | My waitlist |

Это **не платный предзаказ**: денег до приезда не берём (см. §9 — можно добавить позже).

**Вторая половина фичи — деньги партии.** «Поставка» — это одновременно закупка: Максим вбивает закупочную
цену каждой позиции (в валюте завода и по курсу), а когда партия прошла границу — расходы на всю партию
(доставка, таможня, брокер, доставка по Украине, комиссия банка). Система раскидывает расходы на штуки →
**полная себестоимость единицы** → честная маржа по заказам, товарам, брендам и каждой партии (§5А).

Поставку можно завести и без предзаказа — просто «докупил товар, который ещё есть»: тогда это чистая закупка
для учёта себестоимости, очереди нет.

## 2. Что сейчас в коде (на что опираемся)

- `Product.stock` + `ProductVariant.stock`, `stock` товара — сумма вариантов. Оформление заказа берёт
  `FOR UPDATE` на остаток и не даёт уйти в минус (`OrderService.create`).
- Нет в наличии: в каталоге товар уходит вниз (`PublicCatalogService` — `stockFirst`), карточка серая,
  кнопка выключена (`frontend/components/catalog/ProductCard.tsx`, `ProductView.tsx`, сайт — то же).
- Все покупатели (и сайт, и Mini App) — это `users` с `telegram_user_id`, есть `bot_blocked` → писать
  можно каждому через бота. Массовая рассылка с паузами уже есть (`BroadcastService`, ~22 сообщ./с).
- Кнопки в сообщениях бота ведут в Mini App через `?startapp=…` (`ReviewNotifier`, `SupportNotifier`).
- Тексты уведомлений бота на 3 языках редактируются во вкладке «Переводы» (шаблоны, V50).
- Журнал «Бот и сайт» (V47) — туда пишем все отправки.
- На сайте schema.org `availability` пока только InStock/OutOfStock.
- В аудите админки идея уже была (C14 в `.devdata/admin-review-2026-10/05-features-ops.md`).

## 3. Жизненный цикл

```
Поставка:   ЗАКАЗАНО ──► В ПУТИ ──► НА ТАМОЖНЕ ──► ПРИЕХАЛА
               └──────────┴────────────┴──► ОТМЕНЕНА
            (статусы для Максима; покупатель видит 3 шага: Замовлено → В дорозі → На складі)
Деньги:     себестоимость ПРЕДВАРИТЕЛЬНАЯ (вбиты не все расходы) ──► ЗАКРЫТА (Максим жмёт «Все расходы внесены»)

Подписка:   ЖДЁТ ──(поставка приехала, есть штуки)──► БРОНЬ до HH:MM ──► КУПИЛ
              │                                         │
              │                                         └─(не купил вовремя)──► ПРОСРОЧЕНА
              ├─(приехало меньше, чем ждут)──► остаётся ЖДЁТ, номер в очереди
              ├─(покупатель отписался)──► ОТМЕНЕНА
              └─(поставку отменили / товар убрали)──► ОТМЕНЕНА + сообщение
```

### Как раздаются штуки при приезде (рекомендую — «очередь с бронью»)

1. Максим отмечает «Приехала» и вводит, сколько реально пришло по каждой позиции (по умолчанию = заказано).
2. Остаток товара/варианта увеличивается на пришедшее.
3. Подписчики по порядку записи получают **бронь**: столько штук, сколько хотели (но не больше, чем осталось).
   Бронь длится **24 ч** (настраивается в поставке). Забронированные штуки другим не видны.
4. Бот пишет каждому с бронью. Кому не хватило — «приехало меньше, вы №3 в очереди, ждём следующую партию».
5. Каждые 5 минут задача снимает истёкшие брони → штука уходит следующему в очереди (ему сообщение),
   очередь кончилась → штука в свободной продаже.
6. За 3 часа до конца брони — одно напоминание.

Альтернатива на выбор в каждой поставке: **«всем сразу»** — уведомить всех, кто первый купил, тот и купил
(проще, но обидно тем, кто не успел). Переключатель в окне «Приехала».

## 4. Что увидит покупатель (Mini App и сайт одинаково)

### 4.1 Карточка в каталоге

Сейчас «нет в наличии» = серое фото + выключенная кнопка. Для предзаказа:

```
┌──────────────────────┐
│   [фото, НЕ серое]   │
│ ◆ Передзамовлення    │  ← бейдж сине-фиолетовый с иконкой грузовичка, вместо зелёного «В наявності»
│ Lamzu Maya X 8K      │
│ 3 999 ₴              │
│ їде · ~10–20 лис     │  ← мелкая строка срока
│ [ Повідомити ▸ ]     │  ← кнопка не оранжевая, а контурная (вторичная)
└──────────────────────┘
после подписки:  [ ✓ Ви в черзі ]   (приглушённая, тап → отписаться на странице товара)
у меня бронь:    [ Заброньовано · купити ]  (оранжевая, как обычная покупка)
```

Сортировка: в наличии → предзаказ → нет в наличии.

### 4.2 Страница товара

Вместо блока «Додати в кошик»:

```
┌─────────────────────────────────────────────┐
│ 🚚 Їде до нас                                │
│ ● Замовлено у виробника ── ● В дорозі ── ○ На складі │  ← мини-таймлайн 3 шага
│ Очікуємо 10–20 листопада                     │  ← или «~2 тижні» / «20 листопада» — как вбил Максим
│ Чекають 14 людей                             │  ← показываем только от 5 человек
│ «Партія з білими перемикачами» (заметка)     │  ← публичная заметка поставки, 3 языка
│ [   Повідомити, коли приїде   ]              │
│ Без передоплати. Коли приїде — 24 год броні.  │
└─────────────────────────────────────────────┘
```

Тап по кнопке → нижняя шторка: количество (1…лимит антибота), строка «Напишемо в Telegram-боті»,
кнопка «Стати в чергу». Если бот заблокирован — предупреждение «розблокуйте бота, інакше не дізнаєтесь»
со ссылкой на бота (подписку всё равно создаём, бронь видна в кабинете).

После: «Ви в черзі · №5 · 1 шт» + ссылка «Вийти з черги».
Бронь: «Заброньовано за вами до 18:00 завтра» + обычная кнопка «Додати в кошик» с таймером.

Варианты (цвета/свитчи): у чипа варианта в пути — маленькая точка/подпись «їде»; выбор такого варианта
переключает блок на предзаказ, остальные варианты покупаются как обычно.

### 4.3 Отдельный каталог «Скоро в наявності»

- **Сайт:** страница `/[locale]/coming-soon` (+ пункт в меню каталога, если есть открытые поставки), сетка
  карточек, сгруппировано по поставке («Очікуємо 10–20 лис», «Очікуємо початок грудня»).
- **Mini App:** на главной горизонтальная лента «Скоро в наявності →» (показывается, только если есть
  что показать) + полный список по тапу. В фильтрах каталога чип «Передзамовлення».
- По желанию — слайд в баннер-слайдере главной с маскотом-грузчиком (отдельная задача, не в MVP).

### 4.4 Кабинет — «Мої очікування»

Новый пункт в аккаунте (сайт и Mini App): список подписок со статусом —
«Чекаємо · №5 · ~10–20 лис», «Заброньовано до 18:00 → Купити», «Куплено», «Бронь минула — стати знову»,
«Поставку скасовано». Точка-бейдж на вкладке «Акаунт», пока есть активная бронь.

### 4.5 Сообщения бота (3 языка, правятся во «Переводах»)

Решение владельца: **никаких «в пути» и «задерживается»** — пишем только по факту приезда (и подтверждение,
когда человек сам встал в очередь). Сдвиг срока покупатель просто видит на странице товара и в кабинете.

| Когда | Текст (uk, пример) | Кнопка |
|---|---|---|
| Подписался | «Ви в черзі на Lamzu Maya X (№5). Напишемо, щойно приїде.» | Мої очікування |
| Приехало, бронь | «Lamzu Maya X приїхав! 1 шт заброньовано за вами до 18:00 28.10.» | Купити |
| Напоминание за 3 ч | «Бронь на Lamzu Maya X закінчується о 18:00.» | Купити |
| Не хватило | «Приїхало менше, ніж чекали. Ви №2 у черзі на наступну партію.» | — |
| Бронь перешла от другого | как «Приехало, бронь» | Купити |
| Поставку отменили | «На жаль, поставку Lamzu Maya X скасовано.» | Схожі товари |

Кнопка «Купити» → Mini App на товар (`startapp=p_<slug>`); подписавшимся на сайте — ссылка на сайт.

### 4.6 SEO и фиды

- schema.org: `availability: PreOrder` + `availabilityStarts` (начало срока).
- Google Merchant фид: `availability=preorder` + `availability_date`; Hotline — как «под заказ» или исключать
  (уточнить по их правилам при реализации, скилл shop-seo-check).
- После смены статуса поставки — сброс кэша страниц товара (`SiteRevalidator`).

## 5. Что увидит Максим (админка)

### 5.1 Новый раздел «Поставки» (в меню рядом с «Товары»)

Список: название · статус · срок · позиций · **ждут N чел / M шт** · действия.

**Создать поставку:**
- название (для себя, например «Lamzu, заказ 27.10»), поставщик (справочник), приватная заметка
  (номер заказа у завода, трек перевозчика);
- срок — Максим выбирает формат сам: **точная дата** («20 листопада»), **диапазон** («10–20 листопада»)
  или **примерно** («~2 тижні» — хранится как дата-цель, покупателю показывается «~N тижнів» от сегодняшнего
  дня, прошла — «найближчим часом»). Можно менять сколько угодно раз, покупателям ничего не шлём;
  галочка «не показывать срок»;
- публичная заметка (необязательно, переводится как контент);
- позиции: выбор товара/варианта (готовый `ProductPickModal`) + сколько заказано + **закупочная цена за штуку**
  (в валюте поставки) — можно вбить позже;
- бронь, часов (по умолчанию из настроек, 24);
- галочка «Открыть предзаказ» (по умолчанию включена, если товара нет в наличии; выключена — чистая закупка).

**Карточка поставки** — три вкладки:
- **Позиции и очередь:** заказано / пришло / **ждут (людей, штук)** — видно, хватит ли партии;
  список подписчиков: имя, @username, сколько хочет, когда встал, откуда (сайт/Mini App), статус,
  бот заблокирован; экспорт CSV; можно убрать человека из очереди;
- **Деньги:** закупка, расходы, распределение, себестоимость за штуку (см. §5А);
- **Продажи:** что продано из этой партии, выручка, маржа, что осталось на складе.
- кнопки: «В пути» · «На таможне» · «Сменить срок» · **«Приехала»** · «Отменить».

**Окно «Приехала»:** по каждой позиции «пришло» (по умолчанию = заказано) и **цена продажи** — решение
владельца: цену выставляем по приезду, не фиксируем на момент подписки. Рядом — текущая цена, себестоимость
штуки из этой партии (если внесена) и маржа при введённой цене, красным < 10 %. Новая цена применяется
до рассылки, в сообщении бота уже она. Дальше предпросмотр:
«бронь получат 8 чел (10 шт), 4 чел не хватит, 0 шт уйдёт в свободную продажу», режим раздачи
(очередь с бронью / всем сразу), текст сообщения (из шаблона) → «Подтвердить». Остаток пополняется
одной операцией, рассылка идёт в фоне с прогрессом.

### 5.2 Быстрые действия в товаре

- В списке товаров бейдж «Предзаказ» + фильтр.
- В карточке товара с нулевым остатком: кнопка «Заказал у завода» → создать поставку с этим товаром или
  добавить в открытую.
- Если остаток подняли вручную (не через поставку), а у товара есть ждущие — тост «14 человек ждут этот
  товар. Уведомить?» (не автоматически, чтобы не спамить по ошибке).

### 5.3 «Чего ждут» — подписка на любой отсутствующий товар (решение владельца: да)

На **любом** «Немає в наявності» есть кнопка «Повідомити, коли з'явиться» (бейдж остаётся серым
«Немає», без срока — поставки ведь нет). Максиму это подсвечивается везде, где он смотрит:

- **«Поставки» → вкладка «Чего ждут»:** товары/варианты по числу ждущих (людей и штук), когда встал
  первый, сколько новых за 7 дней, последняя цена продажи и маржа (если есть себестоимость) →
  кнопка «Заказать у завода» создаёт поставку с этими позициями, очередь подхватывается.
- **Главная админки:** виджет «Хотят купить» — топ-5 по ждущим.
- **Список товаров:** бейдж «ждут 7» у товаров без остатка + сортировка «по спросу».
- **Карточка товара в админке:** «Ждут: 7 чел / 9 шт» со списком.
- **Сводка раз в день** в push/группу: «Новых в очереди за сутки: 12 · топ: Lamzu Maya X (+5)».

### 5.4 Уведомления админу и метрики

- Сводка «Чего ждут» раз в день (см. выше), не на каждую подписку.
- «Бронь истекает, никто не купил» — нет, лишний шум; видно в карточке поставки.
- Метрики: подписок, приехало, купили из брони (конверсия), просрочено.

### 5.5 Настройки

Бронь по умолчанию (ч), порог показа «чекають N людей» (5), подписка без поставки (вкл.),
лимит активных подписок на покупателя (20), способ распределения расходов по умолчанию,
комиссия эквайринга для расчёта маржи (%).

## 5А. Закупка, расходы партии, себестоимость и маржа

Сейчас себестоимости в магазине **нет вообще** (конструктор кейсов считает маржу общим процентом из
настроек, `GIFT_MARGIN_PERCENT`). Поставки дают её впервые.

### 5А.1 Вкладка «Деньги» в поставке

```
Закупка у завода                     валюта: USD   курс: 41,35 ₴  [курс НБУ на дату оплаты ↻]
  Lamzu Maya X 8K белая    10 шт × $52,00 = $520,00   = 21 502 ₴
  Lamzu Maya X 8K чёрная    5 шт × $52,00 = $260,00   = 10 751 ₴
                                     итого   $780,00   = 32 253 ₴

Расходы партии                                            [+ расход]
  Доставка завод → Польша (карго)   $96      × 41,35 = 3 970 ₴   на всю партию
  Растаможка (пошлина + ПДВ)                           7 120 ₴   на всю партию   📎 фото декларации
  Брокер                                               1 500 ₴   на всю партию
  НП Ужгород → Киев                                      380 ₴   на всю партию
  Комиссия банка за перевод                              420 ₴   на всю партию
                                     итого расходов  13 390 ₴   (+41 % к закупке)

Распределение: ◉ по стоимости закупки  ○ по штукам  ○ по весу  ○ вручную

Себестоимость за штуку           закупка   + расходы   = итого    цена продажи   маржа
  Maya X белая                    2 150 ₴    893 ₴     3 043 ₴    3 999 ₴      956 ₴ · 24 %
  Maya X чёрная                   2 150 ₴    893 ₴     3 043 ₴    3 999 ₴      956 ₴ · 24 %

Статус: ⚠ предварительная — не все расходы внесены      [ Все расходы внесены ✓ ]
```

- **Валюта и курс** — на поставку (USD/EUR/CNY/UAH), курс вводит Максим; кнопка подставляет курс НБУ
  на дату (публичный API bank.gov.ua). У отдельного расхода может быть своя валюта и курс.
- **Расходы** — тип (справочник: доставка до границы, таможня/пошлина/ПДВ, брокер, доставка по Украине,
  банк/обмен, прочее), сумма, валюта, дата, заметка, фото/PDF документа (MinIO, только админам).
  Расход можно привязать ко всей партии или к одной позиции (например, пошлина только на коврики).
- **Распределение** расходов на штуки: по стоимости закупки (по умолчанию — дорогая мышь несёт больше
  таможни, чем коврик), по штукам, по весу (тогда у позиции поле «вес, г»), вручную.
- Расходы можно вносить **когда угодно**, в том числе после приезда и после продаж (таможня часто приходит
  позже). Пока не нажато «Все расходы внесены» — себестоимость помечена как предварительная.
- Брак/недовоз: «пришло» меньше заказанного → расходы делятся на пришедшие штуки (недовоз дорожает),
  можно добавить расход «компенсация от завода» с минусом.

### 5А.2 Как себестоимость попадает в продажи (партии остатка, FIFO)

**Почему FIFO («первым пришёл — первым ушёл»).** Пример: коврики, первая партия 10 шт по 500 ₴, вторая
(другой завод) 10 шт по 300 ₴, на складе 4 старых + 10 новых. Физически коврики одинаковые, поэтому вопрос
«какой именно продали» решает правило учёта, а не склад:
- **FIFO:** первые 4 продажи считаются по 500 ₴, следующие — по 300 ₴. Маржа выросла ровно тогда, когда
  кончился дорогой товар; у каждой партии свой честный итог («партия у завода №2 принесла N ₴»), а таможня,
  внесённая позже, уточняет именно свои продажи.
- **Средняя:** (4×500 + 10×300) / 14 = 357 ₴ на все 14 штук. Проще, но партии смешиваются, итог по партии и
  выгоду от нового завода не увидеть, а поздние расходы размазываются по всему остатку.

Берём **FIFO**. Сравнение заводов покажет вкладка «Продажи» у каждой поставки и строка «себестоимость по
партиям» в товаре (500 ₴ · осталось 4 / 300 ₴ · осталось 10).

Остаток в магазине остаётся одним числом (`stock`) — ничего в оформлении заказа не ломаем. Рядом ведётся
учёт **партий остатка** только для денег:

- «Приехала» → для каждой позиции создаётся партия остатка: сколько пришло, ссылка на позицию поставки.
- Продажа (заказ принят) → списываем штуки из самых старых партий (FIFO) и запоминаем у строки заказа,
  из какой партии сколько ушло. **Себестоимость берётся из партии при расчёте отчёта**, поэтому таможня,
  внесённая через неделю после продаж, сама пересчитает маржу уже проданного.
- Возврат на склад → штука возвращается в ту же партию; списание/брак → уходит из партии в убыток.
- Подарки, призы кейсов, обмены — тоже списывают партии (их себестоимость = расход магазина, впервые видно
  реальную цену кейсов).
- **Старый остаток** (то, что лежит сейчас без поставки) — решение владельца: себестоимость **не вбиваем**,
  считаем только новые поставки. При включении учёта весь текущий остаток становится стартовой партией
  «без себестоимости»; по FIFO она уходит первой, такие продажи в отчётах — «нет данных» (не 100 %).
  Отчёты показывают, какая доля выручки посчитана («маржа известна для 35 % продаж»). Для части товаров
  себестоимость можно задать позже по скринам закупок — экран «Начальная себестоимость» с вводом по
  одному товару, без обязательного заполнения.

### 5А.3 Где Максим видит маржу

- **Карточка товара (админка):** текущая себестоимость (по самой старой партии на складе), наценка и маржа
  при текущей цене; при вводе новой цены/скидки — подсказка «маржа станет 12 %» (красная < 10 %).
- **Карточка заказа:** выручка − себестоимость − скидки/промокоды/бонусы − комиссия эквайринга − подарки
  = прибыль заказа.
- **Комиссия эквайринга** — берём **фактическую** из счёта monobank (`payment_invoices.fee_minor`, приходит в
  статусе оплаты). Проверено на проде 27.10.2026: 121 оплата с 07.10 на ~103 тыс. ₴, комиссия ровно
  **1,3 %** у всех способов (карта, Apple/Google Pay, mono), иностранных карт (2 %) пока не было.
  Если у счёта нет `fee` — считаем 1,3 % (настройка). При возврате комиссию считаем удержанной (банк её
  не возвращает) — сверить на первом реальном возврате. Наложка: комиссию НП 2 % + 20 ₴ платит
  покупатель — в марже не учитываем.
- **Метрики → новая вкладка «Маржа»:** за период — выручка, себестоимость проданного, валовая прибыль, %;
  разрезы по товарам, брендам, категориям, партиям; «заморожено на складе» (остаток × себестоимость).
- **Вкладка «Продажи» в поставке (P&L партии):** потрачено всего, продано на сумму, прибыль, осталось штук
  и на какую сумму, за сколько дней разошлась партия.
- Потом (не в этой фиче): конструктор кейсов и «Вместе дешевле» берут реальную себестоимость вместо
  общего процента маржи.

### 5А.4 Доступ

Закупочные цены и маржа — **только главному админу** (и тем, кому он включит право «Финансы» в «Админах»).
В публичное API, на сайт и в Mini App не попадают никогда; в журнал действий пишется, кто менял цены и
расходы.

### 6.2 Бэкенд — пакет `preorder/` и `costing/`

- `PreorderBatchService` — CRUD поставки, статусы, смена срока (без сообщений покупателям), «приехала»
  (пополнение остатка + создание `stock_lots` в той же транзакции с `FOR UPDATE`, как в `OrderService`), отмена.
- `costing/BatchCostService` — себестоимость за штуку по позиции: закупка × курс + доля расходов по способу
  распределения; считается на лету (данных мало), без хранения итогов → правка расхода сразу видна везде.
- `costing/LotLedger` — FIFO-списание партий. Вызывается из **всех мест, где сейчас меняется остаток**:
  создание заказа, отмена/отклонение (возврат), добавление/удаление/кол-во строки, подарки и призы кейсов,
  обмен, возврат на склад, списание/брак, ручная правка остатка в товаре. Список точек — по
  `grep "setStock\|stock"` в `service/`, `gift/`, модуль `returns` (бывший `OrderAdjustmentService`), `StockWriteoff*`.
  Если партий не хватает (остаток был до учёта) — строка заказа без себестоимости, а не ошибка.
  Расхождение «stock ≠ сумма qty_left» видно в отчёте и выравнивается кнопкой.
- `costing/MarginReportService` — отчёты §5А.3; `NbuRateClient` — курс НБУ (кэш на день, ошибка → ручной ввод).
- `PreorderQueueService` — подписка/отписка, номер в очереди, раздача броней, снятие истёкших
  (`@Scheduled` каждые 5 мин, с блокировкой от двойного запуска), передача следующему.
- **Доступный остаток** = `stock − активные брони других`. Учесть в `PublicCatalogService`,
  `CartService`, `OrderService.create` (свои брони покупатель может взять). При оформлении заказа
  с забронированным товаром подписка → `BOUGHT`, при отмене такого заказа — бронь не возвращаем
  (штука уходит следующему), это проще и честнее.
- `PreorderNotifier` — сообщения через бота с паузами как в `BroadcastService`, после транзакции
  (как `OrderNotificationListener`), запись в журнал «Бот и сайт», учёт `bot_blocked`.
- Отписка покупателя, архивация/выключение товара → отмена подписок с сообщением.
- API:
  - публичное: в `ProductDto` поле `availability: IN_STOCK | PREORDER | OUT` и `preorder { etaFrom, etaTo,
    stage, waitingCount?, note }`; фильтр `availability=PREORDER`; `GET /api/preorders` — список для
    «Скоро в наявності».
  - покупатель: `GET/POST/DELETE /api/me/preorders` (+ `myQueue { position, qty, status, holdUntil }` в товаре).
  - админ: `/api/admin/preorders/batches…`, `/subscribers`, `/arrive` (с `dryRun` для предпросмотра),
    `/demand`, CSV; `/api/admin/costing/…` — расходы, распределение, начальная себестоимость, отчёты
    маржи (право «Финансы»).
- Антибот: лимит подписок, лимит количества = `antibot.maxQtyPerProduct`, rate-limit на подписку.

### 6.4 Тесты

- Бэкенд: раздача броней (хватило / не хватило / частичный приезд / два варианта), истечение и передача,
  гонка «бронь истекла ↔ покупатель оформляет», доступный остаток с бронями, отмена поставки.
- Деньги: распределение расходов 4 способами (сумма долей = сумма расходов до копейки), FIFO через две
  партии, возврат/обмен/подарок/списание двигают партии, расход внесён после продажи → маржа пересчиталась,
  товар без партий → «нет данных». Сверка на копии прода: после прогона всех заказов stock = Σ qty_left.
- e2e админки: создать поставку → подписаться покупателем (`?tgstub=`) → «Приехала» → бронь видна →
  заказ → `BOUGHT`.
- Вёрстка: 7 ширин × 3 языка (shop-ui-qa) — бейдж, строка срока и кнопка не должны переноситься/вылезать.

## 8. Решения владельца

Приняты (27.10.2026):
- «Чекають N людей» — **показывать, от 5 человек**.
- Подписка — **на любой отсутствующий товар**, спрос подсвечивать Максиму (§5.3).
- Срок — **Максим выбирает сам** в поставке: точно / диапазон / примерно, и обновляет при сдвиге (§5.1).
- Сообщения — **только по факту приезда**, без «в пути» и «задерживается» (§4.5).
- Закупочная цена, расходы партии после границы и маржа — **входят в план** (§5А).

- Раздача при приезде — **очередь с бронью 24 ч** (режим «всем сразу» оставляем только как запасной
  переключатель, по умолчанию выключен).
- Цена — **выставляется по приезду** в окне «Приехала» (§5.1).
- Комиссия — **фактическая из monobank**, по проду 1,3 % (§5А.3).
- Старый остаток — **без себестоимости**, считаем только новые поставки; часть товаров можно дозаполнить
  по скринам закупок (§5А.2). Учёт партий — **FIFO** (§5А.2).

Открытых вопросов нет — план готов к одобрению.
