# Вход в админку с двухфакторной защитой

Инструкция для владельца: как подключить приложение-аутентификатор, что делать при потере телефона
и как сбросить доступ главного админа на сервере.

---

## 1. Как теперь устроен вход

1. **Логин и пароль** (или вход через Telegram, если админка открыта из бота).
2. **Код из приложения-аутентификатора**: 6 цифр, меняются каждые 30 секунд.

Без второго шага в админку не попасть. Пароль сам по себе больше ничего не открывает.

Галочка **«Доверять этому устройству 30 дней»** на шаге с кодом: на этом телефоне или компьютере код
не будет спрашиваться 30 дней (пароль спрашивается как обычно). Ставьте её только на своих
устройствах. Забыть все такие устройства можно в «Мой аккаунт».

После 5 неверных паролей или кодов подряд вход в учётку блокируется на 15 минут, даже с верным
паролем. Бот пришлёт об этом сообщение.

## 2. Первый вход после обновления: подключаем приложение

После релиза у всех админов двухфакторная защита ещё не настроена, а все старые входы завершены.
При первом входе админка сама откроет экран **«Защита входа»**.

1. Установите на телефон приложение-аутентификатор: **Google Authenticator**, **1Password**,
   **Authy**, **Microsoft Authenticator** или любое другое с кодами «по времени» (TOTP).
2. В приложении нажмите «+» → «Сканировать QR-код» и наведите камеру на QR-код на экране.
   - Если админка открыта на этом же телефоне, нажмите **«Открыть в приложении на этом телефоне»**.
   - Или выберите в приложении «Ввести ключ вручную», нажмите в админке **«Копировать»** и вставьте
     ключ. Тип — «по времени».
3. В приложении появится строка **«ChiSetup Admin: ваш логин»** с 6 цифрами. Введите их в поле
   «Код из приложения». После 6-й цифры код отправится сам.

Готово. Дальше при каждом входе вводите код из этой строки.

> Сделайте это сразу после выкатки. Пока у учётки нет 2FA, тот, кто знает пароль, может первым
> привязать к ней своё приложение.

**Совет.** 1Password, Authy и Google Authenticator (с входом в Google-аккаунт) хранят копию ключей в
облаке. Тогда при смене телефона коды переедут вместе с приложением.

## 3. Новый телефон (старый на руках)

«Мой аккаунт» → «Двухфакторная защита» → **«Перенастроить»**:

1. введите код из **старого** приложения;
2. отсканируйте новый QR-код новым телефоном и введите код из него.

Старый ключ перестанет работать. Остальные сессии и доверенные устройства будут завершены.

## 4. Потеряли телефон

- **Обычный админ:** попросите главного админа сбросить вам 2FA (появится на этапе 2, в разделе
  управления админами). Пока этого раздела нет, поможет аварийный сброс ниже, но только для главного
  админа. Для остальных: временно через базу данных (см. конец раздела 5).
- **Главный админ:** аварийный сброс на сервере, раздел 5.

Если телефон могли украсть:

1. Войдите в админку с доверенного устройства, если оно есть.
2. «Мой аккаунт» → **«Выйти на всех устройствах»**.
3. Смените пароль.

Если бот прислал «Вход в админку… Это не вы?», нажмите **«Заблокировать»** прямо в Telegram. Все
сессии и доверенные устройства этой учётки завершатся сразу, после этого смените пароль.

## 5. Аварийный сброс главного админа (на сервере)

Сбрасывает **главного** админа, того, чей Telegram ID указан в `ADMIN_BOOTSTRAP_TG_ID`:

- пароль становится равным `ADMIN_PASSWORD` из `.env`;
- 2FA сбрасывается (при следующем входе откроется настройка);
- завершаются все сессии и доверенные устройства;
- снимается блокировка за неверные попытки.

Шаги (на сервере, в папке с `docker-compose.prod.yml` и `.env`):

```bash
# 1. В .env задайте НОВЫЙ пароль и включите флаг:
#    ADMIN_LOGIN=admin                 (логин главного админа)
#    ADMIN_PASSWORD=<новый длинный пароль>
#    ADMIN_EMERGENCY_RESET=true
nano .env

# 2. Перезапустите только бэкенд:
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d backend

# 3. Убедитесь, что сброс выполнен:
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs backend | grep -A6 "АВАРИЙНЫЙ СБРОС"
```

4. Войдите в админку с новым паролем и заново подключите приложение (раздел 2).
5. Уберите флаг из `.env` (`ADMIN_EMERGENCY_RESET=false`) и при удобном случае перезапустите бэкенд.

Сброс выполняется **один раз на значение `ADMIN_PASSWORD`**. Если забыть флаг включённым,
перезапуски ничего не сломают: в логе будет «сброс с этим ADMIN_PASSWORD уже выполнялся». Для
повторного сброса задайте другой пароль. Каждый сброс пишется в «Журнал» как «Аварийный сброс».

`ADMIN_PASSWORD` больше **не перезаписывает** пароль при каждом старте. Он нужен только для первой
учётки на пустой базе и для аварийного сброса. Обычная смена пароля делается в «Мой аккаунт».

Сброс 2FA обычного админа до этапа 2 (вручную, через MySQL):

```sql
UPDATE admin_users
   SET totp_secret_enc = NULL, totp_enabled_at = NULL, totp_pending_enc = NULL,
       totp_last_step = NULL, failed_attempts = 0, locked_until = NULL,
       token_version = token_version + 1
 WHERE telegram_user_id = <id>;
UPDATE admin_trusted_devices SET revoked_at = NOW() WHERE admin_id = <id> AND revoked_at IS NULL;
```

## 6. Настройки сервера (`.env`)

| Переменная | Что это |
|---|---|
| `ADMIN_2FA_KEY` | Ключ шифрования секретов 2FA в базе (AES-256). Сгенерировать: `openssl rand -base64 32`. Задать **до** того, как админы настроят 2FA, и потом **не менять**: со сменой ключа сохранённые секреты станут нечитаемыми, и всем придётся делать сброс. Если не задан, ключ выводится из `JWT_SECRET`, в лог пишется предупреждение. |
| `ADMIN_EMERGENCY_RESET` | `true` включает аварийный сброс (раздел 5). По умолчанию `false`. |
| `ADMIN_AUTH_RATE_LIMIT` | Запросов на `/api/auth/admin/*` с одного IP за 5 минут, по умолчанию 20. |
| `ADMIN_TRUSTED_DEVICE_DAYS` | Сколько дней доверенное устройство не спрашивает код, по умолчанию 30. |
| `ADMIN_INITDATA_TTL_SECONDS` | Сколько секунд действуют данные Telegram для входа в админку, по умолчанию 300. |

## 7. Что видно в «Мой аккаунт»

- **Профиль:** имя, логин, роль (главный админ / админ).
- **Пароль:** смена. Нужны текущий пароль и код из приложения, новый пароль от 10 символов. Все
  остальные сессии и доверенные устройства при этом завершаются.
- **Двухфакторная защита:** статус и «Перенастроить».
- **Устройства и сессии:** сколько устройств доверено, «Забыть все устройства», «Выйти на всех
  устройствах».
- **История входов:** последние 20 попыток. Для каждой видно время, город (по IP), устройство и
  браузер, способ входа (пароль или Telegram), результат. Метки «Новое устройство» и «Новый город»
  помогают заметить чужой вход. История хранится 90 дней.

Входы, неудачи, блокировки, смена пароля, настройка и перенастройка 2FA, «Забыть устройства» и
аварийный сброс пишутся в «Журнал».
