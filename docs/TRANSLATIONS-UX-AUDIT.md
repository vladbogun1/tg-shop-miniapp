# Аудит вкладки «Переводы» (админка) — 2026-10-09

Ветка `ux-i18n`. Номера строк — по состоянию **до** переработки (коммит `bad3ddf`).

## 1. Что есть

### Модель данных (бэкенд)

- `content_translations` (V21, V52): ключ `(entity_type, entity_id, field, locale)`, `text`, `source_hash`
  (SHA-256 русского оригинала, из которого сделан перевод), `origin` = `AI | MANUAL`, `updated_by`, даты.
- Русский — оригинал в основных таблицах; переводятся `uk` и `en`. Покупатель видит перевод только пока
  хеш совпадает с текущим оригиналом, иначе — русский текст.
- Сущности и поля (`TranslationEntityType`): товар (`title`, `description`, `seo_title`, `seo_description`,
  `condition_note`), вариант (`name`), категория (`name`, `seo_title`, `seo_description`, `h1`, `intro_text`),
  способ оплаты (`title`, `description`), шаблон чата (`body`). `TAG`/`BRAND` — без полей.
- Статус поля в языке (`TranslationAdminService.statusOf`, стр. 188–193): `MISSING` (строки нет),
  `STALE` (хеш не совпал — оригинал правили), `TRANSLATED`.
- Кто пишет переводы: импорт со страницы (`/import`, origin из запроса), вычитка оригинала (`/source-fix`, AI),
  «Карточки» (`CardsService.saveTranslation`, AI, MANUAL не трогает), шаблоны чата (`ReplyTemplateService`, MANUAL),
  импорт схемы каталога (`CatalogSchemaImporter`, AI).
- **Прежний оригинал не хранится** — только хеш. Для устаревшего перевода нельзя показать, что изменилось.
- **Проверка человеком не хранится** — переводы ИИ (тысячи строк) и проверенные неотличимы.

### Экран (frontend-admin)

`app/translations/page.tsx` (134 стр.) → две вкладки `SegmentedControl`:

1. **«Перевод с ИИ»** (`components/translations/AiTranslate.tsx`, 690 стр.): шаг 1 — промпт частями с
   фильтром «Всё нужное / Нет перевода / Устарело», шаг 2 — вставка ответа, шаг 3 — проверка (фильтр
   «Все / Готово / Проверить / Ошибки / Правки ru»), выбор чекбоксами, «Отправить в базу», тумблер
   «Перезаписывать устаревшие ручные переводы», итог.
2. **«Все переводы»** (`TranslationList.tsx`, 281 стр.): фильтры «Всё / Нет перевода / Устарело / Переведено»,
   тип, поиск; карточка поля ru | uk | en, карандаш (ручная правка) и «сброс» по языку.

Сверху — три KPI-карточки (uk %, en %, «Нужно перевести»), в меню — бейдж.

## 2. Сценарии владельца и где они ломаются

| Сценарий | Как сейчас | Проблема |
|---|---|---|
| Перевести новый товар | «Перевод с ИИ» → промпт по всем 300+ строкам, либо «Все переводы» → тип → поиск → карандаш на каждом поле и языке | Нельзя перевести «только этот товар / только то, что вижу»; ручной путь — 2 языка × N полей кликов |
| Обновить устаревшие после правки ru-описания | «Все переводы» → «Устарело» → старый перевод серым (opacity .6) рядом с новым ru | Не видно, **что** поменялось в оригинале; если поправили одну опечатку, «перевод всё ещё верен» сказать нельзя — только перевести заново или «сохранить» тот же текст карандашом (и он станет «ручным») |
| Массово перевести через ИИ | Шаг 1–3, по умолчанию отмечены все «зелёные» | «Отправить в базу (N)» — сразу, без подтверждения и без просмотра; после отправки переводы считаются «готово» навсегда |
| Проверить перевод ИИ | — | Сценария нет: нет очереди непроверенного, нет отметки «проверено» |
| Поправить один текст | «Все переводы» → поиск → карандаш | Общий текст (одинаковое описание у 20 товаров) правится по одному полю — 19 остаются старыми |

## 3. Конкретные UX-проблемы

### Счётчики — четыре разные единицы, которые не сходятся

1. Бейдж в меню — «поля × языки» (`lib/translations.ts:25–33`, `Shell.tsx:133`).
2. KPI «Нужно перевести» — те же «поля × языки» **и** «уникальных строк» в подписи (`page.tsx:91–97`).
3. Счётчик вкладки «Перевод с ИИ» — уникальные строки (`page.tsx:46, 105`).
4. Фильтры «Все переводы» — **поля** (без языков), и они пересекаются: поле с `uk = нет`, `en = устарел`
   попадает и в «Нет перевода», и в «Устарело», сумма больше «Всё» (`TranslationList.tsx:41–50, 121–124`).
5. Фильтр промпта «Всё нужное / Нет перевода / Устарело» — опять пересекающиеся уникальные строки
   (`AiTranslate.tsx:82–89, 281–283`).
6. Процент в KPI считается по полям одного языка (`page.tsx:69–71`) — третий знаменатель.

Итог: на одном экране числа 412, 187, 163 и «нет 95 / устарело 120» описывают одно и то же.

### Термины

7. «Готово» означает две разные вещи: статус «uk · готово» = переведено (`shared.tsx:72`) и фильтр проверки
   ответа «Готово» = «без замечаний валидатора» (`AiTranslate.tsx:441`).
8. «Проверить» в шаге 3 — это «есть предупреждения», а не «нужно проверить человеку» (`AiTranslate.tsx:442`).
9. «Перезаписывать устаревшие ручные переводы» (`AiTranslate.tsx:493`) — на деле `force=true` для всего запроса;
   владелец не знает, какие именно ручные переводы будут затёрты.
10. «нет», «устарел», «ручной», «Правки ru», «×3 полей», `t3fa9c1` (id в карточке) — техническая лексика.

### Действия вслепую и тупики

11. Отправка ответа ИИ — одной кнопкой без подтверждения и сводки (`AiTranslate.tsx:489`), «зелёные»
    предвыбраны автоматически (`AiTranslate.tsx:141`). Это ровно «принять вслепую» из «Карточек».
12. После импорта переводы ИИ неотличимы от проверенных — проверить их потом нельзя (нет очереди, нет отметки).
13. Устаревший **ручной** перевод блокирует импорт ИИ (`TranslationAdminService.java:259–263`), выход — найти и
    включить тумблер (п. 9) или подсказка «поправьте во вкладке «Все переводы»» (`AiTranslate.tsx:683–686`).
14. Устаревший перевод: нет сравнения «было → стало» в оригинале — бэкенд не хранит прежний текст (п. 1.1).
15. Нет действия «перевод всё ещё верен» для устаревшего (опечатка в ru) — только перевод заново.
16. Ручная правка — по одному полю и одному языку (`TranslationList.tsx:68–92`); общие тексты дублируют работу.
17. Нет «следующего»: после сохранения пользователь сам ищет следующую карточку; горячих клавиш нет.
18. Вкладка «Перевод с ИИ» открыта по умолчанию даже когда всё переведено (`page.tsx:33`, empty state
    `AiTranslate.tsx:256–264`), а «Все переводы» — 40 карточек + «Показать ещё» (`TranslationList.tsx:27, 250–256`).
19. Сброс перевода — маленькая иконка ↺ рядом с карандашом (`TranslationList.tsx:204–214`), легко промахнуться.
20. Промпт пересобирается при каждом обновлении данных (`AiTranslate.tsx:95–104`): после отправки части 1
    нумерация частей и состав меняются под руками, отметки «скопирована» сбрасываются только фильтром.
21. Поиск не учитывает категорию/шаблон в контексте и не ищет по типу поля.

### Мелочи

22. В «Все переводы» тип «Варианты» отдельно от «Товары», а поиск по товару не находит его варианты, если
    в тексте нет названия.
23. KPI-карточки с анимацией появления занимают первый экран на телефоне, полезное — ниже сгиба.

## 4. Решение (реализовано в этой ветке)

- **Единица работы — уникальный русский текст** (как в промпте ИИ): одно описание у 20 товаров — одна строка,
  перевод/принятие пишется во все поля с этим текстом.
- **Вкладки по задачам**, каждая строка ровно в одной (суммы сходятся):
  «Нужно перевести» (нет перевода хотя бы на одном языке) → «Устарели» (оригинал правили) →
  «Проверить ИИ» (перевод ИИ, человек не смотрел) → «Готово». Фильтры: язык (оба / uk / en), тип, поиск.
  Бейдж меню = «Нужно перевести» + «Устарели» в тех же единицах (`stats.pendingTexts`).
- **Режим просмотра** строки: оригинал и переводы бок о бок, для устаревших — подсветка изменений оригинала
  (бэкенд теперь хранит снимок оригинала `source_text`, V56), правка на месте с живой проверкой,
  «Принять» / «Пропустить» / «Назад», горячие клавиши (Ctrl+Enter, Alt+↑/↓, ←/→, Esc).
- **«Принять»** = «то, что в полях, — верно»: изменённый текст сохраняется как ручной, непроверенный ИИ
  помечается проверенным (`reviewed_at`), устаревший без правок — «перевод всё ещё верен» (перепривязка к
  новому оригиналу, `PUT /accept`).
- **ИИ-перевод** (промпт → ответ → проверка) переиспользован, запускается для **того, что сейчас в списке**;
  части промпта замораживаются на время работы; отправка — только через окно подтверждения со сводкой
  (сколько строк, полей, языков, сколько ручных переводов заменится, сколько правок оригинала); ручные
  переводы заменяются только у явно отмеченных строк (вместо глобального тумблера).
- Импортированное ИИ попадает в «Проверить ИИ», а не в «Готово».
- Массовое «Принять все на вкладке» — только с подтверждением и честной формулировкой.

## 5. Спорные решения

- Единица — уникальный текст, а не поле: правка общего описания меняет перевод у всех товаров с этим текстом
  (так же, как уже работала вычитка оригинала). В режиме просмотра показано, где текст используется.
- Существующие переводы ИИ (сотни строк) после миграции все окажутся в «Проверить ИИ» — это честно, но очередь
  большая; в бейдж меню она не входит. Для разбора — массовое «Принять все» с подтверждением.
- Все переводы, существовавшие до V56 (ручные и ИИ), миграция считает проверенными (`reviewed_at = updated_at`): они давно на витрине, иначе «Проверить ИИ» открылась бы с ~450 строками. В очередь попадают только переводы ИИ, импортированные после релиза.
- Снимок оригинала есть только у переводов, сделанных/подтверждённых после V56, и у текущих актуальных
  (заполняется при старте бэкенда). Для уже устаревших до V56 прежний текст потерян — экран так и пишет.
