# 04. Встроенный ИИ в админке: финальный дизайн

Статус: финальная версия после трёх критик (UX, бизнес/деньги, техника). Документ самодостаточный: «см. v1» нигде нет. Макеты: [`mockups/index.html`](mockups/index.html) (телефон 375 и 320, десктоп 1280; стиль новой админки, без маскота; цифры и имена придуманы). Бизнес-требования: `01-business.md`, поведение бэкенда: `docs/AI.md`.

---

## 0. Что изменилось против первой версии (коротко)

1. **Задачи живут в базе.** Это условие релиза любого экрана. Пока таблицы `ai_jobs` нет, интерфейс не обещает «закройте экран» и «продолжу в фоне»: только ожидание с предупреждением (п. 12).
2. **Дизайн урезан до ядра.** Вырезаны: лимит на админа, режимы качества по функциям, блок «Показ», «Что видит админ», «Сэкономлено», срезы по админам и p50/p95, фильтры центра задач, «без поиска с пометкой», автопродолжение пакета, галочка «Сразу выложить», двухколоночное ревью на ПК.
3. **Ревью карточки переделано под телефон:** полноэкранная страница, группы сворачиваются, подозрительное сверху, футер в две строки, одно число «выбрано N из M».
4. **Деньги защищены жёстко и просто:** лимиты месяц / день / пакет, резерв в базе, потолок на задачу, одна кнопка-выключатель, обязательные предупреждения владельцу через push.
5. **Массовое принятие ограничено:** только «пусто → заполнено», без сомнительного, никогда не публикует, с подтверждением точного числа и откатом на сутки.
6. **Ручной путь нарисован там, где он нужнее всего:** поставка без картинок, пачка «часть 2 из 6», лимит, сбой. Он становится главной кнопкой, а не серой подписью.
7. **Метрики отвечают на вопрос владельца:** состоялся ли переход на встроенный путь, сколько стоит принятая карточка, сколько денег ушло зря. Четыре плитки, остальное в «Подробнее».
8. **Порядок релизов:** 1 карточка (и дозаполнение), 2 пакет, 3 переводы, 4 поставка.

## 1. Принципы

1. **Основной путь = одна акцентная кнопка в контексте** («Заполнить с ИИ», «Прочитать с ИИ», «Перевести с ИИ») с иконкой ✦. Ручной путь («Через ChatGPT вручную») рядом, как заметная ссылка высотой 44 px.
2. **Ручной путь выходит вперёд** (становится акцентной кнопкой, ИИ-кнопка скрыта) каждый раз, когда ИИ недоступен: выключен, лимит, ключ, нет связи, поиск лежит, три сбоя подряд, нет входных картинок. Серой мёртвой кнопки без причины нет. Причина и время «когда продолжится» пишутся всегда.
3. **Один паттерн на все функции:** вход → (подтверждение только если нужно) → фон → «Готово, проверьте» → ревью → применить. Один движок, один журнал, одно ревью.
4. **ИИ ничего не публикует и не заменяет чужую работу сам.** Публикация товара только поштучно, отдельным действием как сейчас. Поле, заполненное человеком, не заменяется без отдельного включения.
5. **Админ не видит денег** (константа, не настройка). Различие показывается отсутствием поля, а не пометкой «(видит владелец)». Это обеспечивается на сервере: админу уходит `JobView` без денег и промпта, владельцу `JobDetail`.
6. **Админке нужно работать на телефоне:** касание ≥ 44 px (строка поля ≥ 48), шрифт не меньше 13 px там, где человек принимает решение, макеты проверены на 320 и 375.
7. **Единые решения, а не зоопарк:** один компонент «причина + ручной путь» на все недоступности; одно число «ждёт проверки» из одного запроса; одна формула счётчика ревью; один способ читать деньги (`money(costMinor)`).

Названия для владельца: раздел **«ИИ-задачи»** (Каталог → ИИ-задачи), вкладка **«ИИ»** в «Метриках», группа **«ИИ»** в «Настройках».

## 2. Единый паттерн ИИ-запуска — [01-pattern.html](mockups/01-pattern.html)

### 2.1. Кнопка-вход

| Где | Вид |
|---|---|
| Футер окна на телефоне | Акцентная кнопка 48 px на всю ширину, под ней оценка, ниже ссылка «Через ChatGPT вручную» (44 px) |
| Футер окна на ПК | Кнопка 220×44, справа оценка, у правого края ссылка ручного пути |
| Панель выбора в списке | `Заполнить с ИИ (N)` + «⋯» (ручные пачки по 4/8) |
| Панель над списком («Переводы») | Кнопка справа; объём = то, что показывает фильтр |

Подпись-оценка: владелец «≈ 0,2 ₴ · около минуты» (p50 за 30 дней по этой функции; пока меньше 10 завершённых задач, берутся константы замера), админ «около минуты». Для пачки админу «12 товаров · около 8 минут», владельцу ещё и диапазон «2–3 ₴». Суммы меньше копейки: «< 1 коп.».

Режима «быстро / обычно / тщательно» при старте **нет**: запуск всегда «обычный». «Тщательнее» доступно как один повтор в ревью (п. 2.6).

### 2.2. Недоступность: один компонент (вместо шести состояний)

Баннер «причина + когда продолжится» + акцентная кнопка ручного пути; ИИ-кнопка не показывается.

| Причина | Текст админу | Текст владельцу (добавка) |
|---|---|---|
| ИИ выключен | «ИИ отключён владельцем. Можно через ChatGPT вручную.» | «Выключен вами в Настройках → ИИ. [Включить]» |
| Лимит дня | «Лимит ИИ на сегодня исчерпан. Продолжится завтра в 00:00. Осталось вручную: Скопировать промпт.» | «День: 40 из 40 ₴. [Поднять лимит]» |
| Лимит месяца | «Лимит ИИ на месяц исчерпан. Обратитесь к владельцу или работайте вручную.» | «Месяц: 420 из 420 ₴. [Поднять лимит]» |
| Нет связи | «Нет связи с сервисом ИИ. Попробуйте через минуту или вручную.» | то же + «Проверить сейчас» |
| Поиск недоступен | «Поиск сейчас недоступен. Подождать (задача встанет в очередь) или вручную.» | «Свой поиск в паузе, платный выключен. [Настройки поиска]» |
| Ключ не принят | то же, что «Нет связи» | «Ключ ИИ не принят провайдером. Проверьте ключ в .env сервера.» |
| Нет картинок (только поставка) | «Нет скринов или PDF. Скопируйте промпт и вставьте текст накладной.» | то же |

Админу вместо денег: «осталось примерно N карточек» (считается от остатка и p50).

### 2.3. Подтверждение (шторка на телефоне, окно 520 на ПК)

Показывается, когда пакет > 5 товаров, или оценка > 2 ₴, или это повтор пакета. Один товар, накладная, перевод до 60 строк идут сразу.

- **Админ:** «38 товаров, около 25 минут». Максимум пакета (по умолчанию **30**) блокирует запуск: «Максимум 30 за раз. Выберите меньше.» Кнопка запуска серая, причина рядом. Рублей нет.
- **Владелец:** «2–3 ₴ (обычно 2,2 ₴), около 25 минут. Лимит дня: хватит, останется 31 ₴» либо «Не хватит: нужно до 3 ₴, осталось 1,5 ₴ (запуск заблокирован)». Если поиск уйдёт на платный Serper, строка «Если поиск уйдёт на Serper: до 6 ₴».
- Общее: «Можно закрыть экран: задача идёт на сервере» (только при готовом ai_jobs). Повтор неудачных идёт через это же подтверждение.

### 2.4. Двойной запуск

«Уже идёт: запустила Анна, 1 мин назад». Кнопки: **«Смотреть ход»** и **«Сообщить мне»** (подписка на готовность). Сервер возвращает 409 с данными активной задачи; кнопка на время запроса блокируется (идемпотентный ключ).

### 2.5. Ход работы

Шаги простыми словами («Ищу в интернете», «Читаю страницы», «Собираю ответ»), таймер, прогресс-полоса. Кнопки «Закрыть, задача идёт на сервере» и «Остановить» (отмена между ходами: текущий шаг может доработать до 3 минут, это написано). Через 3 минуты подсказка «Это дольше обычного». Механика («3 поиска, найдено 4 страницы», «поиск не нужен») только в «Подробнее» у владельца. У товара или строки метка «ИИ работает».

### 2.6. Результат, ревью, повтор

Тост готовности один на пачку готовых задач («Готово 5 · Открыть», до 6 секунд, пауза при наведении, `role=status`). Само ревью см. п. 3.1.

**Повторы:** на задачу один усиленный повтор «Повторить тщательнее» (на 1 шаг глубже, дороже; цена в кнопке видна владельцу, админу «займёт дольше»). Дальше только владелец. Повтор создаёт новую задачу со ссылкой на прежнюю.

### 2.7. Статусы (всегда с текстом, не только цветом)

| Статус | Что значит | Следующий шаг |
|---|---|---|
| Идёт | работает | смотреть ход / остановить |
| Проверить | готово, ждёт решения человека | открыть ревью |
| Применено | принято (полностью, частично, с правками) | открыть карточку |
| Не нашёл данных | ИИ ответил, но полей нет (структурно пусто) | повторить тщательнее / вручную |
| Сбой | ответ не читается или сервис упал | повторить / вручную / показать ответ |
| Сбой сервера, повторите | задачу убил перезапуск, автоповтор не помог | повторить |
| Отменена | остановил человек | запустить заново |
| Пауза | пакет остановлен (лимит, перезапуск) | «Продолжить» кнопкой |

Статусы «Проверить / Не нашёл данных / Сбой» выставляет **бэкенд** по структурной проверке (JSON читается, есть блок на каждый объект, хоть одно непустое поле). Смысловую проверку (подозрительные числа) делает фронт при открытии ревью.

### 2.8. Ручной путь без потерь

«Через ChatGPT вручную» ведёт **сразу к собранному промпту** (три шага: Промпт, Ответ, Проверка). Вверху «Вернуться к встроенному ИИ ✦». Финал один: то же ревью. Если админ уже снял галочки или правил поля, а потом вставил новый ответ, спрашиваем «Сохранить ваши правки поверх нового ответа?» (по умолчанию да). В журнале путь: «встроенный» / «вручную» (и причина ручного: лимит, сбой, выбор). «Показать промпт» остаётся только у владельца в «⋯» как отладка.

### 2.9. Индикатор ✦ в шапке (один источник числа)

Чип виден **всегда** (телефон 320, 375, ПК), питается одним лёгким запросом `GET /ai/jobs/active`:

| Состояние | Вид | aria-label |
|---|---|---|
| идёт N | оранжевый, пульс, «✦ N» | «ИИ: идёт N задач» |
| ждёт проверки M | оранжевый без пульса, «✦ M» | «ИИ: M ждут проверки» |
| проблема | жёлтый | «ИИ: есть проблемы» |
| выключен | серый, «✦ выкл» | «ИИ выключен» |
| пусто | серый «✦» | «ИИ: задач нет» |

Тап: шторка (телефон) или поповер (ПК) со списком идущих и ждущих. Число «ждёт проверки» то же самое, что на вкладке «Проверить»; **бейдж в меню только у «ИИ-задачи»**, в колокольчик и в виджет оно не дублируется (там ссылка). Опрос: 4 с при идущих задачах и видимой вкладке, иначе 60 с, плюс обновление при возврате на вкладку и появлении сети. Мгновенные тосты через сокеты и push готовности (п. 8.3) вне первого релиза.

## 3. Функции

### 3.1. Карточка одного товара и дозаполнение (релиз 1) — [02-card.html](mockups/02-card.html)

Одно окно на три входа (после создания товара, строка списка, товар поставки).

**Старт.** Мини-карточка товара (заполнено 62 %, пусто 8 из 21), фото (добавить 3, только если у товара нет фото), число подсказок. Кнопка «Заполнить с ИИ», под ней оценка, ссылка ручного пути. Выбора режима нет.

**Работает.** П. 2.5.

**Ревью (на телефоне полноэкранная страница, не шторка; без нижней панели навигации).**

Шапка: «Lamzu Maya X 8K», подпись «Заполнено встроенным ИИ · задача № 412», счётчик **«Выбрано 9 из 12»**.

Формула счётчика одна: *M = число полей, которые можно применить* (группы «Проверьте», «Заполнит пустое», «Заменит значение»; замок «Заполнено не ИИ» и «оставить пустым» не входят); *N = из них включено*. Число в шапке и в кнопке «Применить (N)» берётся из одного состояния. Для этого есть unit-тест: сумма включённых по группам = N, кнопка = N.

Группы, в таком порядке:
1. **Проверьте** (сомнительно: красное и жёлтое). Выключено. Развёрнута, если полей ≤ 5, иначе свёрнута с красной точкой. Красное нельзя применить, можно «Оставить пустым». Причина простыми словами 13 px: «Единицы: у других глайдов 256, тут 256000».
2. **Заполнит пустое.** Включено. Развёрнута.
3. **Заменит значение.** Выключено. Свёрнута.
4. **Заполнено не ИИ** (замок). Свёрнута. Строка: «Иван правил 14:20».

Строка поля: вся строка нажимается (≥ 48 px) и включает/выключает поле. Значение «было → стало» 14 px, имя поля, **уверенность цветом** (точка слева: зелёная, жёлтая, красная), без числа. Справа шеврон: по тапу раскрывается «Источник» (иконка-ссылка, название сайта) и «Причина сомнения». Источник и причина не видны, пока не раскрыты (кроме жёлтых и красных: у них причина сразу).

Футер (две строки, одна полоса, не плавает над списком):
- Строка 1: **«Применить (9)»** и «⋯».
- «⋯»: «Повторить тщательнее» (один раз), «Через ChatGPT вручную», «Отклонить результат», «Показать ответ» (при «Сбой»), у владельца «Показать промпт».
- «Сразу выложить на витрину» из футера **убрана**: публикация отдельным действием в карточке.

**Конфликт правок** (пока работал ИИ, карточку изменил другой админ). Задача хранит версию карточки на момент старта. При открытии ревью изменённые после старта поля блокируются, а в строке пишется: **«Иван изменил в 14:20: было 6 → стало 7 → ИИ предлагал 8»**. Если изменено ≥ половины предложенных полей, наверху баннер и кнопка «Повторить на актуальной карточке (≈ 0,2 ₴)» (владельцу цена, админу «около минуты»). Деньги не пропадают молча.

**Определение «Заполнено не ИИ»:** значение не пусто и (нет записи в `card_meta` о том, что его заполнил ИИ, или `edited = true`). Для карточек READY без метки автора непустое значение защищено по умолчанию: замена выключена и без «рекомендуем». До релиза измеряется на проде доля заполненных полей с меткой автора (чтение, `shop-db-report`); результат пишется в `HANDOFF.md`.

**Лимит, ключ и т. п.** Один компонент из п. 2.2.

**ПК:** окно 620 на старте, на ревью 760 в один столбец (так же, как телефон, с прокруткой списка и футером в нижней части окна). Выбор фото — отдельная секция внутри списка полей (если у товара нет фото), не отдельная колонка.

### 3.2. Пачка (релиз 2) — [03-batch.html](mockups/03-batch.html)

Выбор строк → «Заполнить с ИИ (N)» → подтверждение (п. 2.3) → полоса над списком **«Идёт пакет: 12 из 30 · Остановить»** (владельцу ещё «потрачено 2,4 ₴») → готовое появляется во вкладке «Проверить» по мере готовности.

- **Максимум пакета 30**, на всех экранах, в подтверждении и в настройках одно число. Больше — разбивайте.
- **Параллелизм 2** при ≥ 20 товарах; общий лимитер темпа поиска (не более 40 поисков за 5 минут, настройка в «Дополнительно» у владельца); упёрлись — задачи ждут в очереди, а не падают.
- **Лимит посреди пакета:** статус «Пауза», **автопродолжения нет**. Текст: «Готово 18 из 30. Остальные 12 ждут. Лимит дня исчерпан. Продолжить можно завтра кнопкой «Продолжить» или оформить вручную».
- **Перезапуск сервера:** пакет встаёт на «Пауза: сервер перезапускали. [Продолжить]».
- **Итог:** «Готово 22 · Не нашёл данных 5 · Сбой 3» и три кнопки: «Проверить готовое», «Повторить неудачные (8)» (через подтверждение), «Вручную». Три сбоя подряд останавливают пакет и предлагают ручной путь.
- **Ручной путь для пачки** — экран «Часть 2 из 6» (по 4–5 товаров): промпт, поле ответа, «Дальше». Вставленное сохраняется в черновике при выходе («Вернуться: часть 2 из 6, вставлено 1 из 5»). Это запасной путь на случай паузы, не основной.

**Быстрая проверка (лента), основной способ разбирать готовое из пачки.** Один товар на экран, показываются только поля «Проверьте» и «Заполнит пустое» (замены и замок только числом). Кнопки: **«Принять»** (применяет включённое по умолчанию), **«Позже»**, **«Править»** (открывает полное ревью). Счётчик «7 из 22 разобрано». Принять без чтения нельзя: кнопка активна после показа первого экрана полей; быстрее 5 секунд при ≥ 10 полях считается в метрике «применено не глядя».

**«Принять безопасное (N)»** (массовое):
- применяет только поля вида «пусто → заполнено», не жёлтые и не красные, только из задач, где был поиск и есть источник;
- ничего не заменяет, ничего не публикует;
- перед применением подтверждение с точными числами: «Заполнит 143 пустых поля в 21 товаре. Ничего не заменит и не опубликует»;
- после применения откат кнопкой «Отменить применение» в течение 24 часов (возвращаются только поля, которые с тех пор не правили вручную). **Если откат не успевает в релиз 2, массовое принятие в релиз 2 не входит.**

### 3.3. Поставка (релиз 4) — [04-supply.html](mockups/04-supply.html)

Лента из четырёх шагов: Файлы → Чтение → Строки → Форма поставки.

- **Файлы.** Скрины и PDF загружаются отдельно на сервер (до 10 файлов, 10 МБ каждый, JPEG/PNG/WEBP/PDF; PDF до 10 страниц). Надпись: **«Файлы хранятся 7 дней и удаляются сами»**. Поставщик, кнопка «Прочитать с ИИ», оценка «≈ 0,1 ₴ · около 10 секунд».
- **Состояние «нет картинок» нарисовано:** кнопка ИИ скрыта; акцентная «Скопировать промпт», рядом поле «Вставьте ответ». Это же состояние показывается, пока загрузка файлов на сервер не готова.
- **Результат.** Плашка «Прочитано 6 из 6, сумма сошлась, повторы на стыках убраны». У каждой строки метка **с действием**: «Из памяти поставщика» (ничего делать не нужно), «Новый товар?» → **[Выбрать товар] [Создать новый] [Пропустить]**, «Нет в каталоге» → те же три действия. Строки без выбора не дают перейти дальше.
- **Дальше.** Строки приходят в **ту же форму поставки**, что и при ручном вводе, с теми же правилами владельца из `DECISIONS` П.20 (курс НБУ, цена ×2 для новых товаров, количество × цена, повтор строки) и подсвечены «из ИИ, проверьте» до подтверждения строки. Исходные скрины рядом с таблицей (ПК) или по тапу (телефон).

## 4. Центр ИИ-задач — [06-task-center.html](mockups/06-task-center.html)

**Строка-итог месяца:** «Принято 74 карточки, потрачено 19 ₴, около 0,26 ₴ на карточку».

**Четыре плитки:**

2. **Через встроенный ИИ:** «86 %», подпись «вручную 12: лимит 3, сбой 4, по выбору 5». Это главная цель: состоялся ли переход.

**Нет:** «Сэкономлено ≈ 9 часов», срезы по админам, p50/p95, топ исправляемых полей, доли починки JSON (всё это этап 2 при необходимости).

## 8. Бэкенд-контракт, от которого зависит дизайн

Это условия релиза, а не пожелания. Подробности в `03-critique-tech.md`.

### 8.1. Условия релиза 1

1. `ai_jobs` — единственный источник правды: статусы, heartbeat раз в 15 с, `FOR UPDATE SKIP LOCKED`, зависшей считается RUNNING с heartbeat старше 60 с; при остановке сервера задача возвращается в QUEUED, один автоповтор с начала. Параллелизм считается по RUNNING в базе.
2. Контракт `POST /jobs {feature(enum), subjects[], mode(normal|thorough), prompt, files?}`; бюджет поиска и `effort` бэкенд выводит сам; `prompt` и `prompt_version` сохраняются; пакет — один `POST /batches`. Оценка — `POST /estimate`.
3. Структурная проверка ответа → DONE / EMPTY / BAD_ANSWER. Обратная связь `POST /jobs/{id}/outcome {applied, rejected, edited[], ignoredLocked}` идемпотентна.
4. Уникальность активной задачи по `(subject_type, subject_id)`; дубль даёт 409 с данными. Отмена через `cancel_requested`. `killSwitch` и `enabled` читаются из базы на каждом шаге.
5. Лимиты: резерв `ai_reserve` по p90-оценке, проверка суммы потрачено + активные резервы под коротким замком в БД; границы дня по `ShopZone`; сбой записи журнала не глотается. `feature` — enum. Потолок расхода и дедлайн на задачу.
6. Версия карточки (`subject_version`) сохраняется при старте; диф считается на фронте при открытии ревью.
7. Права: `JobView` без денег и промпта для админа, `JobDetail` для владельца; `/status`, `/search-test`, метрики, настройки под правом владельца; в API ключ только «задан / нет». Аудит: `AdminAuditService.record`.
8. Деньги: микро-доллары как факт, курс на момент завершения в `ai_jobs.rate_milli`, API отдаёт `costMinor`; фронт `money(costMinor)`.
9. Предупреждения: `ai_alerts` + `AdminPushService`.
10. Миграции только добавляющие; номера перенумеровать перед слиянием (`ai_usage` → V86, остальные V87+ с учётом ветки Новой почты). Откат образами через `rollback.sh`.
11. **Характеризующие тесты** на поведение `AiJobs` (BUSY, FAILED, DONE) и лимит месяца до переписывания очереди; затем интеграционный тест на MySQL (два исполнителя, reaper, резерв).

### 8.2. Дополнительно для следующих релизов

- Релиз 2: `POST /batches`, общий лимитер темпа поиска и «отдых» провайдера в БД, откат применения (`before-values` в outcome), пауза пакета после перезапуска.
- Релиз 4: загрузка `POST /ai/files` в MinIO (TTL 7 дней), даунскейл до 1600 px, PDF → PNG до 10 страниц, мультимодальный запрос.

### 8.3. Вне первого релиза
Сокет-тосты, push готовности, лимит на админа, пороги авто-READY как настройки, SEO-поля.

## 9. Фронт: как держать кодом

- Новая фича `frontend-admin/features/ai/` с публичным `index.ts`: `AiEntryButton`, `AiJobSheet`, `AiReview`, `AiTaskCenter`, `AiSettings`, `AiMetrics`, чип шапки.

- Состояние задачи — чистая машина состояний `model/job-state.ts` с таблицей переходов и unit-тестами. Ревью строится из `parseAnswer` + состояния, счётчик считается одной функцией.
- Лимиты кода: файл ≤ 400 строк, компонент ≤ 200, сложность ≤ 15. `use-card-completion` (около 20 `useState`) не раздувать: ревью выносится в `ai/`.
- Деньги только `core/money`, запросы только `HttpClient`, `useApiMutation` с идемпотентным ключом, тексты в словаре админки (русский).
