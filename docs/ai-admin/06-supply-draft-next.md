# «Поставка с ИИ» после v3.53.0 — что нелогично и что делаем дальше

Статус: план, ждёт «да» владельца. Основа — первый боевой черновик на проде (№1, накладная WESTLAB, 08.11.2026)
и экран «ИИ-задачи» после него.

## 1. Сопоставление промахивается: ИИ не видит наш каталог

### Что было в черновике №1

| Строка накладной | Что решил ИИ | Что есть у нас |
|---|---|---|
| L1 `西城WESTLAB小圆点脚贴`, вариант «6.5 мм микро-плоские точки, 30 шт», 20 шт × 8,96 CNY | **новый** «Глайды WestLab Universal Dots V2 6.5 мм…, 30 шт» | «Глайды WestLab Universal Dots V2 черные 30 шт.» (остаток 19) + Universal Dots ещё 8 цветов |
| L2 `WEST LAB西城超薄聚氨酯防滑贴`, «1 лист», 20 шт × 7,4 CNY | **новый** «Противоскользящая наклейка WestLab Grip Tape…» | «Грипсы WestLab Universal Grip Tape 0.2/0.55 мм» (остаток 20) |
| L3 `西城WESTLAB特氟龙UPE鼠标脚`, «синие точки 20 шт» | сопоставил: «Universal Dots синие» | верно |

Две из трёх строк ушли бы в каталог дублями.

### Почему

ИИ выбирает только из кандидатов, которых ему заранее подобрал наш код (до 8 на строку). Кандидаты были плохими:
- L1 — «(нет похожих)», хотя WestLab-глайдов 9;
- L2 — «Ковер STAR SHADOW 1» и кейкапы «на 1\3 клавы»: совпало только слово «1»;
- L3 — один кандидат (нашёлся по «синие»).

Причины в поиске кандидатов (`SupplyMatcher.candidatesOf`, `SupplyText.words`):
1. Латиница слеплена с иероглифами: `西城WESTLAB小圆点脚贴` — одно «слово», бренд из него не выделяется.
2. `WEST LAB` с пробелом ≠ `WestLab` в каталоге.
3. Строка — по-китайски/по-английски («mouse feet», «grip tape»), каталог — по-русски («Глайды», «Грипсы»). Общих слов почти нет.
4. Ответ с товаром не из списка кандидатов сервер отбрасывает (`MatchPrompt`: «товар … не из списка кандидатов»).
   Так что даже если бы модель знала про наш товар, выбрать его она не могла.

### Что делаем

**Да, отдаём ИИ весь каталог.** Это дёшево и надёжнее любого поиска:
- товаров не в архиве — 471 (279 на витрине + 192 скрытых), вариантов — 48, названия ≈ 16 тыс. символов;
- компактно, по категориям и брендам: `## Глайды` → `WestLab: p8cad1a34 Universal Dots V2 черные 30 шт · paf69c4a5 Universal Dots синие · …`;
  это ≈ 8–12 тыс. токенов. У MiniMax Flash это доли гривны за поставку, а неизменный каталог в начале промпта ещё и кэшируется;
- скрытые товары тоже идут (с пометкой «скрыт»): туда попадают товары, заведённые прошлыми черновиками; архив — нет;
- ответ проверяем по всему каталогу, а не по списку кандидатов;
- кандидаты кода остаются подсказкой: «скорее всего одно из: …».

**Чиним и сам поиск кандидатов** (он нужен для подсказок, ручного пути и «уверенных» совпадений без ИИ):
- отделять латиницу от иероглифов (`西城WESTLAB小圆点` → `westlab`);
- сравнивать бренды без пробелов и регистра (`WEST LAB` = `WestLab`) и по алиасам бренда;
- если в строке узнан бренд — все товары этого бренда в кандидаты;
- словарь родовых слов en/zh → наша категория: mouse feet / skates / 脚贴 → «Глайды», grip tape / 防滑贴 → «Грипсы», mouse pad / 鼠标垫 → «Коврики», keycaps / 键帽 → «Кейкапы» и т. д.

**Третий исход «не уверен между нашими».** Сейчас у ИИ есть только «это товар X» или «новый». Для L1 честный ответ —
«это наш Universal Dots V2 30 шт, но цвет в накладной не указан». Добавляем решение «выберите из этих» со списком: строка
остаётся нерешённой, с готовыми кнопками этих товаров. Новый товар ИИ предлагает, только если в каталоге нет этой модели
ни в каком цвете.

**Проверка.** Перед выкаткой прогнать черновик №1 заново (та же накладная) на копии прода: L1 → «выберите из Universal
Dots V2 30 шт» или V2 черные, L2 → «Грипсы WestLab Universal Grip Tape», L3 → синие. Плюс e2e с fake-ai на ответ вне списка
кандидатов.

## 2. «ИИ-задачи → Проверить» засоряется задачами поставки

Вкладка показывает любую готовую задачу, по которой никто не нажал «Применить» или «Отклонить». У шагов поставки
(разбор, сопоставление, карточки новых товаров) такого решения нет: они решаются на экране черновика. Поэтому они висят
там вечно и накручивают ✦. «Карточка» без названия — это карточка нового товара из черновика. Её «Проверить» ведёт на
обычную проверку карточки товара, которого ещё нет.

Делаем:
- в «Проверить» — только то, что проверяется на своём экране (карточки товаров). Задачи поставки — в «Истории» с подписью
  «Черновик поставки №1 · Грипсы …» и ссылкой на черновик;
- решение ставится само: «Принять» черновик → его задачи «применены»; удалить черновик → «отклонены»; старый ручной
  путь: создали поставку → «применено». Метрики ИИ («сколько работы ушло зря») станут честными;
- миграция-чистка: уже висящие задачи поставки получают решение (не удаляются).

## 3. Черновика нет во «Внимании»

Push пришёл, закрыли — и напоминания нигде нет, кроме «Поставок».

Делаем: группа «Поставки ждут проверки» во «Внимании» (источник `InboxExtraSource`, как у поддержки и отзывов):
- «西城外贸 · 3 строки, 2 новых · Готово — проверьте» → черновик; можно отложить, как остальные строки;
- пропадает сама, когда черновик принят или удалён;
- «Не вышло» — там же, с переходом к «Повторить»;
- видят создатель и финансисты (как и сам черновик).

## 4. Мелочи, которые тоже нелогичны

- После «Принять» новые товары скрыты, и о них легко забыть → на странице поставки плашка
  «Новые товары: N скрыты — посмотреть / опубликовать».
- Ту же накладную можно разобрать второй раз и заплатить за ИИ снова → при запуске: «этот файл уже в черновике №1 —
  открыть?» (по хэшу файла за последние дни).
- «Не вышло» не напоминает о себе → закрывается пунктом 3.

## Порядок

Один релиз (минорный): сначала сопоставление (п. 1, самое важное: иначе дубли в каталоге), затем п. 2–4.
