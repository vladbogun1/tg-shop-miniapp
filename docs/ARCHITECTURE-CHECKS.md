# Автоматические проверки архитектуры

**Принцип: старый долг заморожен, новый запрещён.** Правила из `CLAUDE.md` агенты и люди со временем смягчают,
поэтому строгость держат проверки в CI: всё, что нарушало правило на 29.10.2026, записано в список исключений
и пока терпится, любое новое нарушение валит `mvn -B -ntp test` или `npm run lint`.

Список исключений — это долг, а не разрешение. Он может только **уменьшаться**.

## Бэкенд (`backend/`, часть `mvn -B -ntp test`, без Spring-контекста)

| Проверка | Где | Исключения |
|---|---|---|
| Контроллеры (`..web.controller..` и `*Controller`) не обращаются к репозиториям (`..repository..` и наследники Spring Data `Repository`) | `architecture/ArchitectureTest` | `src/test/resources/archunit_store/` |
| Нет **новых** циклов между пакетами верхнего уровня `com.maxsolch.shop.*` | `ArchitectureTest` + `CyclicPackageDependencies` | там же |
| `Order.setStatus(…)` вызывается только из 10 уже существующих методов (`OrderService`, `OrderAdjustmentService`, `OrderMergeService`) | `ArchitectureTest` | там же |
| Файл в `src/main/java` не длиннее 500 строк | `architecture/ClassSizeTest` | `src/test/resources/architecture/large-classes.txt` |

Детали:

- **Заморозка** — `FreezingArchRule` из ArchUnit. Нарушение сравнивается с записанным без номера строки и без
  списка параметров (`SignatureInsensitiveMatcher`): перенос кода внутри файла, новый параметр метода или новая
  зависимость в конструкторе контроллера не считаются новым долгом. Новый метод, который зовёт репозиторий
  или `setStatus`, — считается.
- **Циклы** считаются как рёбра «пакет → пакет» внутри одной компоненты сильной связности: ArchUnit-овский
  `beFreeOfCycles()` на нашем графе (`service`/`domain`/`tg`/… связаны почти все со всеми) перебирает циклы
  до OutOfMemory. Новый импорт по уже замороженному ребру — можно; новое ребро, замыкающее цикл, — нельзя.
- **Большие классы** из `large-classes.txt` могут вырасти не больше чем на 5 % от записанного размера.
  Удалили/переименовали файл — уберите строку, иначе тест упадёт.
- Когда нарушение исправлено, ArchUnit сам вычёркивает его из `archunit_store/` при прогоне тестов —
  закоммитьте изменённый файл стора вместе с исправлением. Уменьшился большой класс — понизьте число в
  `large-classes.txt` (или удалите строку, если он стал ≤ 500).
- Ключ правила в `archunit_store/stored.rules` — полный текст правила, включая `because(...)`. Поменяли текст —
  стор для правила придётся пересоздать (см. ниже), поэтому без нужды формулировки не трогать.

## Фронты (`site/`, `frontend/`, `frontend-admin/`, часть `npm run lint`)

Общие лимиты — `shared/eslint/architecture-limits.mjs`: `complexity` 15, `max-lines` 400 (без пустых строк
и комментариев), `max-depth` 4. Для всех файлов это **error**. Файлы, которые уже нарушали правило, перечислены
**по правилам** в `eslint.legacy-limits.mjs` каждого фронта и получают **warn** только по своему правилу —
долг видно в выводе линтера, но сборку он не валит. Словари `i18n/{en,ru,uk}.ts` — данные, для них `max-lines`
выключен насовсем.

`next build` тоже запускает ESLint, поэтому ошибка лимита в новом файле уронит и Docker-сборку — так и задумано.

## Что делать, если проверка упала

1. **Сначала — исправить код**, а не список: вынести новую логику в отдельный класс/компонент в пакете фичи,
   переход статуса — через один метод с проверками, доступ к данным — через сервис. Это и есть смысл проверок.
2. Добавлять исключение можно, только если нарушение осознанное и у него есть причина, которую можно написать
   одной строкой (например, сгенерированный код или временный перенос, который закончится в следующем коммите).
   Причину — в сообщении коммита. Исключение «чтобы CI позеленел» — это ровно тот костыль, ради которого
   проверки заведены: каждый такой пункт делает следующий легче и через месяц список снова никого не держит.
3. Как добавить исключение, если оно действительно нужно:
   - **ESLint** — путь файла в нужный массив `eslint.legacy-limits.mjs` (путь от корня фронта, скобки в
     `app/[locale]/…` экранирует helper).
   - **Размер Java-класса** — строка `<путь от src/main/java> <текущее число строк>` в `large-classes.txt`.
   - **ArchUnit** — перезаморозить стор и посмотреть в `git diff`, что добавилось ровно одно ожидаемое нарушение:

     ```bash
     cd backend && mvn -B -ntp test -Dtest=ArchitectureTest -Darchunit.freeze.refreeze=true
     ```

     Refreeze записывает **все** текущие нарушения правила, поэтому diff стора обязателен к просмотру.
4. Новое правило: добавить `@ArchTest` в `ArchitectureTest` через `freeze(...)` и один раз создать стор:

   ```bash
   cd backend && mvn -B -ntp test -Dtest=ArchitectureTest -Darchunit.freeze.store.default.allowStoreCreation=true
   ```

   В обычном прогоне создание стора запрещено (`archunit.properties`), чтобы правило без стора падало,
   а не молча замораживало всё, что есть.
