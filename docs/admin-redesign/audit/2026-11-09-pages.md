## Находки подробно

### 1. Шторка «⋯» на открытой поставке на ПК — мешает
- **Где:** `/preorders/5` (поставка в пути), 1024–1440. На 320 — нормально.
- **Что:** «⋯ Ещё действия» открывает нижнюю шторку во всю ширину экрана (как на телефоне). Ровно то, что владелец прислал про черновик.
- **Скрин:** `_shots/explore/1440__preorders_5_click_button_aria_label_.png`.
- **Причина:** `frontend-admin/features/supply/ui/BatchHeader.tsx:113-133` — `<ActionSheet open={menu} …/>` без проверки ширины. Так же было в `DraftHeader.tsx:75`.
- **Предложение:** как в `features/promo/ui/RowMenu.tsx:26-45` / `features/staff/ui/RowMenu.tsx:22-51`: `useIsDesktop()` → выпадающее меню у кнопки, шторка только < 1024. Лучше вынести один компонент «меню действий» (кнопка + выпадашка/шторка), чтобы не чинить по одному экрану: он уже нужен в черновике, поставке и, вероятно, будет нужен дальше.

### 2. Китайский текст в черновике ИИ-поставки — мешает
- **Где:** `/preorders/drafts/1`, все ширины.
- **Что:** блок «Обратите внимание» — «含运费¥4；实付款¥562.53…», заголовок шторки/черновика — название продавца «西城外贸». Владельцу нечитаемо.
- **Скрин:** `_shots/explore/1440__preorders_drafts_1.png`, `_shots/explore/320__preorders_drafts_1_click_button_aria_label_.png`.
- **Причина:** `backend/src/main/java/com/maxsolch/shop/procurement/domain/supplyai/SupplyExtract.java:21-60` — промпт «supply-1» описывает `notes`/`docNotes`, но не говорит, на каком языке их писать; модель переписывает текст накладной как есть.
- **Предложение:** в промпт: «notes и docNotes — по-русски, суммы в исходной валюте»; для поставщика — оригинал + транслитерация/перевод в скобках. Новый номер промпта («supply-2»), чтобы в журнале ИИ было видно, какие черновики собраны старым.

### 3. Тяжёлые загрузки на поставках и кейсе — мешает
- **Где:** `/preorders`, `/preorders/<id>`, `/gift`, частично `/translations`.
- **Что:** список поставок при открытии тянет `GET /api/admin/products` целиком (≈1,8 МБ, ≈315 КБ сжато, 3–6 с в браузере). Страница поставки дополнительно тянет `cards/export?status=all` (≈1,45 МБ, ≈272 КБ сжато) — только чтобы показать плашки «Скрыты с витрины» и «Новые карточки». `/gift` тоже грузит весь каталог. `/translations` — две выгрузки по ~1,5 с.
- **Скрин:** нет (замер по сети); цифры из прямых GET.
- **Причина:** `features/supply/ui/PreordersScreen.tsx:74` (`useProductsQuery` при монтировании — нужно только для модалки выбора товара); `features/cards/queries.ts:31` `useCardItems` используется в `features/supply/ui/HiddenProductsBanner.tsx:19` и `NewCardsBanner.tsx:16`; `features/gift/ui/use-gift-problem.ts:9`, `GiftProductField.tsx:31`.
- **Предложение:** каталог грузить при открытии модалки выбора; для плашек — маленький эндпоинт «флаги по id товаров поставки» (или включить флаги в ответ поставки). Для кейса — проверку «проблемных товаров» считать на бэкенде.

### 4. «Пользователи» на 1024 едут вбок — мешает
- **Где:** `/users`, карточка пользователя поверх списка; 1024 (на 768 и ≥1280 нормально).
- **Что:** ширина страницы 1094 > 1024, колонка «Был(а)» за правым краем, вся страница скроллится по горизонтали.
- **Скрин:** `_shots/matrix/1024_users.png`, `_shots/matrix/1024_user-card.png`.
- **Причина:** `frontend-admin/features/customer/ui/list/UsersDesktopTable.tsx:34` — `overflow-x-auto md:block lg:overflow-visible`: с `lg` (1024) свой скролл таблицы отключается, а таблица ещё не помещается рядом с сайдбаром.
- **Предложение:** оставить `overflow-x-auto` до `xl` или ужать колонки (имя/телефон в одну ячейку, «Был(а)» короче) — проверить на 1024 с развёрнутым сайдбаром.

### 5. «Метрики»: старая оплата на карту с нулём — мешает (проверить в базе)
- **Где:** `/metrics`, «Этот месяц», блок способов оплаты; 1440.
- **Что:** «Перевод на карту (старый): полная оплата — 19 заказов, 0 ₴». Способ давно не используется, а заказов в нём больше, чем во многих живых.
- **Скрин:** `_shots/explore/1440__metrics.png`.
- **Причина (гипотеза):** `backend/src/main/java/com/maxsolch/shop/analytics/domain/MetricsFacts.java:132-141` `scheme()` — любой заказ без онлайн-оплаты и без `paymentDueAt`, но с названием способа оплаты, попадает в `CARD_FULL`. Похоже, это заказы на 0 ₴ (подарки, объединённые, созданные админом). В базе не проверял.
- **Предложение:** проверить запросом (shop-db-report), какие заказы туда падают; завести отдельные корзины «0 ₴ / подарок», «создан админом», «объединён», а `CARD_FULL` считать только по явному способу.

### 6. «Товары»: два разных «всего» — мешает

- **Скрин:** `_shots/explore/1440__products.png`.
- **Предложение:** подзаголовок «281 в продаже · 473 всего» или убрать число из подзаголовка; склонение через общий `plural()`.
