# Аудит потерь: промокоды, подарки, кейсы, реестр

Сверка старого кода (`frontend-admin/features/promo`, `features/gift`, `app/promocodes`, `app/gift`) с макетами `mockups/promo-gift/` по рекомендованным вариантам README (промокоды A, форма A + пример из B, кейс A, приз A, настройки уровня A, автосборка A, тест B, настройки подарка A, реестр A + режим B).
Методика: макеты статичны, поэтому «не показано» (в макете просто нет, но могло подразумеваться) отделено от «убрано/изменено». Сохранённое не перечислено. Стилистика не рассматривалась.

Не найдено: **«Вместе дешевле» (бандлы)**. В этой ветке нет ни экрана админки, ни роута, ни типов бандлов во `frontend-admin` (в `backend` слово `bundle` встречается только в классах ошибок и маржи). Макета тоже нет. Аудит этой части невозможен; если PR #25 с бандлами живёт в другой ветке, его надо сверять отдельно.

Шкала: **критично** — теряется возможность или защита от ошибки; **заметно** — ухудшает работу, но обходится; **мелочь**.

## Сводные риски, не относящиеся к одному пункту
