# Макеты: карточка заказа, чат и модалки (A/B)

Статичный HTML+CSS без зависимостей, по отчёту `../../order-drawer-modals.md`. Открывать `index.html`. В каждом файле рамки телефона 390, ПК 1440 (уменьшены масштабом) и где уместно планшет 820. Скриншоты проверки — в `_shots/`. Код приложения не менялся.

Рекомендации (Р) и что спорно (С):

| Экран | Файл | Р | Почему / что спорно |
|---|---|---|---|
| /orders/[id] | `deeplink-page.html` | B сейчас, A потом | B (шторка + доска под ней) закрывает главную боль за S; A — целевое состояние (L). С: на ПК A чат всегда виден, но нужен общий `OrderWorkspace`. |
| Шапка шторки | `drawer-header.html` | A, затем элементы B | A — M и без смены навигации. С: «визитка» B красива, но вкладки внизу на телефоне меняют привычку админов; линейку статусов из B стоит взять в A. |
| Детали | `details-tab.html` | A для запуска, B на телефоне позже | A — перестановка карточек, безопасно для e2e. B (списки-входы) ближе к принятому «как чаты», но +1 экран на каждое действие. С: что считать «Требует внимания» на входе в B. |
| Позиции состава | `items-stepper.html` | A + подтверждение доплаты из B | A — S, решает промахи. С: в B лишний шаг для неоплаченных заказов, оставить только для оплаченных. |
| Панель действий | `action-bar.html` | A | «⋯ Ещё» с группами дёшево и понятно. B (колонка действий на ПК) хорош на 1280+, но дублирует меню. С: подпись «Следующий шаг» нужна текстами на 3 языках. |
| Чат и шаблоны | `chat.html` | A | чипы быстрых шаблонов дают 1 касание. С: B (панель по темам) нагляднее, но съедает высоту на 320; карточка заказа из B полезна как раскрывающаяся замена строки контекста. |
| История | `history.html` | A | фильтры-чипы + полоса типа. С: B плотнее, но без фильтров. |
| Каркас модалок | `modal-frame.html` | A по умолчанию, B для денег и мастеров | `footerLayout="stack"` + ручка. С: полноэкранный режим только для сложных модалок, иначе теряется «шторка». |
| Смена статуса | `status-change.html` | A | один экран, кнопка по цели. С: чек-лист B для отправки может раздражать опытных; взять только карточку получателя. |
| Корректировка оплаты | `payment-modal.html` | B | «до → после» снижает цену ошибки. С: пресеты сумм должны брать данные из `payableMinor`. |
| Скидка | `discount-modal.html` | A, «Своя скидка» из B позже | A проще, поиск и превью. С: пресеты % в B — новое поведение. |
| Объединение | `merge-modal.html` | A | аккордеон без смены шагов; B — если на тестах путают «этот/тот». С: автовыбор единственного кандидата в B пропускает шаг. |
| Возврат (3 шага) | `return-modal.html` | A | минимальная правка (`fixedHeight`). С: B (одна страница) удобнее, но меняет сценарий и тесты. |
| Посылка вернулась | `return-received.html` | A | быстрый путь «Принять всё без брака» — основной случай. С: B яснее для частичного брака. |
| Обмен | `exchange-modal.html` | A на ПК, B на телефоне | две колонки на ПК, лента «было → стало» на телефоне вместо 3 шагов. С: два разных вида — больше поддержки. |
| ТТН, Архив, Подарок/кейс, Возврат денег, Доставка | `modal-*.html` | A везде, у «Доставка» — B | мелкие правки без смены логики. С: у «Доставки» B (поиск отделения над клавиатурой) зависит от Autocomplete и требует проверки на iOS. |
| Выбор товара | `item-picker.html` | A | список с поиском проще; B (плитки + «＋») нужен, только если часто добавляют по несколько. |
| Ручной заказ | `new-order.html` | A | аккордеоны + sticky «Итого». С: B (мастер) безопаснее на телефоне, но дольше. |

Общее спорное: цифры и тексты — примерные (сид-данные не использовались); эмодзи-иконки заменить на иконки проекта; на телефонах нужна проверка с экранной клавиатурой, макеты её не показывают.
