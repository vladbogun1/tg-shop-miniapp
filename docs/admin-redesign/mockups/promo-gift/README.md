# Макеты: Промокоды, Кейс, Реестр подарков

Статичный HTML+CSS, без зависимостей. Старт — `index.html`. Исследование — `../../promo-gift.md`.
Рамки: телефон 390, десктоп 1440 (масштаб 0.62 в просмотре, внутри рамки вёрстка в натуральную ширину), где нужно — планшет 820 и большой 1920. Скриншоты проверки — `_shots/`.

## promocodes.html — список промокодов
- **A** — плотная строка со Toggle и «⋯», заказы кода в правой панели; **B** — группы как чаты, на десктопе мастер–деталь с правкой на месте.
- Рекомендую **A**: самое частое действие (выключить код) в одно касание, быстрее всего внедряется поверх текущих компонентов. Из B стоит взять плашку-сводку «Действуют / Резерв / Истекают».
- Спорно: оптимистичный Toggle у кода с резервом (нужно предупреждение); в B лишний шаг для тех, у кого почти все коды в «Мои».

## promo-form.html — «Новый промокод»
- **A** — одна форма с пресетами, кубиком и сроком; **B** — живой «билет» и три шага на телефоне.
- Рекомендую **A** для первой волны (проще, мало кода), элемент «пример расчёта» взять из B. Билет-превью — на потом.
- Спорно: поле «Срок до» требует проверки `promoBody`/API; на 390 px форма A не помещается без прокрутки (в макете скролл скрыт).

## case.html — конструктор кейса
- **A** — «рабочий стол»: sticky-тулбар, мини-сводка, лейны (канбан на 1920); **B** — редкости списком-входами, на десктопе таблица всех призов.
- Рекомендую **A**: сводка шансов/маржи не уезжает, одна кнопка «Опубликовать». B на телефоне приятнее для обзора, но правка шанса требует входа в лейн; таблица B хороша как режим «Таблица» позже.
- Спорно: канбан 1920 без DnD между редкостями — только вёрстка; слои sticky на 320 px съедают высоту.

## case-prize.html — модалка приза
- **A** — drawer рядом с доской; **B** — диалог с блоком «до / после».
- Рекомендую **A** (доска остаётся видна), на телефоне — шторка с живой строкой маржи; блок «до / после» из B — как раскрывающаяся деталь.
- Спорно: drawer требует общего компонента Drawer; в макете доска не сжимается под панель.

## case-tier-settings.html — настройки уровня
- **A** — длинная форма с группами и плашкой «маржа 54 → 61 %»; **B** — разделы-входы и график «порог → маржа».
- Рекомендую **A** с дельтой маржи; график B красив, но нужны данные для кривой.
- Спорно: сохранение сразу при вводе — «Готово» только закрывает.

## case-autofill-test.html — автосборка и тест
- Автосборка: **A** — форма + предпросмотр под ней; **B** — шаги, справа список призов. Рекомендую **A** (шаги на десктопе избыточны), на телефоне можно B.
- Тест: **A** — модалка с гистограммой; **B** — панель рядом с доской / нижняя полка. Рекомендую **B** на 2xl и телефоне: подкрутил шанс — сразу виден результат.
- Спорно: предпросмотр автосборки требует прогона алгоритма без записи в черновик.

## gift-settings.html — глобальные настройки подарка
- **A** — строка-сводка «вкл · кейс · лимит · маржа» и шторка; **B** — отдельный раздел-входы со статистикой.
- Рекомендую **A**: экран кейса не загромождён, одно место сохранения. B уместен, если настроек станет больше.
- Спорно: куда деть «Упор на скидки» (в B отдельный пункт, в A остаётся ссылкой).

## registry.html — реестр подарков
- **A** — таблица для бухгалтера (sticky-ряд, «Только сверх лимита», итоговая строка, с 820 px); **B** — группировка по получателям с полосой лимита.
- Рекомендую **A** как основу (нужна сверка и CSV), **B** — как режим «По людям»: на телефоне он нагляднее, чем карточки.
- Спорно: на 820 px объединена колонка «Заказ» с «Подарком»; сортировка/группировка на клиенте до ~1000 строк.
