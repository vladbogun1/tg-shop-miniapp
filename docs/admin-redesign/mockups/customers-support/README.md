# Макеты: Пользователи, Рассылки, Поддержка

Статичный HTML+CSS, без зависимостей. Старт — `index.html`. Источник — `../../customers-support.md`.
В каждом файле: вариант A и B, телефон 390 и ПК 1440 (где уместно — планшет 820). Данные вымышленные.
Скриншоты проверки — `_shots/`. Код приложения не менялся.

## Пользователи
- **users-list.html** — рекомендую **A** (один ряд «поиск + чипы со счётчиками», sticky-шапка, «Показати ще»): меньше всего меняет привычную таблицу и сразу даёт выигрыш по высоте. Спорно: B (сегменты как чаты Telegram) красивее на телефоне, но требует фильтры и счётчики на бэкенде (`hasOrders`, `premium`, `total`); можно взять только телефонную часть B.
- **user-profile.html** — рекомендую **A** (drawer с действиями, сводкой 4 ячейки и вкладками): укладывается в существующий `Drawer`. Спорно: B (досье с хронологией заказов и обращений) мощнее, но «Обращения» по `userId` — бэкенд; бейдж «Проблемный» считается на клиенте и может задевать.
- **users-analytics.html** — рекомендую **A** (KPI выше карты, карта свёрнута): S–M, без новых экранов. Спорно: B (метрики как вход, карта отдельным экраном) — больше навигации; графики по каждой метрике надо делать заново.

## Рассылки
- **broadcasts.html** — рекомендую **A** (две колонки с липким предпросмотром на ПК, три сегмента и нижний бар на телефоне): модель `use-compose` не меняется. Спорно: B (мастер на 4 шага) надёжнее против ошибки аудитории, но медленнее для опытного владельца; можно взять из B только экран «Проверка». Плашка прогресса — «Остановить» не показана: нужен бэкенд.
- **broadcast-confirm.html** — рекомендую **A** (зажать для отправки + мини-предпросмотр) для N ≥ 100; **B** (разбивка по языкам и отсчёт 1,5 с) — для ПК. Спорно: «зажать» не очевидно без подсказки и плохо с клавиатуры; разбивка по языкам требует подсчёта получателей на каждый язык.
- В конце `broadcasts.html` — мелочь про «Тест себе / …другому» (один вариант, без альтернативы).

## Поддержка
- **support-list.html** — рекомендую **A** (очередь «Ждут ответа», сортировка по ожиданию, «ждёт 2 ч 40 мин», цвет срочности). Спорно: B (группы/доска по срочности) нагляднее при большом потоке, но при 5–10 обращениях колонки полупустые; пороги 30 мин / 2 ч — нужно согласовать.
- **support-chat.html** — рекомендую **A** (мастер-деталь, шапка в одну строку, «Отправить ▾ Отправить и закрыть»): самый высокий приоритет и меньше риска. Спорно: B (три панели с контекстом клиента) на 1440 ужимает чат — только от 1600 px; на телефоне вкладки «Чат / Клиент / Товар» — лишний слой. Оба варианта требуют аккуратного монтирования чата (один экземпляр при смене `lg`).
- **support-templates.html** — рекомендую **A** (⚡ + шторка/popover + три чипа): единообразно с «Заказами». Спорно: B (слэш-команда с предпросмотром подстановок) быстрее для опытных, но без бэкенда (`reply-templates` для тредов, `locale` в треде) подстановки и язык не определить; на телефоне «/» неудобен.
- **start-thread.html** — рекомендую **B** (клиент подставлен из профиля + проверка дубля + «Недавние»): снимает главную боль — ручной ввод ID. Спорно: проверка дубля требует поиска тредов по `userId`; если бэкенда нет, брать A (автокомплит).
