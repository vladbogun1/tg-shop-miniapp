# Редизайн админки: Категории, Бренды, Теги, Переводы (+ модалки)

Статус: предложения, код не менялся. Код: `frontend-admin/features/{catalog,translation}/ui`.
Оценка: S до полудня, M 1-2 дня, L 3+ дня. Приоритет P1 (болит ежедневно) / P2 / P3.
Размеры: Тел 320-639, План 640-1023, Ноут 1024-1535, Большой 1536-2560.

## 0. Сквозное (сделать один раз, применять везде)

1. **Теги.** `app/tags/page.tsx` это только `redirect("/categories")`, экрана нет. Оставить редирект, ссылки на
   «Теги» убрать. `TagInput` на деле ввод алиасов бренда: переименовать в `AliasInput` (S, P3).
2. **Скролл-контейнер.** Экраны живут в потоке `<main>`; «Переводы» зовут `window.scrollTo`, sticky-панели привязаны
   к `bottom: var(--bottom-nav)`. Когда «Заказы»-подход (один скролл-контейнер) станет общим, это сломается.
   Нужен общий `ScreenBody` (шапка + sticky-тулбар + область скролла) и хук `useScrollTop()` (M, P1).
3. **PageHeader** на Ноуте ~70px (h1 + subtitle + действия). Для каталога: subtitle убрать в `title=`/sr-only,
   главную кнопку поставить в одну строку с поиском (S, P1).
4. **Тач-цели.** `Act`, `RowToggle`: `pointer-coarse:h-10` (40px), `RowBtn` и `CELL` в GroupsDialog 32-36px.
   Нужно ≥44 (`pointer-coarse:h-11 pointer-coarse:w-11`) (S, P1).
5. **Модалки** (`@shop/ui/overlay` Modal): на телефоне уже bottom-sheet; `fixedHeight` до 680px, `size` до `lg`. Добавить
   `size="xl"` (~960) для двухколоночных форм и `Drawer` справа для редакторов на Ноуте (S).
6. **Единый sticky-тулбар каталога**: поиск + чипы-фильтры + счётчики + главная кнопка, один ряд
   (`sticky top-0 z-10 bg-[var(--bg)]/95 backdrop-blur`). Сейчас в Категориях/Брендах `flex-wrap` даёт 2 ряда.
7. **Массового режима нет нигде.** Один паттерн: чекбокс в строке -> липкая `BulkBar` («Выбрано N · действие · Снять»).
   Компонент общий для 3 экранов (M, P1).

## 1. Категории (`categories/*`)

**Что не так**
- Строка: ↑ ↓ и «⋯» по 32px; каждый клик ↑ это запрос (`planShift`), поднять на 5 мест = 5 запросов. DnD нет.
- На Тел число товаров голое (`md:hidden`, без подписи); число характеристик только на `lg+`, на меньших путь к схеме
  лишь через «⋯».
- Каждый корень отдельная `card` с `gap-2.5`: на 15+ корнях длинная лента, низкая плотность.
- Нет «Свернуть/Развернуть всё»; состояние свёрнутости теряется. Нет массовых операций (скрыть из меню, переместить
  несколько). `first/last` через `findIndex` в каждом рендере (шум, O(n²)).
- Поиск без подсветки совпадений; абзац про «Уценку» внизу экрана, а нужен при создании/переносе.

**Предложение (логика).** Дерево остаётся деревом (2 уровня, правило домена), таблица не нужна, но строка плотнее:
`[⠿][▸][название + slug][SEO/скрыта][товаров][хар-к][⋯]`. Порядок: DnD (`@dnd-kit/sortable`, в пределах siblings),
один PUT с порядком siblings на drop (`CategoryReorderItem[]` уже есть); ↑↓ оставить в «⋯» для клавиатуры.
Чекбоксы -> BulkBar: «Показывать/скрыть в меню», «Переместить в…». Тулбар: поиск, «Свернуть все», чипы
(«Скрытые», «Без характеристик», «Без товаров», «С SEO»). «Группы характеристик» убрать в «⋯» тулбара (справочник).

**Размеры**
- Тел: корни без карточек, один `divide-y`; строка в 2 строки (название, под ним `slug · N товаров · M хар.`),
  справа только «⋯» 44px; сортировка включается кнопкой «Порядок» (показывает ручки DnD).
- План: то же + видны «товаров» и бейджи, ручки всегда видны.
- Ноут: полная строка, числа в колонках `w-24 text-right tabular`, «M хар.» кнопка к схеме.
- Большой: две колонки, слева дерево (`max-w-[720px]`), справа панель выбранной категории вместо модалки (п.1.1).

**Tailwind:** `lg:grid lg:grid-cols-[minmax(0,720px)_1fr] lg:gap-6`; панель `2xl:sticky top-4 max-h-[calc(100dvh-2rem)]
overflow-auto`; строка `min-h-12 pointer-coarse:min-h-14`, ручка `touch-none cursor-grab`; BulkBar `fixed inset-x-0
bottom-[var(--bottom-nav)]` на Тел, `sticky bottom-3` на Ноуте.
**Риски:** framer `layout` на `motion.li` конфликтует с DnD (отключить на время drag); оптимистичный порядок брать
из `planShift`. **M, P1.**

### 1.1 Модалка «Категория» (`CategoryDialog`: Основное / SEO / Характеристики)
- Не так: `fixedHeight` 680px, на Большом тесно, на Тел 3 вкладки + футер съедают высоту; в футере два смысла
  (на вкладке specs «сохраняется сразу», кнопки нет, а «Основное» может быть dirty и это не видно).
- Предложение: на Ноуте/Большом `Drawer` справа 560-720px, на Тел fullscreen-sheet; вкладки липнут под заголовком;
  точка dirty на вкладке «Основное». SEO: превью выдачи (title ~60, description ~160) справа от полей на `lg`,
  сверху на Тел; `introText` с авто-ростом. «Основное»: `grid-cols-1 sm:grid-cols-2`, плитка выбирается картинкой,
  а не `Select` с кодами. **M, P2.**

### 1.2 Вкладка «Характеристики» (`CategorySpecsTab`, `AttributeRow`)
- Не так: порядок ↑↓ по одному; серые унаследованные занимают половину списка; на Тел бейджи «фильтр/карточка»
  скрыты (`hidden sm:flex`), а это ключевая информация; поиска нет (у «Мыши» десятки); кнопки «Группы» и
  «Характеристика» переносятся рядом с длинным текстом.
- Предложение: сегмент «Свои / Унаследованные / Все» (по умолчанию «Свои»), поиск, DnD в группе, режим выбора
  с массовым «в фильтр / на карточку / удалить», «Скопировать схему из категории…». Ноут: `data-table`
  (`Название · Ключ · Тип · Группа · Фильтр · Карточка · Товаров`); Тел: карточки с бейджами под названием.
- Риск: сейчас порядок свапом двух записей (`useSwapAttributes`); для DnD нужен bulk-reorder (проверить бэкенд). **M, P1.**

### 1.3 Модалка «Характеристика» (`AttributeDialog` + Labels/Units/Flags/Buckets/Options)
- Не так: один `flex-col gap-5` из 7 блоков; опции enum (иногда сотни) правятся в той же вертикали; нет превью
  «как увидит покупатель».
- Предложение: `size="xl"`, на `lg` две колонки: слева подписи ru/uk/en (3 в ряд), ключ, тип, группа, флаги; справа
  опции/корзины со своим скроллом и превью фильтра. Опции: массовая вставка (по строке), поиск, DnD.
  Тел: аккордеон блоков (открыт один), липкий футер. **M, P2.**

### 1.4 «Переместить в…» (`MoveCategoryModal`)
- Не так: `Select`, а корни с товарами просто отсутствуют без объяснения.
- Предложение: список корней (radio) с отключёнными строками и причиной («есть товары»); принимает N категорий из
  BulkBar. **S, P2.**

### 1.5 «Группы характеристик» (`GroupsDialog`)
- Не так: сетка `130px 1fr 1fr 1fr 116px` в `lg` узка; на Тел 3 колонки по `h-9` мелкие; вызывается из двух мест с
  независимым состоянием.
- Предложение: на Тел карточка группы (RU, раскрытие UK/EN/ключ), DnD вместо ↑↓, инпуты 44px. **S/M, P3.**

## 2. Бренды (`brands/*`)

**Что не так**
- Таблица `md+` и карточки на Тел это правильно, но: нет сортировки по заголовкам (вместо неё `SegmentedControl`),
  нет sticky `thead`, нет фильтров («без товаров/логотипа/сайта»), строка ~72px из-за логотипа 96px.
- Массового режима нет, а основная боль это дубликаты («AttackShark»/«Attack Shark»): объединение по одному.
- На Тел карточка в 3 ряда (название, алиасы, действия).

**Предложение.** Таблица с сортировкой по `th`, sticky `thead`, колонка чекбоксов. Чипы: «Без товаров N», «Без
логотипа», «Возможные дубликаты». «Возможные дубликаты»: клиентская группировка по `normText` без пробелов/дефисов,
кнопка «Объединить группу» (выбрать главный, остальные станут алиасами). BulkBar: «Объединить в…», «Удалить пустые».
Тел: компактная карточка в 2 строки (логотип 40px, название, `slug · N`, «⋯»), алиасы в раскрытии.
Большой: режим «сетка логотипов» (`grid-cols-[repeat(auto-fill,minmax(160px,1fr))]`) для проверки ленты на главной.

**Tailwind:** `data-table`, `thead` `sticky top-0 bg-[var(--surface)]`; колонки `w-10` чекбокс, `w-20` логотип,
числа `text-right tabular`; «Сайт» `hidden xl:table-cell`.
**Риски:** слияние необратимо, нужен confirm со сводкой. **M, P1** (дубликаты), остальное S/P2.

### 2.1 Модалка «Бренд» (`BrandFormModal`, `BrandLogoField`)
- Не так: логотип, главное визуальное поле, в самом низу длинной формы; дубль имени даёт ошибку, но не предлагает
  «Объединить».
- Предложение: сверху блок логотипа с превью на тёмном/светлом (`sm:grid-cols-[160px_1fr]`), ниже поля; у ошибки
  дубля ссылка «Открыть существующий / Объединить»; липкий футер. **S, P2.**

### 2.2 Модалка «Объединить» (`MergeBrandModal`)
- Не так: результат описан только текстом, не видно, какие алиасы и сколько товаров переедут.
- Предложение: сравнение «Было -> Станет» (логотип, товары, алиасы), кнопка «Объединить N товаров». **S, P3.**

## 3. Переводы (`translation/ui`)

**Что не так**
- До первой строки списка три стопки: вкладки, `FilterBar` (язык, тип, поиск), `TabHint` (текст + 2 кнопки): на Ноуте
  ~260px пустой «шапки».
- `TranslationQueue`: `PAGE=50` + «Показать ещё», без виртуализации; выбрать подмножество строк нельзя, есть только
  «Принять все» по всему фильтру (`acceptEverything`) без предпросмотра.
- Просмотр по одному (`TranslationReview`) скрывает список (`hidden`), контекст и фильтры не видны, позиция
  привязана к индексу очереди, `window.scrollTo`.
- ИИ-поток (`AiTranslate`): три карточки-шага подряд; шаг 3 это длинный список `AiReviewRow` на 3 колонки (`lg`), на Тел
  в столбик (RU, UK, EN каждый до 10 строк), 5 сегментов фильтра + «Отметить…» переносятся на 2-3 ряда; нет
  прогресса частей («скопировано 2/5, вставлено 1/5»).
- «Устарел» значит «скрыт от покупателя», а виден только чипом 10px.

**Предложение (логика).** Master-detail: слева список с чекбоксами, справа (Большой) редактор строки: «по одному»
становится правой панелью, горячие клавиши (`Ctrl+Enter`, `Alt+↑/↓`) остаются. Список на `lg+` таблицей
(`☐ · Тип · Где · RU · UK · EN`), виртуализация (`@tanstack/react-virtual`) вместо «Показать ещё». BulkBar по выбранным:
«Принять», «Перевести через ИИ (только выбранные)», «Сбросить перевод», «Подтвердить устаревший как есть».
Быстрые выборки: «Без замечаний», «Все видимые», «По типу». Три стопки сжать в одну sticky-строку: вкладки со счётчиками,
справа поиск/язык/тип (на Тел за кнопкой «Фильтры (N)»); `TabHint` в одну строку (i-popover), действия в BulkBar.
ИИ-поток: stepper «1 Промпт -> 2 Ответ -> 3 Проверка» (sticky), выполненные шаги сворачиваются; шаг 3 таблицей на
`lg`, на Тел карточка с переключателем RU/UK/EN. Для устаревших прямо в строке mini-diff (`wordDiff` уже есть) и
кнопка «Подтвердить».

**Размеры**
- Тел: вкладки скроллятся (уже), фильтры в sheet, строка-карточка из 2 строк (тип + место, RU, чипы uk/en);
  выбор по кнопке «Выбрать»; редактор fullscreen-sheet с кнопкой «Принять и дальше» 48px.
- План: список во всю ширину, редактор sheet справа 480px.
- Ноут: таблица + `Drawer` справа 520px по клику.
- Большой: две панели `grid-cols-[minmax(0,1fr)_minmax(480px,640px)]`, список видит 25+ строк.

**Tailwind/компоненты:** `Tabs` (`pointer-coarse:min-h-11`) оставить; FilterBar `sticky top-0 z-10`; BulkBar из п.0;
`Drawer` из `@shop/ui/overlay`; `StateChip` 11px; `Kbd` только `md+`.
**Риски:** `acceptAll(strings, langs)` уже принимает произвольный список (ок); ИИ «только выбранные» меняет
`scope` на выбранные хеши (ок); master-detail требует хранить `selectedHash` вместо индекса `review.start`;
виртуализация против `scroll-mt` и фокуса по клавишам. **L, P1.** Этапы: (1) sticky-тулбар + компактный `TabHint` (S);
(2) чекбоксы + BulkBar (M); (3) master-detail + таблица (L); (4) шаг 3 ИИ таблицей/свёрнутыми строками (M).

### 3.1 Просмотр по одному (`TranslationReview`, `LangPanel`, `OriginalPanel`, `ReviewActions`)
- Не так: `lg:grid-cols-2`, `2xl:grid-cols-3`: на Ноуте оригинал слева на двух рядах, UK/EN справа, очень высоко; на Тел
  всё в столбик, textarea растёт до 16 строк; «Удалить перевод» ссылка 12px.
- Предложение: на Тел RU сверху (сворачиваемый), UK/EN вкладками, липкая «Принять и дальше» 48px, удаление в «⋯»;
  замечания (`IssueList`) рядом с полем. **S/M, P2.**

### 3.2 Шаг 3 ИИ (`AiReviewRow`, `SendSummaryView`)
- Не так: строка развёрнута всегда (3 колонки + блок «Правка оригинала» + чекбоксы), страница на сотни строк.
- Предложение: сжатая строка по умолчанию (чекбокс, id, тип, по 1 строке RU/UK/EN, индикаторы), клик раскрывает
  правку; в панели «Сохранить отмеченные · N» чипы «Только без замечаний»; итог отправки в sheet. **M, P2.**
