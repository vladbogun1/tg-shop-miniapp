# Бриф: реализация редизайна админки (frontend-admin)

Общий для всех разработчиков-агентов. Свою тему, свои макеты и свои папки ты получаешь в задании.

## Что делаем
Переносим в настоящий код рекомендованные варианты из `docs/admin-redesign/mockups/<тема>/README.md`
(там, где «A на ноуте, B на телефоне», делаем оба, переключение по ширине). Исследование — `docs/admin-redesign/<тема>.md`.

ОБЯЗАТЕЛЬНО до кода:
1. `docs/admin-redesign/audit/DECISIONS.md` — решения владельца. Они главнее макета.
2. `docs/admin-redesign/audit/<тема>.md` — чек-лист потерь. Правило: всё, что было в старом коде, ОСТАЁТСЯ
   (критичные — по DECISIONS, заметные и мелочи — по умолчанию возвращаем). НЕ делаем только то, что дизайнер выдумал
   и чего нет в API/бэкенде (поля, счётчики, фильтры, которых бэк не отдаёт). Тексты подсказок и формулы — из старого кода.
3. Бэкенд НЕ меняем. Нужна новая штука от бэка — не делай, запиши в отчёт как «нужен бэкенд».

## Владение файлами (работают 10 агентов параллельно в ОДНОЙ папке)
- Правь ТОЛЬКО свои папки из задания (+ e2e-тесты своих экранов в `e2e/tests/`).
- ЧУЖОЕ НЕ ТРОГАТЬ. Особенно:
  - `components/ui/*`, `shell/*`, `nav-config` — только агент «оболочка». Нужен новый общий примитив — сделай его у себя в
    `features/<твоя>/ui/` и упомяни в отчёте (потом вынесем).
  - `lib/*`, `packages/*` — ни у кого (только чтение). Исключение: агент «оболочка» может добавить новый файл в `lib/`.
  - Доска заказов уже сделана: `features/order/ui/board/*`, `features/order/ui/Orders*.tsx`, `use-status-nav.ts`,
    `use-is-kanban.ts`, `features/analytics/ui/TodayChips.tsx`, `TodayStrip.tsx`, `features/procurement/ui/WantedWidget.tsx`,
    `lib/use-fill-height.ts`, `lib/use-hide-on-scroll.ts`, `lib/use-css-var-height.ts` — НЕ ТРОГАТЬ.
- Видишь в `tsc`/`eslint` ошибки в чужих файлах — это соседи работают, не чини, игнорируй.
- git: НЕ коммитить, НЕ stash, НЕ checkout/reset/restore. Только правка файлов.
- Не запускай dev-сервер и браузер (порты общие); визуальную проверку сделает координатор.
