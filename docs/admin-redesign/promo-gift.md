# Админка: «Промокоды», «Кейс», «Реестр подарков» — предложения по редизайну

Только исследование, код не менялся. Разбор по `frontend-admin/features/promo`, `features/gift`, `app/{promocodes,gift}`.
Сокращения: S/M/L — трудоёмкость; P1 — делать в первой волне, P2 — после, P3 — по желанию.
Размеры: тел = 320–639, план = 640–1023, ноут = 1024–1535, большой = 1536–2560.

## Общий принцип (как в «Заказах»)
Меньше «шапки», больше места главному: на «Кейсе» главное — доска призов + шансы/маржа, на «Промокодах» — список и быстрое создание,
на «Реестре» — таблица. Один прокручиваемый контейнер, фильтры/сводка sticky, шторки на телефоне, тач-цели >=44px, без `max-w-3xl` на ноутбуке и выше.

## 1. Промокоды (`PromocodesScreen`, `PromoRow`, `PromoFilters`, `PromoList`)

**Что не так (по коду)**
- `mx-auto max-w-3xl` (768px) на любой ширине: на 1440+ список — узкая колонка посередине, по бокам пусто; карточки по одной.
- До первого кода четыре слоя: PageHeader (заголовок + subtitle + кнопка) -> вкладки -> поиск+статус -> строка про «За отзывы». Ни один не sticky: при прокрутке длинного списка вкладки и поиск уезжают.
- `PromoTabs` рендерит ДВА `SegmentedControl` (sm:hidden / hidden sm:block) — дубль DOM ради коротких подписей.
- В строке нет быстрого вкл/выкл: чтобы выключить код, надо открыть модалку, найти «Активен», сохранить. Это самое частое действие.
- Карточка высокая (`py-3.5`, плитка 44px с иконкой билета, под ней ещё строка статистики) — на экране помещается 5–6 кодов. Иконка Ticket у всех одинакова и информации не несёт.
- «Удалить» при `used > 0` — `disabled` + `title`; на телефоне подсказки нет, кнопка просто мёртвая и непонятная.
- Бейджи (активен/лимит/резерв/личный/до даты) в одну wrap-строку с кодом: на 320px код и 3 бейджа дают 2–3 строки.
- «Заказы с кодом» раскрываются внутри карточки (строки-кнопки с 6 колонками в wrap) — на телефоне это каша; раскрытие сдвигает список.
- Форма: поля `expiresAt` нет, хотя строка показывает «до …» и коды из кейса/отзывов её имеют; владелец не может поставить срок у своего кода. Нет кнопки «сгенерировать код», нет живого примера «5 % от 2 000 ₴ = −100 ₴».
- `closeOnBackdrop={false}` + `dirty` — правильно, оставить.

**Предложение (логика: «быстрое создание», «быстро выключить»)**
1. Один sticky-ряд управления: `[вкладки] [поиск] [Все/Действуют/Не действуют] [+ Новый]`. Заголовок/subtitle убрать (на телефоне заголовок уже в top bar), «+ Новый промокод» — в этот же ряд (на телефоне — иконка `+` 44px справа от поиска либо FAB-нет, см. риски).
2. Строка списка — компактная таблица-карточка (одна визуальная строка на ноутбуке): `код (mono) | скидка | исп./лимит (мини-прогресс) | срок | [Toggle] [⋯]`. «⋯» -> меню: Редактировать / Заказы с кодом / Копировать код / Удалить (с пояснением, почему недоступно).
3. Статусные бейджи сократить до одного «главного»: выключен / исчерпан / истёк / резерв — по приоритету; остальное — в тултип/деталь. Тип происхождения (личный/отзыв) уже даёт вкладка — бейдж «личный · tg id» оставить только в «Персональных».
4. «Заказы с кодом» -> правая панель (ноут+) / шторка (тел.) вместо раскрытия в карточке; там же итого: заказов, суммарная скидка, выручка с кодом.
5. Модалка «Новый промокод» — в шторку на телефоне (уже bottom sheet), на ноуте — `size="md"`; сверху пресеты «5 % / 10 % / 15 % / 100 ₴ / 200 ₴» (чипы), кнопка-кубик «Сгенерировать код», поле «Срок до» (дата + чипы 7/30/90 дн., как `PROMO_DAYS` в кейсе), живая строка-пример, `Активен` — по умолчанию включён и выглядит как строка, а не отдельная карточка. «Сохранить» — в sticky footer (он уже есть).
6. Вкладка «Персональные»: два списка (коды и ручные скидки) разделить подзаголовками sticky; ручные скидки — таблица со ссылкой на заказ, не карточки.
7. «За отзывы»: вместо абзаца — компактная плашка-счётчик «выдано N · использовано M · конверсия %» в ряду управления.

**По размерам**
- Тел: ряд = 2 строки (вкладки на всю ширину с горизонтальным скроллом `overflow-x-auto snap-x`, ниже поиск + фильтр-иконка -> шторка с «Все/Действуют/Не действуют»). Строка кода — 2 строки: код+скидка / исп.+срок; Toggle справа, «⋯» 44px. Создание — шторка на всю высоту (`fixedHeight`).
- План: один ряд управления, список в одну колонку, строка в одну-две линии.
- Ноут: `max-w` снять -> `max-w-[1200px]`; список таблицей (`grid-cols-[minmax(160px,1.2fr)_1fr_1fr_120px_auto]`), заказы кода — правая панель 380px.
- Большой: список + постоянная правая панель деталей выбранного кода (master–detail), `max-w-[1600px]`; никаких растянутых строк.

**Tailwind/компоненты**
- Ряд управления: `sticky top-0 z-20 -mx-4 bg-[var(--bg)]/90 px-4 py-2 backdrop-blur` (как в «Заказах»).
- Список: `divide-y divide-[var(--line)]` внутри одного `panel`, строка `min-h-[56px] pointer-coarse:min-h-[64px]`; сетка `lg:grid lg:grid-cols-[…]`, на тел. `flex-wrap`.
- Вкладки: один `SegmentedControl` + `overflow-x-auto`; короткие подписи брать через CSS (`<span class="sm:hidden">`/`hidden sm:inline`), а не двумя контролами.
- Toggle в строке: существующий `components/ui/Toggle` + оптимистичный `useSavePromo` (нужен PATCH только `active`; проверить, что `promoBody` не затирает остальное).
- Меню «⋯»: существующий dropdown/popover shell, пункты >=44px на `pointer-coarse`.
- Срок: `Input type="date"` как в реестре + чипы.

**Риски:** оптимистичный Toggle может конфликтовать с резервами (код с `reservedCount>0` — предупредить «N клиентов держат код»); поле срока требует поддержки в `promoBody`/API (проверить бэкенд — `expiresAt` в типе есть); master–detail меняет URL (`?tab=&code=`) — не сломать `usePromoTab`.
**Оценка:** ряд управления + sticky + снять max-w — S, P1; компактная строка + Toggle + меню — M, P1; пресеты/срок/генератор/пример в форме — M, P1 (быстрое создание); панель заказов/master–detail — M–L, P2.

## 2. Кейс (`GiftScreen`, `GiftSection`, `StatsStrip`, `CasePanel`, `TierTabs`, `CaseLane`, `SummaryCard`, `DraftBar`)

**Что не так (по коду)**
- Порядок экрана сверху вниз: PageHeader -> StatsStrip (4 плитки + строка по уровням) -> GiftSection (`max-w-3xl`, 6–8 полей) -> панель «Кейсы» (описание-абзац -> TierTabs -> NoCaseNote -> TierSwitch -> DraftBar -> доска+сводка) -> LowMarginPanel. Доска призов, ради которой пришли, находится на 3–4 экрана ниже фолда, и там же она делит ширину со сводкой.
- Главная пара «шансы + маржа» (`SummaryCard`) лежит в `aside` и только на `lg+` sticky; на телефоне она `order-1` ПЕРЕД доской — то есть видна до призов, но при правке призов уезжает вверх, и результат правки (маржа/доля %) не виден. Нет плавающей мини-сводки.
- На ноуте `lg:grid-cols-[1fr_320px]` — доска получает ~500–700px при 2 колонках призов только с `xl` (`xl:grid-cols-2` в лейне), на 1920+ линии растягиваются, призы остаются мелкими строками 40px-картинкой.
- Нет сводки «в одну строку» над доской: шансы по редкостям (полоска 12px), «Кейс обходится в», «Доля маржи» — только в карточке справа; цвет-индикатор тонет (маленький текст 11.5–13px).
- `TierTabs` (60–72px картинки) + `TierSwitch` + кнопка «Порог, скидка, промокод» + `DraftBar` = 4 слоя управления одним уровнем, у каждого свой стиль. Настройки уровня (порог, гарантия, замена, срок) спрятаны в модалку, хотя порог и гарантированная скидка напрямую влияют на маржу (видна в сводке).
- `DraftBar` не sticky: правишь приз в нижней линии, а «Опубликовать» остался наверху. Есть ещё общий sticky-бар «Несохранённых изменений» из GiftScreen (`bottom: calc(var(--bottom-nav)+12px)`) — два разных паттерна сохранения на одной странице (черновик кейса vs. настройки), оба называются по-разному («Опубликовать»/«Сохранить») и могут быть видны одновременно.
- Лейн: заголовок + `ShareInput` 64px + две иконки-кнопки (32px; 36px на coarse) — на тач меньше 44px; иконки без подписей, смысл «Package/Percent» неочевиден.
- Строка приза — вся кнопка, правка в модалке; чтобы поправить шанс 5 призов — 5 открытий модалки. Нет ни перетаскивания между редкостями, ни инлайн-шанса.
- «Тест» и «Автособрать» — 2 кнопки под сводкой; на телефоне они в самом верху, а не рядом с призами.
- `GiftSection` показывает «Порог запасного товара-подарка» + выбор товара + «Лимит подарков на человека» + «Напомнить» + «Средняя маржа» — смесь глобального (вкл/лимит) и кейса (маржа, напоминание) без явных групп; `isCase` меняет смысл поля порога.
- `LowMarginPanel` — отдельная `panel` внизу, влияет на призы всех уровней, но не связана с сводкой.

**Предложение (логика: видеть шансы, маржу, призы одновременно)**
Экран из двух зон: `[Глобальные настройки — сворачиваемая полоса сверху]` + `[Конструктор: рабочая область на всю высоту]`.
1. **Конструктор = «рабочий стол»**. Верхняя sticky-полоса уровня (одна): `[Бронза | Серебро | Золото]` (компактные табы 40px с мини-картинкой 28px, точка-«черновик») · `Toggle разыгрывается` · порог `от N ₴` (кликабельный, редактирует инлайн) · справа `Автособрать` `Тест` `⚙` `Опубликовать (N)`. Кнопка «Опубликовать» — акцентная только когда есть черновик, иначе серый чип «Опубликовано».
2. **Сводка всегда на виду**: компактная полоса `ШАНСЫ ▮▮▮▮▮▮ 62/25/9/3/1 %` + 3 числа: `Средний приз`, `Кейс ≈ N ₴`, `Доля маржи 54 %` (цвет ok/warn/danger, 16–18px). На ноуте+ — правая колонка `sticky top-[toolbar]` с полной карточкой; на планшете/телефоне — sticky-мини-полоса под тулбаром (одна строка, раскрывается в шторку «Подробнее»).
3. **Доска**: лейны редкостей как колонки на широком экране (`Обычный | Редкий | Эпический | Легенда | Джекпот` — горизонтально, канбан) — призы карточками 2-х размеров; на узком — вертикальные лейны-аккордеоны. Инлайн-редактор шанса прямо в карточке (степпер/поле), клик по карточке — правая панель/шторка вместо центральной модалки.
4. **Глобальное** (вкл/выкл, режим «Один товар/Кейс», запасной товар, лимит в месяц, маржа, напоминание) — свернуть в одну строку-сводку «Подарок за сумму: вкл · кейс · лимит 2 161 ₴/мес · маржа 15 %» с «Изменить» (раскрывается/шторка). Сохранение глобальных настроек — в одном месте (шторка с собственным «Сохранить»), не sticky-бар на всю страницу.
5. **StatsStrip** — перенести в сворачиваемую «Статистика 30 дней» (свернута по умолчанию на тел., в одну строку-чипов на ноуте), не 4 плитки до контента.
6. **LowMarginPanel** -> вкладка/секция «Упор на скидки» внутри «⚙ Настройки кейса» (она уже влияет на шансы на уровне), либо отдельный чип в тулбаре «Упор на скидки: N товаров».
7. Настройки уровня (порог/гарантия/замена/срок промокода) — шторка с живым пересчётом сводки на заднем плане (сейчас сохраняется сразу — оставить, но показывать дельту маржи).

**По размерам**
- Тел (320–639): sticky-тулбар 2 строки (табы 3 на ширину; действия — иконки 44px + «Опубликовать»); под ним sticky-мини-сводка (шансы-полоса + «Доля маржи %»); лейны аккордеоном, строка приза 56px, шанс в строке; правка приза — шторка; «Автособрать/Тест» — в «⋯» тулбара. Глобальные настройки — сворачиваемая карточка в самом верху (закрыта).
- План (640–1023): тулбар в одну строку, сводка sticky одной полосой, лейны в 1 колонку с призами в 2 колонки.
- Ноут (1024–1535): доска (лейны в 2 колонки призов) + правая sticky-сводка 340px; глобальные — сворачиваемая полоса сверху.
- Большой (1536–2560): лейны колонками-канбан (5 колонок по 260–300px, горизонтальный скролл не нужен до 2560), сводка + «Тест» (живой результат) справа 400px; контейнер `max-w-[2200px]`.

**Tailwind/компоненты**
- Тулбар: `sticky top-0 z-30 flex flex-wrap items-center gap-2 border-b border-[var(--line)] bg-[var(--bg)]/90 backdrop-blur`; мини-сводка: `sticky top-[var(--toolbar-h)] z-20`.
- Сетка рабочего стола: `grid lg:grid-cols-[minmax(0,1fr)_340px] 2xl:grid-cols-[minmax(0,1fr)_400px]`; канбан: `2xl:grid 2xl:grid-flow-col 2xl:auto-cols-[minmax(240px,1fr)]` вместо `xl:grid-cols-2`.
- Мини-полоса шансов — тот же markup, что в `SummaryCard` (`h-3` + `CASE_RARITY_COLOR`), вынести в общий `ChanceBar` и использовать в таб-карточке уровня (маленькая версия под названием).
- Инлайн-шанс: переиспользовать `ShareInput` (уже коммит на blur/Enter) для строки приза; цели `h-11` на `pointer-coarse`.
- Панель приза: общий компонент `components/ui/Drawer` (если есть в `@shop/ui/overlay`) на `lg+`, на тел. — `Modal` (шторка снизу, уже так).
- Единый «dirty bar»: один sticky-элемент снизу (`bottom: var(--bottom-nav)`), показывает «Черновик кейса: N» **или** «Настройки: N» с одной кнопкой; не два.
- Цвет «Доля маржи»: оставить логику `costTone`, добавить иконку/текст («Опасно»/«В норме»), не только цвет (доступность).

**Риски:** канбан на 5 колонок = DnD между редкостями — отдельная задача (L), сначала хватит «Редкость» в панели; sticky-слои (тулбар+сводка+bottom-nav) на 320px съедают до 140px высоты — мини-сводка должна быть 1 строка и скрываться при скролле вниз; изменение раскладки не должно трогать `use-case-board`/`case-draft` (логику шансов — не трогать).
**Оценка:** sticky-тулбар + мини-сводка + единый dirty bar — M, P1; сворачивание глобальных настроек и статистики — S–M, P1; инлайн-шанс в строке + правая панель приза — M, P2; канбан по редкостям на 2xl — M, P2; DnD призов между редкостями — L, P3; «Упор на скидки» внутрь настроек уровня — S, P3.

## 4. Реестр подарков (`RegistryScreen`, `RegistryView`)

**Что не так (по коду)**
- Панель периода (стрелки месяца + две даты + «Скачать CSV») — отдельная `panel` над содержимым; 4 плитки итогов — ещё один слой; предупреждение о лимите — третий; только затем таблица. На ноуте первая строка таблицы на ~420px вниз.
- Таблица `min-w-[60rem]` в `overflow-x-auto` и появляется только с `lg`; на 1024–1200px она всё ещё скроллится вбок, при сайдбаре ширина контента ~ 800px.
- Нет сортировки, поиска по получателю/заказу и фильтра «Сверх лимита» (самое нужное бухгалтеру — выделяются только цветом строки); шапка таблицы не sticky; нет итоговой строки.
- Мобильные карточки (`lg:hidden`) — на 640–1023 они одна колонка, хотя места хватает на таблицу.
- Дата произвольного периода: два `type="date"` сбрасывают месяц; на тач `Input type=date` ок, но CSV скачивается без выбора формата/группировки по человеку.
- Заголовок страницы + кнопка «Кейс» — дубль меню (навигация «Назад к кейсу» нужна, но не как кнопка в шапке).

**Предложение**
1. Один sticky-ряд: `[‹ Ноябрь 2026 ›] [С–По (в поповере)] [поиск] [Только сверх лимита ▢] [CSV]`; плитки итогов — компактная строка-чипы в нём же (или справа в ряду на ноуте): `Подарков N · ₴ сумма · Людей M · Сверх лимита K`.
2. Предупреждение о лимите — не абзац, а чип «Сверх лимита: K» в строке; клик включает фильтр; полный текст про НДФЛ — в тултип/раскрывающуюся плашку (один раз, закрываемую).
3. Таблица: sticky `thead`, сортировка по колонкам (дата, получатель, стоимость, «за месяц»), группировка по получателю (опционально), итоговая строка в конце. Таблица с `md` (>=768px), а не `lg`; колонки «Заказ» и «Вручён» объединить в одну на узком.
4. Телефон: карточки остаются, но компактнее (2 строки), чип-фильтры горизонтальным скроллом, «Скачать CSV» — в «⋯»/иконка.
5. «Кейс» ↔ «Реестр»: вкладки-ссылки в самом верху (две вкладки `Кейс | Реестр подарков`), а не кнопка в PageHeader.

**По размерам:** тел — карточки + sticky-ряд из двух строк; план — таблица на 5 колонок без «Вручён»; ноут — полная таблица `max-w-[1400px]`; большой — таблица + правая панель «топ получателей / по месяцам» (опционально).
**Tailwind:** `thead th { @apply sticky top-[var(--toolbar-h)] bg-[var(--surface)] }`, таблица `md:table`, карточки `md:hidden`; ряд `sticky top-0 z-20`; фильтр — `SegmentedControl size="sm"` / чекбокс 44px.
**Риски:** сортировка/поиск на клиенте ок до ~1000 строк, дальше нужна серверная; CSV не менять. **Оценка:** sticky-ряд + таблица с `md` + фильтр «сверх лимита» — M, P1 (нужно бухгалтеру); сортировка/итоги/группировка — M, P2.
