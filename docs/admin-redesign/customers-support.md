# Админка: Пользователи, Рассылки, Поддержка — предложения по редизайну

Домен: `features/customer`, `features/notification` (рассылки), `features/support`, их модалки и шторки.
Только исследование по коду (ветка orders-layout), код приложения не менялся. Размеры: S ≤ 0,5 дня, M ≈ 1–2 дня, L > 2 дней или нужен бэкенд.
Опора: у «Заказов» уже есть один прокручиваемый контейнер, sticky-панели, `--hdr-h` (`useCssVarHeight`), `--bottom-nav`, `pointer-coarse:` для тач-целей. Все новое строим на этом, а не рядом.

## 0. Общие решения (сначала они)

1. **Компонент `MasterDetail`** (`components/layout/`): на `lg+` две колонки в высоту экрана, на `<lg` — два экрана (список / деталь). Нужен только Поддержке, но потом пригодится Пользователям.
   `lg:grid lg:grid-cols-[minmax(340px,400px)_minmax(0,1fr)] lg:gap-0 lg:h-[calc(100dvh-var(--hdr-h,61px)-3.5rem)]`; колонки `min-h-0 overflow-y-auto thin-scroll`.
2. **`StickyActionBar`** (низ телефона): `sticky bottom-[var(--bottom-nav)] z-20 border-t bg-[var(--surface)]/95 backdrop-blur pb-2`. Нужен рассылкам («Разослать (N)»).
3. **`FilterSheet`**: на телефоне фильтры и сортировка уходят в шторку (`Modal` уже становится нижним листом на `<sm`), в строке остаются поиск + кнопка «Фильтры (2)».
4. **Вынести `TemplatePicker`** из `features/order/ui/chat/ReplyTemplates.tsx` в общий слой, чтобы Поддержка не копировала (см. 3.4).
5. **Не плодить «Открыт / активен»**: бейдж показываем только для отклонения от нормы (заблокировал, ждёт ответа, закрыт). Сейчас «активен» стоит у ~95 % строк и «Открыт» у всех открытых — это шум и 20–30 px высоты на каждую строку.
6. **Тач ≥ 44 px везде**: `FmtBtn` (h-9), кнопки `size="sm"`, закрыть-крестик в `PointHeader` (h-8/h-9) — добавить `pointer-coarse:h-11 pointer-coarse:w-11`.
7. **Строки-кнопки вместо `<tr onClick>`**: `motion.tr` в `UsersDesktopTable` не фокусируется и не открывается с клавиатуры → `tabIndex={0}`, `role="button"`, `onKeyDown` Enter/Space, `focusable`.

## 1. Пользователи (`/users`)

### 1.1 Экран «Список» (`UsersScreen` → `UsersTable`)
**Что не так**
- Над списком три слоя: `PageHeader` (заголовок + подзаголовок), ряд «Список/Аналитика», потом тулбар внутри `.panel`. На ПК до первой строки ~260 px, на телефоне ~330 px (поиск, кнопка-фильтр, select сортировки — три строки).
- Страница прокручивается целиком: тулбар и `thead` не липкие, при листании 30 строк поиск уходит вверх.
- Нет общего числа и «Показати ещё»: «Стр. 3» + две стрелки (бэкенд числа не отдаёт, `hasNextPage` = «страница полная», возможна пустая последняя). Нельзя понять, сколько клиентов под фильтром.
- Фильтр один — «Заблокировали бота». Владельцу нужнее «С заказами / Без заказов / Premium / язык», а счётчики для них уже есть в `useUserMetrics` (activeUsers, inactiveUsers, premiumUsers, blockedUsers).
- Поиск без «×», без `/`-горячей клавиши и автофокуса на ПК; пустой результат не предлагает «сбросить фильтры» кнопкой (только текст).
- Таблица: 7 колонок, «Язык» и «Статус» почти всегда одинаковые; нет самого полезного — «Последний заказ» и «Средний чек». Ширина `min-w` не задана, на 1024–1280 колонка «Пользователь» сжимается (truncate), даты на двух строках не переносятся (`whitespace-nowrap`) — уходит горизонтальный скролл внутри `.thin-scroll`.
- Мобильная карточка: 3 строки + бейдж «заблок.» (сокращение), дата регистрации справа внизу, язык и корона вперемешку с суммой.

**Предложение (логика: поиск → профиль с историей)**
- Один ряд на ПК: `[Поиск ×] [чипы: Все · С заказами · Без заказов · Premium · Заблокировали (N)] … [Список|Аналитика]`. Заголовок и подзаголовок убрать (название есть в шапке шелла). Чипы со счётчиками — `SegmentedControl` с `count` (он уже умеет).
- Тулбар и `thead` — `sticky top-[var(--hdr-h)] z-10 bg-[var(--bg)]`/`[&_th]:sticky [&_th]:top-[calc(var(--hdr-h)+56px)]`.
- Колонки: Пользователь (имя, @username · #id, 👑) · Заказы · Потрачено · Последний заказ · Был(а) · статус-точка только у заблокировавших. Язык — маленький `chip-tint` рядом с именем. «Регистрация» — в профиль/tooltip.
- «Показати ещё» внизу вместо пейджера (как в каталоге), счётчик «Показано 30 из 1 248» если бэкенд добавит `total` (см. риски).
- Выбранная строка (профиль открыт) подсвечивать: уже есть `.data-table tr[aria-selected="true"]` — ставить `aria-selected`.
- Телефон: ряд `[поиск ×][Фильтры •2]`, под ним горизонтальный скролл чипов (одной строкой, `-mx-4 px-4 overflow-x-auto`), сортировка — в `FilterSheet`. Карточка строки: имя + ₴ справа, вторая строка `@user · 3 зак. · был 2 ч назад`, высота ≤ 64 px. Высота первого экрана выигрывает ~120 px.
- Пустой результат: кнопка «Сбросить фильтры».

**Tailwind/компоненты**: `SegmentedControl` (чипы), `Input` + `rightSlot` (как в Поддержке), `Select` → `FilterSheet`, `.data-table`, `.card-hover`.
**Риски**: `total` — бэкенд; фильтры «с заказами/Premium/язык» — новые query-параметры API (сейчас только `blockedOnly`); смена пагинации ломает `resetKey`-анимацию (убрать stagger на «ещё»).
**Оценка**: чипы+sticky+колонки+клавиатура — **M**; «Показати ещё» без `total` — S; фильтры на бэкенде — **L**. Приоритет: **высокий** (ежедневный экран).

### 1.2 Профиль клиента (`UserProfileDrawer`)
**Что не так**
- Единственное действие — «Открыть в Telegram». Нет «Написать в поддержку» (а `StartThreadModal` требует вручную вставить Telegram id и обещает «скопировать в карточке покупателя» — в карточке копирования id нет).
- Две крупные плитки «Заказов / Потрачено» (≈ 100 px) — мало информации: нет среднего чека, последнего заказа, возвратов/отмен, активных вопросов в Поддержке.
- Дата регистрации и «был(а)» — отдельной серой строкой ниже плиток.
- Список заказов без фильтра/суммарной полосы; skeleton 88 px, реальная строка ~72 px — список «прыгает».
- Drawer не получает `backClose` (в отличие от `SupportThreadDrawer`) → на телефоне системное «Назад» уходит со страницы, а не закрывает профиль. Проверить на Android и в PWA.
- Профиль поверх заказа поверх профиля: на телефоне три полноэкранных слоя, нет «хлебной крошки» откуда пришёл.

**Предложение**
- Шапка: имя + бейджи; под ней строка действий (не выше 44 px): `[Написать] [Telegram] [Копировать ID]`. «Написать» открывает поддержку-тред с этим id (готовый `StartThreadModal` с предзаполненным клиентом или переход в существующий открытый тред).
- Сводка одной полосой 4 ячейки (`grid-cols-2 sm:grid-cols-4 gap-2`): Заказов · Потрачено · Средний чек · Был(а). Всё считается из уже загруженных `orders` (средний чек, последний заказ, число отмен/возвратов) — без бэкенда.
- Вкладки/сегменты внутри: «Заказы (N)» · «Обращения (N)» (список тредов клиента из `supportApi.threads?q=`/по userId) · «Данные» (язык, регистрация, premium, блок). Если обращений нет — вкладку скрыть.
- Метка «Проблемный» (много отмен/возвратов) — бейдж, считается на клиенте; без блокировки действий, только сигнал.
- Строка заказа: сумма крупно справа, статус и дата мелко; высота одинаковая со skeleton (72 px).
- `<Drawer backClose="userProfile" …>`.

**Риски**: «Обращения» — нужен запрос по userId (сейчас `q` ищет по имени/товару) → проверить/добавить параметр; цикл импортов customer ↔ support — прокидывать действие render-prop'ом, как `renderOrderDrawer` (уже принятый приём).
**Оценка**: действия + сводка + backClose — **M**; вкладка «Обращения» — **M–L**. Приоритет: **высокий** (связывает Пользователей с Поддержкой).

### 1.3 «Аналитика» (`UserMetrics`, карта)
**Что не так**
- Первой идёт карта высотой `min(560px,62vh)` (мин. 340), KPI только ниже: на телефоне первый экран — карта, цифры за прокруткой; Leaflet грузится сразу.
- 6 KPI-карточек `grid-cols-2` ≈ 3 ряда по 116 px на телефоне.
- Переключатель периода относится только к KPI/графикам, но стоит рядом с вкладками, а карта имеет свой переключатель дней — два «периода» на экране.
- `PointPanel`: нижний лист в карте (`max-h-[72%]`), крестик 32–36 px; на телефоне закрывает почти всю карту.

**Предложение**
- Порядок: KPI-полоса (на телефоне — один ряд горизонтального скролла `snap-x`, карточка 140 px) → графики → карта в конце, свёрнутая по умолчанию («Показать карту») или с `loading="lazy"`-триггером через `IntersectionObserver`.
- Период «Новых за период» — маленький сегмент прямо в шапке блока KPI; переключатель рядом с вкладками убрать (останется один «период»).
- `OnlinePill` вынести в шапку страницы (рядом с вкладками) — живой индикатор нужен без прокрутки.
- `PointPanel` на телефоне — настоящая шторка поверх карты (`fixed inset-x-0 bottom-0`, перетягиваемая), крестик `pointer-coarse:h-11`.

**Риски**: ленивый Leaflet — следить за `ssr:false` и размерами при раскрытии (`invalidateSize`). **Оценка**: **S–M**. Приоритет: средний.

## 2. Рассылки (`/broadcasts`)

### 2.1 Экран целиком (`BroadcastsScreen`)
**Что не так**
- Пять карточек друг под другом: Сообщение + Предпросмотр (две колонки), Тест, Рассылка, История. Кнопка «Разослать» — в третьей карточке, в самом низу после textarea на 9 строк и поля теста; на телефоне это 3–4 экрана прокрутки.
- Предпросмотр на телефоне идёт после всей формы: писать и видеть результат одновременно нельзя.
- Порядок логики перепутан: «Тест» стоит до «Рассылки», а выбор аудитории (кто получит) — после текста и теста.
- Много мелкого текста 11 px (подсказки про HTML, язык, правку, «уходит текст вкладки»): ниже читаемого порога на телефоне, и их по 4–5 штук; `section-title` с иконкой в каждой карточке — ещё 4 строки «шапок».
- Прогресс отправки спрятан внутри `SendCard`; пока рассылка идёт, пользователь может прокрутить мимо и не видеть, что она ещё идёт.
- Нет кнопки остановки — а в подтверждении написано «нельзя отменить».
- История — список карточек без раскрытия; причины ошибок (`errorLabel`) живут в другом месте — `features/activity` → вкладка «Рассылки», это дубль данных без ссылки между ними.

**Предложение (логика: текст → кому → тест → отправка → результат)**
- **ПК, `lg+`**: левая колонка (`min-w-0 lg:col-span-7`) — шаги «1 Сообщение» (вкладки языков, тулбар, textarea `rows=10` с авторостом, фото, кнопка), правая колонка (`lg:col-span-5 lg:sticky lg:top-[calc(var(--hdr-h)+16px)] self-start`) — «Предпросмотр» (макет Telegram), под ним «Кому» (аудитория + язык одним блоком), «Проверить» (тест себе — одна кнопка; поиск пользователя прячем под «…другому»), главная кнопка «Разослать (N)». История — ниже на всю ширину или во вкладке «История».
- **Телефон**: сегмент вверху `Сообщение · Кому · История`. Предпросмотр — иконка-глаз в `StickyActionBar` → нижняя шторка (`Modal`). Постоянно виден нижний бар: `[👁] [Тест себе] [Разослать (N)]`, сам кнопки 44 px.
- Прогресс: плашка под шапкой (`sticky top-[var(--hdr-h)]`) пока `status.running`, с кнопкой «Остановить» (если бэкенд умеет; иначе без неё и без слова «нельзя»).
- Подсказки: оставить одну строку под полем (12 px), остальное — в `title`/иконке «?»; убрать `EditHint` для «основной» вкладки.
- История: строка раскрывается (`Disclosure`) и показывает полный текст + разбивку причин; «В черновик» остаётся; ссылка «Подробный журнал» на вкладку активности.

**Tailwind/компоненты**: `grid lg:grid-cols-12 gap-4`, `StickyActionBar`, `Modal` как шторка, `SegmentedControl`, `.card` без `section-title` с иконкой (иконки оставить только в шагах), `Textarea` с автороcтом (`field-sizing-content` нельзя — iOS < 16.4/Chrome 92: считать высоту в `onInput`).
**Риски**: `use-compose` держит один набор состояния — карточки разрезаем без смены модели (S); «Остановить» — бэкенд. Тест в шторке: проверять, что уходит текст открытой вкладки (сейчас так).
**Оценка**: раскладка ПК (2 колонки, sticky) — **M**; телефонные шаги + нижний бар — **M**; остановка — **L** (бэкенд). Приоритет: **высокий** (риск ошибки отправки аудитории).

### 2.2 Модалки и мелочи
- **`ConfirmModal`** (`size="sm"`, на телефоне нижний лист — это хорошо). Не показывает сам текст и фото: подтверждают «аудиторию», а не сообщение. Добавить мини-предпросмотр (первые 3 строки + «+ фото» + кнопка), число получателей крупно; для N ≥ 100 кнопку делать с задержкой 1,5 с или «зажать». Обе кнопки 44 px (footer `Modal` уже `pb-[safe-bottom]`).
- **`TestCard`**: три поля в ряд (`Тест себе` / `или пользователю` / `или Telegram ID`) с `min-w` — на 320–360 переносятся беспорядочно. Свернуть: «Тест себе» всегда, «другому…» раскрывает `Autocomplete` (Telegram ID — внутри, как запасной вариант).
- **`FormatToolbar`** 36 px → `pointer-coarse:h-11 pointer-coarse:w-11`; на телефоне ряд в одну строку со скроллом.
- **`PhotoField`**: оставить, но превью 64 px → 96 px, кнопка «Заменить/убрать» ≥ 44 px.
- **Счётчик**: `text.length / MAX_LEN` показывает 4096 при фото, а лимит подписи 1024 — подпись «длиннее 1024 — отдельным сообщением» это покрывает; сделать счётчик цветным (warn > 90 %).
**Оценка**: **S** каждое. Приоритет: Confirm — высокий, остальное — средний/низкий.

## 3. Поддержка (`/support`)

### 3.1 Список обращений (`SupportScreen`, `ThreadRow`)
**Что не так**
- Очередь «ждут ответа» — вторая вкладка; по умолчанию открывается «Открытые» (`useState("open")`), то есть в обычный день первое, что видно, — смесь ждущих и отвеченных.
- Сортировка «последняя активность», а для очереди нужно «кто ждёт дольше всего — сверху». Время в строке — `timeAgo(lastMessageAt)` (когда было сообщение), а не «ждёт ответа 3 ч»; нет цветовой срочности.
- Каждая строка ≈ 110–120 px (аватар-товар, имя, тема, превью, два-три бейджа): на 1080p видно 6–7 обращений. «Открыт» и источник «Mini App» у каждой строки — шум.
- Над списком: `PageHeader` с подзаголовком (на телефоне подзаголовок остаётся видимым, `sr-only` у заголовка только), кнопки «Написать клиенту» и «Обновить», затем сегмент + поиск. «Обновить» не нужен: опрос 15 с + фокус окна.
- Список с задержками появления (`delay: index*0.025`), на каждый опрос/смену фильтра строки «дёргаются»; `limit: 200` без «ещё».
- Строка: цвет «активной» (`border-[rgba(255,102,0,.45)]`) — единственная отметка выбранной, а в drawer список затемнён и недоступен.

**Предложение (поддержка = очередь + быстрый ответ)**
- Дефолтный фильтр: «Ждут ответа», если их > 0, иначе «Открытые» (стартовое состояние из `useSupportUnread`). Чип «Ждут ответа (N)» акцентный.
- В режиме «Ждут ответа» сортировать по `awaitingSince` по возрастанию (на клиенте, без бэкенда); в строке вместо «5 мин назад» — «ждёт 2 ч 10 мин» c цветом: `<30 мин` нейтральный, `30 мин–2 ч` `--warn`, `>2 ч` `--danger-ink` + левая полоса того же цвета (`shadow-[inset_3px_0_0_…]` уже есть для waiting — менять цвет по давности).
- Компактная строка 72 px: слева аватар-инициалы/превью товара 40 px, имя + время справа, тема+превью одной строкой `truncate`, бейдж только «Закрыт», иконка 🌐 для сайта. Непрочитанные — `count-badge` + жирное имя.
- Шапка списка в одну строку: `[Поиск ×] [Написать +]`, чипы под ним. Подзаголовок и «Обновить» убрать (индикатор обновления — тонкая полоска `animate-pulse` под шапкой или иконка в правом верхнем).
- Анимацию появления оставить только при первой загрузке; при опросе — без неё.
- Горячие клавиши на ПК: `j/k` — следующий/предыдущий, `Enter` — открыть, `/` — поиск (S, опционально).

### 3.2 Мастер-деталь и телефон (`SupportThreadDrawer`)
**Что не так**
- Чат всегда в drawer `max-w-[640px]` поверх затемнённого списка: чтобы ответить следующему, нужно закрыть и открыть. Для очереди это самое дорогое действие (2 клика + анимации на каждое обращение).
- Шапка drawer трёхэтажная: eyebrow «Поддержка», имя (кнопка профиля), бейджи; под ней `ThreadProductBar` (миниатюра 56 px, название на 2 строки, ссылки «В админке/На сайте», «с даты», кнопка «Закрыть/Открыть снова» на всю ширину на `<sm`). На телефоне до первого сообщения ~200 px, ещё `composer` rows=2 внизу — окно чата ~ 40 % экрана.
- «Закрыть» — деструктивная для очереди кнопка, самая крупная на экране; нет «Ответить и закрыть».
- Имя-кнопка профиля открывает `UserProfileDrawer` поверх (ok), но через `await findUser` без индикатора.

**Предложение**
- **ПК `lg+`**: `MasterDetail`. Слева список (340–400 px) со своим скроллом, справа чат без затемнения — высота `calc(100dvh - hdr - padding)`, шапка чата одной строкой: `имя (→ профиль) · статус · источник` + кнопка `⋯` (Закрыть, Открыть в админке, На сайте, Профиль). Товар — компактная плашка 52 px над сообщениями (миниатюра, название `truncate`, «В админке» иконкой); сворачивается.
- После ответа: следующее «ждёт» подсвечивать в списке; кнопка «Закрыть и к следующему» (split-кнопка у отправки: `[Отправить][▾ Отправить и закрыть]`).
- Ссылка `?thread=`: оставить поддержку deep link, но в мастер-детали не вычищать параметр, а синхронизировать (`replaceState`), чтобы F5 возвращал в тот же тред.
- **Телефон `<lg`**: два экрана. Список — страница; чат — текущий `Drawer` (полный экран, `backClose` уже есть), но с шапкой одной строки: `‹  Имя клиента  ⋯`, ниже одна строка статуса (`Ждёт 2 ч · Mini App`). Товар — тонкая плашка 48 px, по тапу раскрывается. «Закрыть» — в `⋯`/нижнем листе, не отдельной полноширинной кнопкой.
- Composer: `pb-[calc(8px+var(--safe-bottom))]`, поле авторастущее до 5 строк (`rows=1`, пересчёт в `onInput`; сейчас `rows=1` на ПК не растёт — `max-h-32` без авторазмера), кнопки 44 px (уже), «⚡» 44 px слева.

**Tailwind/компоненты**: `MasterDetail`, `Drawer`/`useBackToClose` на `<lg`, `useIsDesktop()` для выбора варианта (как у «Заказов»), `ThreadProductBar` → `ThreadHeader` + `ProductChip`.
**Риски**: два режима рендера одного чата (`SupportChat` внутри drawer или колонки) — ключ по `threadId`, чтобы не потерять черновик; Realtime (STOMP) и `markRead` должны срабатывать, когда колонка видима и вкладка активна (`document.visibilityState`); не плодить два монтирования чата при ресайзе через `lg`.
**Оценка**: мастер-деталь + шапка — **L**; компактная строка + сортировка по ожиданию + дефолт — **M**; split «ответить и закрыть» — S. Приоритет: **самый высокий** в домене.

### 3.3 Непрочитанные
- Сейчас: бейдж-счётчик в строке, «Ждёт ответа», бейдж в навигации; в чате нет границы «новые сообщения».
- Предложение: разделитель «Непрочитанные» в `SupportChat` по первому сообщению клиента без `readAt` до `markRead`; в заголовок вкладки браузера `(N) Поддержка`. **S–M**, приоритет средний.

### 3.4 Шаблоны ответов
**Что не так**: в `OrderChat` есть ⚡ (`TemplatePicker`, рендер под заказ и язык покупателя, `/api/admin/orders/{id}/reply-templates`), в Поддержке шаблонов нет вообще — `Composer` содержит только скрепку и отправку. Привязка шаблонов к `orderId` мешает их использовать.
**Предложение**:
- Кнопка ⚡ слева от поля: ПК — popover над composer со списком и поиском по названию (`/` внутри списка), телефон — нижняя шторка (`Modal` как лист). Над полем — до 3 самых частых шаблона чипами (`-mx-1 flex gap-1.5 overflow-x-auto`), тап вставляет текст в поле, не отправляет.
- Подстановки `{имя}`, `{товар}` для треда: бэкенд `GET /api/admin/support/threads/{id}/reply-templates` (язык берётся из `users.locale`) либо клиентская подстановка из `thread.customerName`/`productTitle` и языка клиента. Первый вариант лучше — единый источник языка, как у заказов.
- `TemplatePicker` и `TemplatesManager` вынести из `features/order` в общий модуль (параметр `source: { kind: "order" | "support", id }`).
**Риски**: язык у треда не приходит (в `SupportThread` нет locale) → без бэкенда подбирать язык нельзя; текущий список без привязки к тредам даст сырой текст с плейсхолдерами. **Оценка**: **M** с готовым бэкендом, **L** с ним. Приоритет: **высокий** (самый заметный выигрыш времени оператора).

### 3.5 `StartThreadModal` («Написать клиенту»)
**Что не так**: Telegram id вводится вручную (`inputMode=numeric`), подсказка «скопировать в карточке покупателя» не выполнима — в профиле нет кнопки копирования; поле «Тема» и «Сообщение» без шаблонов; сообщение уходит как есть без предпросмотра языка.
**Предложение**: клиент выбирается `Autocomplete` по пользователям (паттерн уже есть в `TestCard` рассылок: `broadcastApi.searchUsers`), ID — запасной вариант в «…по Telegram ID»; открытие из профиля — с предзаполненным клиентом; в поле «Сообщение» ⚡-шаблоны; кнопка «Отправить» disabled пока нет клиента+текста (уже так, через `parseStartThread`). Размер `sm` оставить (нижний лист на телефоне).
**Риски**: после отправки `onStarted` открывает тред; если у клиента уже есть открытый тред — предложить открыть его вместо второго (нужна проверка по userId). **Оценка**: **S–M**. Приоритет: средний.
