# Админка: «Отзывы», «Оплата», «Настройки» — предложения по редизайну

Только исследование, код не менялся. Опора — «Заказы»: один прокручиваемый контейнер, sticky-панели, шторки, цели >= 44px.
Размеры: Тел 320-639, План 640-1023, Ноут 1024-1535, Бол 1536+. Файлы: `features/{review,payment,settings}/ui`.

## 0. Общее для всех трёх экранов
- Корень — обычный поток страницы: `PageHeader` (заголовок + подзаголовок, ~100px) + контент, прокручивается вся страница.
  Предложение: заголовок в topbar, подзаголовок в `?`-подсказку, высота контейнера `100dvh - topbar - var(--bottom-nav)`. S, P1.
- Плашки сохранения сделаны дважды: `SaveBar` (настройки, только при правках) и свой блок в `PaymentSettingsScreen` (виден всегда).
  Свести в один `components/ui/DirtyBar` (count, invalid, onDiscard, onSave, onJump). M, P1.
- Тач-цели < 44px: `Button size="sm"` (проверить высоту), стрелки `OrderBtn` в `OptionCard` 28x17, «Сбросить» в `SettingField` (11.5px).
  Добавить `max-sm:min-h-11`. S, P1.
- Входная анимация `motion.section y:16` на каждом блоке даёт «волну» на длинной странице; уважать `prefers-reduced-motion`. S, P3.
- Хоткеи-паттерн уже есть: `features/translation/ui/review/use-review-session.tsx` (`isTyping`, `keyAction`, `useOverlayLayer`).
  Вынести в `lib/use-queue-hotkeys.ts`. M, P1 (нужен для модерации).

## 1. Отзывы (`ReviewsScreen`, `ReviewCard`, `ReviewActions`, `ReplyEditor`, `ReviewMeta`)

### 1.1 Что не так
1. `mx-auto max-w-3xl`: на ноуте и большом экране две трети ширины пустые; карточка ~230px, на экран 2-3 отзыва.
2. Нет режима разбора: каждое действие — мышью по кнопке в карточке; после «Опубликовать» карточка исчезает, список
   едет под курсором. Клавиатуры и свайпа нет.
3. Дубли: чип «на модерации» на каждой карточке при фильтре «На модерации»; две даты; мета (`ReviewMeta`) в трёх стилях ссылок.
4. Фильтры: 4 пункта `SegmentedControl` + чип товара (2 строки на 320px). Нет поиска и фильтра по звёздам (1-3 звезды — обычно нужен ответ).
5. Пагинация «Стр. N из M» внизу, после 30 карточек; на телефоне до неё долго листать.
6. Действия (Опубликовать/Скрыть/Ответить/Удалить) в одном wrap-ряду — на 320px два ряда; у не-SUPER_ADMIN на каждой карточке
   подпись «Удаляет главный админ» — шум.
7. `ReplyEditor` раскрывается внутри карточки и сдвигает очередь; нет шаблонов ответов (один placeholder), нет счётчика (maxLength 2000).
8. Бонус: тост «может быть отправлен бонусный промокод» — админ ДО публикации не знает, получит ли автор бонус.
9. `OrderDrawer` открывается поверх, но позиция в очереди не запоминается.

### 1.2 Предложение: очередь, а не лента
- **Ноут/Бол:** две колонки `grid-cols-[minmax(320px,420px)_minmax(0,1fr)]`. Слева компактная очередь (строка 64px: звёзды, автор,
  товар, 1-2 строки текста, возраст). Справа открытый отзыв крупно: текст, мета, редактор ответа всегда виден, панель действий
  прижата к низу (как footer `Modal`).
- **Клавиши:** `J/K` или `↓/↑` — по очереди; `P` — опубликовать и далее; `H` — скрыть и далее; `R` — фокус в ответ;
  `Ctrl+Enter` в ответе — «ответить и опубликовать»; `Del` — удалить (SUPER_ADMIN, через `useConfirm`); `?` — шпаргалка.
  `kbd`-подсказки на кнопках с `lg:`.
- **После действия:** автопереход к следующему + toast «Отменить» (обратный статус) 6 с. Очередь замораживается на сессию
  (как в переводах), чтобы строки не прыгали.
- **Планшет:** очередь в одну колонку, деталь в правом `Drawer` 400px, действия sticky.
- **Телефон:** режим «по одному» (переключатель Список/По одному) + свайп: вправо — опубликовать, влево — скрыть, ответ — в `Sheet`.
  Нижняя sticky-панель из 3 кнопок (Скрыть / Ответить / Опубликовать, `min-h-12`). Свайп только с undo-toast.
- **Фильтры:** статусы + поиск (текст/товар/автор) + звёзды (чипы-мультивыбор); на телефоне одна кнопка «Фильтры» -> `Sheet`.
  Синхронизация с URL уже есть (`reviewsSearch`), расширить параметрами `q`, `stars`.
- **Бонус:** строка в панели решения «Первый отзыв по заказу #…: автор получит промокод -5 % (до 100 ₴)» или «Бонус не положен».
  Нужно поле `bonusEligible` от бэка, иначе не показывать.
- **Загрузка:** для очереди — подгрузка при прокрутке (IntersectionObserver), пагинатор только для «Все».
- **Шаблоны ответов:** чипы над полем, список хранить в localStorage (позже — в настройках).

### 1.4 Tailwind и компоненты
- Контейнер `flex min-h-0 h-[calc(100dvh-var(--topbar-h,56px)-var(--bottom-nav))]`, колонки `overflow-y-auto overscroll-contain thin-scroll`.
- Строка очереди: `min-h-[64px] px-3 py-2 data-[active=true]:bg-[var(--accent-soft)]`, `role="listbox"`/`aria-selected`.
- Свайп: `framer-motion` `drag="x"`, порог `info.offset.x > 96`. Панель: `sticky bottom-0 pb-[calc(12px+var(--safe-bottom))]`.
- Переиспользовать `SegmentedControl`, `ActionSheet`, `Sheet`/`Drawer` из `@shop/ui/overlay`, `useConfirm`. Новый `ReviewQueueRow`;
  `ReviewCard` остаётся как деталь; `Stars` вынести в `components/ui`.

### 1.5 Риски, размер, приоритет
- Риск: случайная публикация публичного контента (клавиша/свайп). Митигация: undo-toast, `P` не работает в поле ввода, свайп только на телефоне.
- Многопользовательская модерация: статус мог смениться у другого админа — обработать 409 и пропустить отзыв.
- Бэк: `bonusEligible`; для остального хватает текущего списка.
- Размер L (разбор + хоткеи + свайп), P1 для ноута/клавиатуры, свайп P2.
- Быстрый выигрыш S, P1: убрать `max-w-3xl`, скрыть статус-чип на фильтре PENDING, компактная мета, цели 44px.

## 2. Оплата (`PaymentSettingsScreen`, `MonobankCard`, `OptionCard`, `HowItWorks`)

### 2.1 Что не так
1. Порядок: большая `MonobankCard` -> способы -> справа статичный `HowItWorks` (4 шага) на целую колонку 340px. Справка занимает место рабочего контента.
2. При «Подключено» `MonobankCard` ~110px ради «всё хорошо»; нужна компактная пилюля, разворачивающаяся при проблеме.
3. `OptionCard` ~330px высотой, все поля всегда раскрыты: на ноуте видны 2 способа. Стрелки порядка 28x17px, `items-end` ряд
   «стрелки + название + корзина» на 320px сжимает поле. Порядок стрелками, хотя в проекте есть DnD.
4. «Показывать выключенные» по умолчанию `true`, удалённые с заказами остаются выключенными — список растёт.
5. Плашка «Сохранить» видна всегда (даже «Все изменения сохранены») — постоянные ~64px снизу.
6. Чеки и счета (`Receipts`, `InvoiceRow`) живут только в карточке заказа; сводки «FAILED-чеки, возвраты в обработке» нет.

### 2.2 Предложение
- **Статус:** `StatusPill` в шапке («monobank · подключено · вебхук 12 мин назад · подпись верна»). Клик -> поповер/`Sheet` с деталями
  и «Проверить». При `!enabled` или `error` — красная пилюля + инлайн-баннер (блокирует продажи).
- **Способы:** компактная строка [DnD] [Название] [Тип: «Полная» / «Предоплата 100 ₴»] [Тоггл] [меню ⋯]. Правка по клику:
  Ноут — inline-аккордеон (одна открыта), Тел — `Sheet` «Способ оплаты» с footer «Готово». 6-8 способов на одном экране.
- **Порядок:** DnD (как у фото и категорий) + «Выше/Ниже» в меню ⋯ для клавиатуры и телефона.
- **HowItWorks:** кнопка «Как это работает» -> поповер; колонкой справа только на Бол.
- **Сохранение:** общий `DirtyBar` только при изменениях. `saveBlocker` — текст в панели, клик ведёт к строке-виновнице (scrollIntoView + фокус).
- **Опционально (M, P3):** вкладка «Чеки и возвраты» со сводкой; нужен агрегирующий эндпоинт — в бэклог.

### 2.4 Tailwind и компоненты
- `OptionRow`: `grid grid-cols-[28px_minmax(0,1fr)_auto_auto] items-center gap-2 min-h-[56px] px-3`; на `max-sm` тип переносится `col-span-full`.
- Ручка DnD `touch-none cursor-grab h-11 w-8`. Новые: `StatusPill` (на `Badge`), `OptionRow`, `OptionEditor` (поля из `OptionCard` без стрелок).

### 2.5 Модалки
Все на `@shop/ui/overlay` `Modal`: на телефоне уже нижний лист с прижатым footer — оставить.
- **`PaymentModal` («💳 Корректировка оплаты»):** эмодзи в заголовке выбивается из иконок lucide — убрать. Два вводных абзаца + радио + каналы +
  заметка = ~600px, на 320px после открытия клавиатуры «Сумма» уезжает. Плашку свернуть в `?`; радио -> `SegmentedControl` (Предоплата / Вся / Другая);
  каналы `min-h-10` -> `min-h-11`; «Наложка после: N» в footer слева, чтобы не прыгала. Двухшаговое подтверждение «Полная оплата» оставить,
  красный блок сделать `role="alert"`.
- **`RefundModal`:** логика верная (две стадии, `role="alert"`, «Назад»). Добавить пресеты суммы чипами («Остаток», 50 %); поле `type=number`
  на iOS с запятой по локали ненадёжно — `type="text" inputMode="decimal"` (проверить `parseMinor`); на 320px развести «Назад» и «Вернуть» (`gap-3`).
- **`DeleteOptionModal`:** сократить текст до одной фразы + `Badge` «останется выключенным, если есть заказы».
- Риск: менять только UI, не `model/` (`amounts.test.ts`, `options.test.ts` есть). Размер M (список + Sheet + StatusPill), модалки S.
  Приоритет P2 (экран открывают редко), кроме тач-целей стрелок — P1/S.

## 3. Настройки (`SettingsScreen`, `SettingGroups`, `SettingField`, `SaveBar`, `DevicePanel`, `SystemPanel`)

### 3.1 Что не так
1. Все группы (orders, stock, notifications, bot, novaposhta, inbox, antibot, support + ссылка gift) — одна длинная лента панелей,
   поле = карточка ~150px. Десятки настроек = несколько экранов прокрутки, нет оглавления и поиска.
2. Правая колонка 340px: `DevicePanel` + `SitePanel` + `SystemPanel` — системные блоки, а не настройки магазина. На телефоне `DevicePanel`
   стоит ПЕРВЫМ, до главного содержимого.
3. Раскладка одна на все типы: INT в `max-w-[220px]` слева в широкой карточке (пустота справа), BOOL — тоггл «Включено/Выключено» под описанием.
4. «Изменено»: оранжевая рамка и бейдж в каждом поле + `SaveBar`, но нет перехода к следующему изменённому и счётчика по группам;
   невалидное поле вне экрана не найти.
5. `SaveBar` (`z-[55]`, sticky) перекрывает последние поля; «Отменить» сбрасывает всё без подтверждения.
6. «Сбросить» — текст 11.5px, цель < 44px.
7. `BotTexts`: переключатель uk/ru/en + одно поле на 5 строк, нет предпросмотра сообщения.
8. Тройной заголовок: `PageHeader` + `PanelHeader` группы + `section-title`.

### 3.2 Предложение: группы, поиск, «изменено — сохранить»
- **Группы:** Ноут — левое липкое оглавление 220px: иконка, название, бейдж «N изменено», красная точка при ошибке, scroll-spy.
  «Это устройство», «Сайт», «Система» — пункты оглавления внизу, а не правая колонка. Тел/План — sticky чипы групп под шапкой
  (`overflow-x-auto snap-x`) или `Select` «Раздел».
- **Поиск:** поле в sticky-шапке (`/` — фокус, `Esc` — очистка) по `label`/`description`/`key`; группы без совпадений скрываются,
  совпадения подсвечиваются, пусто — `EmptyState`. Чистая функция `model/search.ts` + тест рядом с `draft.test.ts`.
- **Плотные строки вместо карточек:** слева label + описание (`text-[12px]`), справа control (180-260px) или тоггл; на Тел — столбиком.
  ~72px вместо ~150px. «По умолчанию» — точка у label с tooltip; «Сбросить» — иконка 44x44.
- **Изменено — сохранить:** единый `DirtyBar`: «Изменено: 3 (в 2 группах) · [Показать] [Отменить] [Сохранить]». Ноут — sticky сверху контента,
  Тел — над таб-баром. «Показать» — к следующему изменённому/невалидному. `Ctrl/⌘+S` — сохранить. «Отменить» при >= 3 правках через
  `useConfirm`. Серверное «всё или ничего» не трогать.
- **Тексты бота:** редактор + живой предпросмотр пузырём (`Bubble`) на `xl+`; ниже — табы «Редактор / Предпросмотр».
- **Сворачиваемые группы:** раскрыта первая и все с правками/ошибками; при поиске раскрываются совпавшие; состояние в localStorage.

### 3.4 Tailwind и компоненты
- Каркас `grid lg:grid-cols-[220px_minmax(0,1fr)] gap-6`; оглавление `lg:sticky lg:top-[88px] lg:max-h-[calc(100dvh-104px)] overflow-y-auto`.
- Чипы: `-mx-4 flex gap-2 overflow-x-auto px-4 snap-x`, чип `min-h-11 px-3 snap-start`.
- Строка: `grid gap-2 py-3 sm:grid-cols-[minmax(0,1fr)_minmax(180px,260px)] sm:items-center border-b border-[var(--line)]`;
  изменённая — `shadow-[inset_2px_0_0_var(--accent)]` (как сейчас).
- Новые: `SettingsToc`, `SettingsSearch`, `DirtyBar`, `Disclosure`, `SettingRow`. `SettingControl` и `model/draft.ts` не трогать.

### 3.5 Устройство, сайт, система
- `DevicePanel` -> раздел «Это устройство»; наверх вынести только баннер, если push выключен на устройстве админа. iOS-подсказки — в `Disclosure`.
- `SystemPanel`: `sm:grid-cols-2`; ошибка синка НП новее последнего успешного — красная плашка вверху экрана, а не в боковой колонке.
- `GiftLink` — пункт оглавления «Подарок -> Кейс».

### 3.6 Риски, размер, приоритет
- Группы и иконки брать из ответа сервера (`groups`, запасная иконка уже есть), порядок не хардкодить.
- Невалидное поле в свёрнутой группе — раскрывать автоматически, иначе «Сохранить» заблокирована непонятно почему.
- `z-index`: `DirtyBar` (55) ниже `Modal` (150); следить за конфликтом сверху/снизу.
- Размер L, делить: (1) плотные строки + DirtyBar — M, P1; (2) оглавление/чипы + поиск — M, P1; (3) предпросмотр бота — S, P3;
  (4) раздел «Это устройство» — S, P2.
