# Оболочка и системные экраны админки: исследование и предложения

Область: `shell/` (Shell, Sidebar, NavLinks/NavRow/RailSection, TabBar, MobileMenu, nav-config, use-nav-badges),
`components/NotificationsBell`, `components/pwa/Banners`, экраны «Админы», «Инциденты», «Мой аккаунт»,
вход (AuthGate, Login, CodeStep, SetupStep), dev-login и их модалки. Код приложения не менялся.
Оценка: S = до полудня, M = 1-2 дня, L = больше. Приоритет: P1 важно, P2 полезно, P3 позже.
Примечание: Shell.tsx правится параллельно (хук `useCollapsedSidebar` уже возвращает объект) — перечитать перед работой.

## Общая картина
Навигация: 4 «ежедневных» пункта + 4 раздела (~19 пунктов), счётчики по 5 ключам, на ноутбуке 1024–1279 рейл с
флайаутами, на телефоне 4 вкладки + «Ещё» (шторка = тот же SidebarInner). Главные дыры: нет поиска и командной
палитры, нет избранного и «недавних», нет хлебных крошек у вложенных страниц (/orders/:id, /preorders/:id,
/gift/registry), нижняя панель не совпадает с ежедневными задачами (Поддержка со счётчиком спрятана в «Ещё»).

## 1. Командная палитра (Ctrl+K) — НОВОЕ
1) Не так: найти раздел можно только глазами (19 пунктов в 4 складках, на рейле — через флайаут). Заказ по номеру,
   товар, пользователя, промокод нужно искать внутри экранов.
2) Предложение: `CommandPalette` по Ctrl/Cmd+K и по иконке-лупе в шапке (на телефоне — в «Ещё»).
   Группы: «Разделы» (из nav-config, с учётом superOnly), «Действия» (Новая поставка, Пригласить админа, Свернуть меню),
   «Недавние» (5 последних страниц), «Заказы / Товары / Люди» — серверный поиск при вводе от 2 символов (debounce 250 мс,
   отмена прошлого запроса). Префиксы: `#1234` — заказ, `@` — пользователь. Enter — открыть, Ctrl+Enter — в новой вкладке.
3) Размеры: телефон — лист снизу на весь экран, поле 48px, строки результатов ≥48px, список не перекрыт клавиатурой
   (`html.kb-open` уже есть); планшет и ноутбук — по центру 560px; 1920+ — 640px, не шире.
4) Tailwind/компоненты: основа — `Modal` + `useOverlayLayer` из `@shop/ui/overlay` (Esc, стек, lock scroll); список —
   `role="listbox"` + `aria-activedescendant`; добавить в `NavItem` необязательное `keywords?: string[]`
   («ТТН», «наложка», «возврат»). Источник разделов — nav-config, не дублировать.
5) Риски: перехват Ctrl+K в полях ввода и в Telegram WebView (слушать на `document`, не открывать поверх модалок);
   нужен лёгкий отдельный эндпоинт поиска. **M, P1.**

## 2. Сайдбар и рейл (Sidebar, NavLinks, NavRow, RailSection)
1) Не так:
   - `LogoutEverywhereButton`: `const collapsed = false` — мёртвая ветка; «Выйти» и «Выйти везде» стоят рядом, опасное
     почти равно обычному по виду (оно отзывает вход и на этом устройстве). В рейле «Выйти везде» нет.
   - Подвал: Мой аккаунт + Выйти + Выйти везде + Свернуть = 4 строки около 170px — на ноутбуке 768px высоты съедают список.
   - Заголовок раздела при открытой странице из него некликабелен (`cursor-default`), но выглядит как кнопка.
   - Нет избранного: по умолчанию открыт только «Каталог»; Метрики, Оплата, Журнал за двумя складками.
   - Бейджи: у свёрнутого раздела сумма, но не видно, какой пункт срочный; в рейле у иконки точка без числа.
2) Предложение:
   - Подвал → один блок «профиль»: аватар/имя/роль + меню (Мой аккаунт, Выйти, Выйти везде с подтверждением).
     В рейле — только аватар с тем же меню во флайауте. Экономит около 100px.
   - «Закреплённое»: звёздочка у пункта (по hover / долгому тапу), блок над разделами, хранение в `localStore`
     (`admin.nav.pins`), позже — на сервере по админу. По умолчанию: Внимание, Заказы, Отправка, Поддержка.
   - «Недавние» (3 пункта) под закреплёнными — после палитры.
   - В рейле число до 99 в углу иконки вместо точки, когда есть место.
3) Размеры: 320–767 — сайдбара нет (шторка); 768–1023 — сейчас тоже шторка (`lg:`), планшет в альбомной лучше с рейлом
   76px от ~900px; 1024–1279 — рейл принудительно (уже), флайаут зажимать по `innerHeight`; 1280–1919 — полное меню 248px;
   1920–2560 — 264px, шрифт тот же, контент важнее меню.
4) Tailwind: меню профиля — `Popover` как в `RowMenu` (портал); звёздочка — `opacity-0 group-hover:opacity-100
   focus-visible:opacity-100`; затухание списка снизу через `mask-image` вместо жёсткой границы подвала.
5) Риски: порядок закреплённых и синхронизация между устройствами; не плодить второй источник правды рядом с `PRIMARY`.
   **M, P1 (подвал + закреплённое); мелочи S.**

## 3. Верхняя панель и колокольчик (Shell header, NotificationsBell)
1) Не так: на телефоне в шапке лого + заголовок, справа пусто; на десктопе заголовок мелкий серый (13px, tracking 0.2em)
   и слабо отличается от лейблов; у вложенных страниц нет «назад» и крошек («Заказ» без номера, «Поставка» без названия).
   Колокольчик ведёт на /inbox и дублирует пункт «Внимание», но без превью — клик не отвечает на «что там».
2) Предложение:
   - Слева заголовок/крошки (`Заказы / #1234`; на телефоне стрелка «назад» вместо лого на вложенных страницах), справа:
     поиск (Ctrl+K), колокольчик, профиль. Страницы задают `title`/`actions` через контекст; часть `PageHeader`
     переезжает в sticky-шапку и не дублируется (согласовать с «Заказами»).
   - Колокольчик → поповер «Что ждёт»: группы из `useInbox` (оплаты, чаты, возвраты…) ссылками на нужную вкладку
     + «Открыть Внимание». На телефоне колокольчика нет (Внимание — вкладка) — так и оставить.
   - Точка «нет связи / переподключение» (realtime.ts) рядом с заголовком.
3) Размеры: телефон — 48px + safe-top, заголовок 16px, действия ≥44px; планшет — как десктоп; ноутбук — высота 56px
   (сейчас 61), `px-5`; 1920+ — контент центруется `max-w-[1680px]`, шапка на всю ширину.
4) Tailwind: sticky + `backdrop-blur` уже есть; крошки — `nav aria-label="Путь"` с `truncate`/`min-w-0`; высоту шапки
   отдать в CSS-переменную `--topbar-h` (есть `useCssVarHeight`) для sticky-панелей страниц.
5) Риски: разброс z-индексов (30 шапка, 60 tabbar, 70/80 шторка, 350 баннер) — свести в токены; пересечение с sticky-панелями
   «Заказов». **M, P2.**

   а Товары — не ежедневные. Бейдж только у «Внимание» (сумма inbox, куда входят и чаты), а в сайдбаре у «Поддержки»

2) Предложение:
   - Панель: Внимание · Заказы · Отправка · Поддержка · Ещё. Товары — первым в «Ещё»/в закреплённом. Позже состав
     настраиваемый из «закреплённого» (до 4 + «Ещё»).
   - «Ещё» → нижняя шторка (85dvh, ручка, свайп вниз) вместо левой: сверху поиск, ниже плитки 3×N (закреплённое + разделы

   - Бейдж «Поддержки» — свой счётчик `support`; «Внимание» — inbox без чатов (или единая логика — решить с владельцем).
3) Размеры: 320px — 5 ячеек по 64px, «ПОДДЕРЖКА» в 10.5px упирается — truncate или короче («Чаты»); 360–430 — норма;

## 5. Баннеры установки и push (InstallBanner, PushOfferBanner, UpdateBanner)
1) Не так: две карточки в потоке `main` над контентом, на телефоне по ~130px каждая и сдвигают экран (стек при первом
   входе); «×» у установки = «навсегда», у push = «позже» (один значок — две семантики); `UpdateBanner` фиксирован

2) Предложение: очередь баннеров, одновременно максимум один (приоритет Update > Push > Install); компактная плашка 52px
   с кнопкой и «×», подробности (iOS «Поделиться → На экран Домой») — раскрытием. Установка и push дублируются в
   «Профиль → Приложение». «×» везде = «позже на 30 дней», «Не напоминать» — отдельно.
3) Размеры: телефон — плашка на всю ширину под шапкой, не sticky; планшет/ноутбук — тост справа снизу 360px, Install там
   не показывается (уже так); 2560 — не шире 420px.
4) Tailwind: `role="status"`, `aria-live="polite"`; анимация высоты `grid-rows-[0fr]→[1fr]` как в NavLinks.

## Общие правила
- Тач-цели ≥44px на `pointer: coarse` (`.hit`); у `RowMenu` сейчас 36px.
- Один источник навигации — nav-config; палитра, плитки, закреплённое читают его.
- z-индексы в токены (`--z-topbar/--z-tabbar/--z-sheet/--z-toast`), сейчас числа разбросаны по файлам.
- Перед показом: 320/360/390/430/768/1024/1280/1920/2560 × uk/ru/en (скилл shop-ui-qa), iOS 15.4+, без lookbehind.
