# Редизайн админки, этап 2: то, что требовало бэкенда

Этап 1 (макеты → код админки) сделан без бэкенда. Агенты пометили места, где макету не хватило API.
Теперь доделываем: бэкенд + админка, каждому агенту — своя группа. Работаем в одном worktree
`tg-shop-v2/_worktrees/orders-layout` параллельно, поэтому правила ниже обязательны.

## Общие правила

1. Прочитай `CLAUDE.md` worktree, `docs/ARCHITECTURE.md` (разделы 3 и 7 — рецепт нового эндпоинта) и
   `docs/ARCHITECTURE-FRONT.md` по месту. Решения владельца по экрану — `docs/admin-redesign/audit/DECISIONS.md`
   и `docs/admin-redesign/audit/<тема>.md`; макет — `docs/admin-redesign/mockups/<тема>/`.
2. Бэкенд: новый тонкий `Admin<Что>Controller` в `<модуль>/api` + сценарий в `<модуль>/app`; в большие
   контроллеры не дописываем. Файл ≤ 400 строк, метод ≤ 80. Ошибки — `<Модуль>Error` + строки в `messages*.properties`.
   Аудит действий админа — `AdminAuditService.record`. Время — `Clock`/`ShopZone`. Деньги — minor.
3. Миграция — только твой номер (см. задачу). Только добавлять (новые колонки NULL/DEFAULT, новые таблицы):
   старый бэкенд должен работать на новой схеме (откат образом). Скилл `shop-migration` — правила.
   Номер не понадобился — так и скажи в отчёте.
4. **Maven и генерация типов — только под общим замком** (дерево общее, одновременные сборки ломают `target/`):
   ```bash
   L=/c/Users/nikto/AppData/Local/Temp/claude/fe7a63a9b48e6c9e/2dd00d24-fe52-4a5c-81e8-64351a8a5ad9/scratchpad/mvn.lock
   until mkdir "$L" 2>/dev/null; do sleep 15; done; trap 'rmdir "$L"' EXIT
   cd backend && mvn -q test -Dtest='<твои тесты>,OpenApiSnapshotTest' -Dopenapi.update=true && cd .. && npm run gen:api
   ```
   Замок держи только на время команды. Целиком `mvn test` не гоняй (это сделает координатор).
   Не компилируется из-за чужого файла — подожди и повтори, чужие файлы не правь.
   Свои Java-файлы пиши целиком за один заход, чтобы дерево компилировалось.
5. Админка: типы — только из `packages/core/src/api/generated.d.ts`; запросы — `features/<x>/api.ts`,
   мутации — `useApiMutation`. Убери заглушки/пометки «нужен бэкенд» и включи то, что было в макете.
   Лимиты фронта: файл ≤ 400, complexity ≤ 15, без `eslint-disable`.
6. Проверки своей части: юнит/IT-тесты бэкенда на сценарий; `npm run typecheck` и `npx vitest run <свои файлы>`
   в `frontend-admin`. Полный прогон сделает координатор.
7. Сайт и Mini App не трогать, если задача прямо не требует. Не коммитить. Не трогать файлы других групп.
8. Отчёт (по-русски, коротко): что сделал на бэкенде (эндпоинты, миграция), что в админке, тесты,
   что не сделал и почему, есть ли изменение поведения для покупателя.
