## Цель

1. Покупатель выбирает: **відділення / поштомат / кур'єр на адресу** (+ самовивіз), видит примерную цену доставки.
2. Оплата: онлайн полностью, предоплата + остаток при получении, **полностью при получении** («Контроль оплати»).
3. Админ одной кнопкой (или пачкой на «К отправке») **создаёт ТТН** с суммой к оплате и **печатает этикетки** 100×100.
4. Статус посылки подтягивается сам: «відправлено» → «прибуло» → «отримано»/«відмова», без ручного ввода ТТН и статусов.
5. Позже — отправка в Европу (отдельный договор, см. EU-документ).

## Что проверено на боевом ключе ФОП (2026-10-23, только чтение)

- Ключ — бизнес-кабинет ФОП, работает в API 2.0 и в UA-REST (`/clients/authorization` → JWT).
- Опции контрагента: **`CanAfterpaymentOnGoodsCost=true`** («Контроль оплати», деньги на р/с ФОП), `CanNonCashPayment=true`,
  `CanSentFromPostomat=true`, `CustomerReturn=true`, **`InternationalDeliveryContract=false`**, `PickupService=false`,
  печать маркировки: **`m100x100` и `m85x85A4`**.
- В кабинете уже есть ТТН с «Контролем оплати» (WarehouseWarehouse, платит получатель) — схема знакома.
- **Печать работает**: `printMarking100x100/.../type/pdf` и `printDocument/.../type/pdf` по существующей ТТН → `200 application/pdf`.
- Цена (`getDocumentPrice`, 1 кг, 20×30×10, оценка 3000 ₴, Київ→Львів):
  відділення **105 ₴**, поштомат **115 ₴**, кур'єр на адресу **165 ₴**; комиссия денежного перевода 3000 ₴ — 80 ₴.
- Интервалы курьерской доставки (`getTimeIntervals`) и забора (`getPickupTimeIntervals`) отдаются.
- Контактных лиц отправителя — 2, адресов отправителя — 0 (отправка из отделения).

## Решения

1. **API для Украины — старый 2.0** с бизнес-ключом: в нём есть «Контроль оплати», адресная доставка, правка, печать, реестры.
   Новый REST для UA пока неполон (см. `shipments.md`). Трекинг — `getStatusDocuments` опросом; вебхуки нового API — позже как ускоритель.
2. **Деньги при получении — через «Контроль оплати»** (`AfterpaymentOnGoodsCost`), а не наложку `BackwardDeliveryData`:
   деньги идут на р/с, услуга уже подключена. Сумма = `codMinor` заказа. В один ТТН — только одно из двух.
3. **Способы доставки** (новое значение enum, не ломая старое):
   `NOVA_POSHTA` (відділення/пункт), `NP_POSTOMAT`, `NP_COURIER`, `PICKUP`; позже `NP_INTERNATIONAL`.
   `ServiceType`: `WarehouseWarehouse` / `WarehousePostomat` / `WarehouseDoors`.
4. **Отправитель** — в настройках админки (город, отделение отправки, контактное лицо, телефон, описание груза по умолчанию,
   «кто платит доставку»), подтягивается кнопкой «Загрузить из кабинета НП».
5. **Ключ НП** — только на сервере (`NOVAPOSHTA_API_KEY`), печать — через прокси бэкенда (в URL печати уходит ключ).
6. **Песочницы у 2.0 нет** → тесты: создать ТТН на завтрашнюю дату и сразу `delete` (до сдачи в отделение бесплатно).
   На демо — флаг `NP_DRY_RUN=true`: запросы `save/delete` логируются и возвращают фиктивный номер, реальные ТТН не создаются.

## Этапы

Миграции — с **V65** (в других ветках заняты V58/V61/V62, см. скилл shop-migration).

### Этап 0. Подготовка (½ сессии)
- Перебазировать ветку на master; клиент `NovaPoshtaApiClient` (API 2.0: ретраи, коды ошибок → понятный текст, лог без ключа).
- Настройки отправителя (`settings`), кнопка «Проверить ключ» (= `getCounterparties`) в «Системе».
- Поля товара: вес (г) и габариты упаковки (мм) у товара/варианта + **значения по умолчанию по категории** и пресеты коробок в настройках.
  Без этого ТТН создаётся с весом по умолчанию 1 кг и коробкой 20×30×10 (как в ручных ТТН).
- Починить `TYPE_POINT`.

### Этап 1. Авто-трекинг (1 сессия) — самая быстрая польза
- Таблица `order_shipments` (V65): `order_id`, `carrier`, `ttn`, `np_ref`, `service_type`, `status_code`, `status_text`,
  `cod_minor`, `delivery_cost_minor`, `scheduled_at`, `arrived_at`, `received_at`, `storage_paid_from`, `last_polled_at`, `raw_json`.
  `orders.tracking_number` остаётся (совместимость, откат).
- Джоб раз в 30 мин: все SHIPPED (и созданные ТТН) пачками по 100 → `getStatusDocuments` с телефоном получателя.
- Переходы: 4/5/6/41/101 → SHIPPED (если ещё нет); 7/8 → «прибыло» (уведомление покупателю, бейдж в админке);
  9/10/11 → DELIVERED (`received = total` только когда пришёл перевод/«Контроль оплати»); 102/103/105/106 → «Внимание: отказ/возврат».
  Неизвестные коды — только лог.
- Напоминание покупателю за день до платного хранения (`DateFirstDayStorage`).
- Ссылка «Відстежити» `https://novaposhta.ua/tracking/?cargo_number=<ТТН>` на сайте и в Mini App + статус посылки текстом.
- В «Внимание»: «посылка лежит в отделении N дней», «отказ», «возврат».

### Этап 2. ТТН и печать из админки (1–2 сессии)
- В заказе кнопка **«Створити ТТН»** (предпросмотр: получатель, тип, вес/коробка, оценка, сумма к оплате, кто платит, цена НП) →
  `Counterparty.save` (получатель) → `InternetDocument.save` → сохраняем `Ref`+номер → заказ в SHIPPED (или «ТТН создана», см. вопросы).
  «Скасувати ТТН» → `InternetDocument.delete` (только до сдачи). «Изменить» → `update`.
- **«К отправке»: «Створити ТТН для всіх» + «Друк етикеток»** — одна PDF на все (100×100 или 85×85 на A4), открывается в новой вкладке.
- `InfoRegClientBarcodes` = номер заказа (виден в трекинге), `Cost` = сумма товара, `AfterpaymentOnGoodsCost` = остаток к оплате.
- Опционально: реестр (`ScanSheet`) на сдачу пачки.
- **Автопечать**: браузер не печатает без диалога. Варианты: (а) PDF в новой вкладке → Ctrl+P (сразу); (б) маленький агент печати
  на ПК с термопринтером (QZ Tray или свой сервис) — PDF уходит на принтер без кликов; (в) печать из приложения НП по номеру.
  Решить после выбора принтера.
- Опционально «создавать ТТН автоматически» при одобрении/оплате заказа (настройка, по умолчанию выкл.).

### Этап 3. Оформление заказа v2 (2 сессии)
- **Общий компонент доставки** в `shared/` для сайта и Mini App (сейчас две копии и разные i18n-ключи).
- Вкладки: **Відділення · Поштомат · Кур'єр · Самовивіз**.
  - Поштомат: фильтр точек, предупреждение о лимите (≤ 30 кг, габариты), блок, если корзина не влезает.
  - Кур'єр: город → улица (онлайн-поиск `Address.searchSettlementStreets` через бэкенд, кэш) → дом, квартира, комментарий курьеру,
    при желании интервал доставки (`getTimeIntervals`).
- Получатель: **Прізвище + Ім'я** раздельно (+ «отримувач інша людина» с телефоном); ФИО уже в заказах — разбивать при миграции.
- Оплата: варианты зависят от способа доставки (`payment_options.delivery_methods`); новый вариант **«Оплата при отриманні»** (0 ₴ онлайн,
  без 24-ч автоотмены, но с подтверждением админом или лимитом суммы — защита от «не забрал»).
- **Цена доставки ориентировочно**: `getDocumentPrice` (кэш по город+тип+вес) → «≈105 ₴ + комісія за переказ ≈80 ₴, за тарифом НП».
- Сервер проверяет доставку (`OrderService.createOrder`): ref существуют, поля по способу заполнены.
- Подстановка из прошлого заказа — по `ref`, а не по названию; позже «Мої адреси» в профиле.
- Тексты на 3 языках (скилл shop-i18n-keys), страница «Доставка та оплата» (`delivery-payment.md`).
- Админка: `DeliveryEditModal` учится менять тип/адрес; шаблоны ответов и уведомления знают курьера и поштомат.

### Этап 4. Вебхуки нового API (по желанию)
- Подписка `tracking-push` (тип `legal` по ИНН ФОП) → мгновенные статусы; опрос этапа 1 остаётся как страховка.

### Этап 5. Европа — см. [NOVA-POSHTA-EU.md](NOVA-POSHTA-EU.md)
Нужен отдельный договор и ключ my.novapost.com, только предоплата, пошлины на получателе.

## Проверка и выкатка
- Юнит-тесты маппинга статусов и сборки `save`-запроса (фикстуры ответов из скилла).
- e2e админки: создать ТТН (dry-run), печать (PDF отдаётся), трекинг (фикстуры).
