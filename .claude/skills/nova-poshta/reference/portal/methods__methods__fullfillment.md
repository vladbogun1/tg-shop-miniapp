## Check Inbound Plan Status

> This endpoint is used to retrieve the current status and actually received items for one or more inbound plans (document types \`1\`, \`3\`, \`7\`, \`11\`).\
> \
> It supports filtering via query parameters by inbound plan IDs, external numbers, destination warehouse codes, and creation date range.\
> \
> Filter values within the same parameter are combined using \`OR\`, while different parameters are combined using \`AND\`.\
> \
> Array query parameters must be passed by repeating the parameter for each value. Do not pass multiple values as a comma-separated list.\
> \
> Example: \`GET /inbound-plans/status?externalNumbers\[]=PP-1781501639086\&externalNumbers\[]=FF-1781501639011\`\
> \
> When both \`startDate\` and \`endDate\` are provided, the response returns documents where \`startDate <= document creation date <= endDate\`. The following condition must be met: \`startDate <= endDate <= current date\`.\
> \
> 🔹\*\*If no filter parameters are provided, the response returns the most recently created inbound plans.\*\*\
> \
> 🔹If no data matches the specified filters or the specified warehouses do not exist, the response returns an empty \`data\` array with \`200 OK\`.\
> \
> 🔸If unknown or unsupported query parameters are provided, or if the date format is invalid, the API returns \`422 Unprocessable Entity\`.\
> \
> \*\*Received item processing rules:\*\*\
> \- If an item contains both normal (\`condition = 0\`) and defective (\`condition = 1\`) units, they are returned as separate objects in the \`items\` array.\
> \- If multiple defect reasons are recorded for defective items (\`condition = 1\`), their quantities are aggregated into a single \`receivedQuantity\` value.\
> \- Different units of measurement (\`measureUnitName\`) or expiry dates (\`expiryDate\`) for the same item are returned as separate objects.\
> \- If the actual receiving process has not yet occurred or the received value is empty, \`receivedQuantity\` is returned as \`0\`.<br>
